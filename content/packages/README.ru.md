# Пакеты локаций Forever

Первая версия менеджера находится в нашем Tauri-лаунчере: **Настройки → Пакеты
локаций**. Выбирается локальная папка пакета; затем лаунчер проверяет её для
указанного каталога `_classic_beta_`, показывает готовность, устанавливает
клиентскую часть и позволяет откатить последнюю операцию.

Это новый функционал исходников лаунчера. Уже установленный на компьютере
лаунчер получит его только после сборки/обновления приложения. К обычным
Lua-аддонам эта установка не относится.

## Статус Даларана

`legion-dalaran/manifest.json` — **экспериментальный черновик без игровых файлов**.
Каталог лаунчера показывает, что установка пока недоступна. В нём намеренно
не выставлены `client_render_verified` и `server_ready`: успешная работа нового
ресурса в игровом движке ещё не подтверждена. Наличие этого раздела в лаунчере
не означает, что Даларан уже перенесён.

## Ограничения первой версии

- Это **пакет для точного состояния CASC**, а не универсальный установщик во
  все клиенты той же версии. Хеши `.build.info`, shmem, всех IDX/LRU должны
  совпадать с исходным снимком. Другой набор локальных индексов требует подготовки
  другого пакета. Это ограничение текущего способа изменения CASC.
- Поддерживаются локальные папки пакетов, без автоматической загрузки из сети.
- Установка/откат в интерфейсе включены для Windows и Linux. macOS пока явно
  отклоняет изменение пакетов; обычные функции лаунчера продолжают работать.
- Серверную часть устанавливает администратор отдельно: геометрия, записи карты,
  миграции, NPC и сценарии. Клиентский лаунчер не исполняет shell, Python или SQL.
- `server_ready` — **декларация автора пакета**, что нужная серверная часть уже
  установлена; это не запрос к серверу и не независимая проверка доступности карты.
  Признаки проверки в манифесте не являются криптографической подписью. Импортируйте
  пакеты из доверенного источника, подготовленные оператором вашего сервера.

## Формат папки

```text
package/
  manifest.json
  payload/
    .build.info
    Data/
      config/ab/cd/abcdef0123456789abcdef0123456789ab
      data/data.053
      data/0000000060.idx
      data/shmem
```

Это пример структуры, не готовые игровые данные или реальные хеши. Формальная
схема — `manifest.schema.json`. Манифест содержит:

- `format`: `wowforever-zone-package-v1`;
- `id`, `name`, `version`, точную `client_version`;
- `status`: `experimental` или `verified`;
- `client_render_verified`, `server_ready` — декларации проверок автора;
- `base_files`: полный исходный снимок `.build.info` и файлов shmem/IDX/LRU
  из `Data/data` с SHA-256;
- `files`: операции `path`, `before`, `after`. Хеш `null` означает отсутствие
  файла. `before=null` создаёт новый файл; `after=null` удаляет старый индекс.
  Байты для `after` находятся в `payload/<path>` и проверяются SHA-256.

Обязательна операция замены `.build.info`, привязанная к её исходному хешу.
Архивы `data.NNN` и конфигурации разрешено только создавать с новым именем:
готовый пакет не перезаписывает старые архивы. Изменение/удаление IDX/LRU
должно быть явно перечислено. `.build.info` переключается последней.

Разрешены только `.build.info`, `Data/config/<2hex>/<2hex>/<32hex>`,
`Data/data/data.NNN`, shmem, штатные IDX и LRU. Переходы `..`, ссылки/junction,
дубли путей без учёта регистра, исполняемые файлы, WTF и любые другие пути
отклоняются. Ограничения: 1 MiB манифеста, 1024 операции, 8 GiB полезных файлов.

## Установка и восстановление

Полностью закройте игру. На странице настроек выберите нужный клиент, затем
папку пакета. Если пакет готов и исходное состояние совпадает, станет доступна
кнопка **Установить**. Исходная копия другого клиента при этом не обновляется.

Перед изменением файлов лаунчер проверяет свободное место, копирует и проверяет
полезную нагрузку и резервные копии. В клиентском корне создаётся
`.forever-content/operations/<id>` с журналом и резервной копией. Параллельные
операции сериализуются файловой блокировкой, а запуск игры этим лаунчером
заблокирован на время установки. Также проверяется уже запущенный WowB.exe.

Ошибка во время переключения запускает восстановление предыдущих файлов.
Прерванная операция отображается в интерфейсе и может быть восстановлена кнопкой
**Откатить**. При неизвестных изменениях затрагиваемых файлов восстановление
останавливается и оставляет резервную копию для диагностики.

Если после установки игра/лаунчер изменили индексы или другие исходные метаданные,
обычный откат может быть отклонён: менеджер первой версии не объединяет такие
изменения с резервным снимком. Поэтому универсальное обновление установленной
локации потребует полноценного согласования состояния CASC; оно пока не реализовано.

Для релиза локации нужны отдельно проверенные клиентский пакет и серверный пакет.
Нынешний эксперимент TVFS на одной текстуре остаётся отдельным этапом проверки
Даларана, а не заменяется пустым манифестом.

## Подготовка папки пакета оператором

`scripts/export-zone-package.py` экспортирует **одну** завершённую операцию
`install-legion-resources.py` из её журнала и клиентских файлов. Он не собирает
цепочку предыдущих операций и не включает серверные данные: исходный клиент
для установки должен соответствовать снимку перед этой конкретной операцией.
Скрипт читает клиент и пишет только в новую папку вне репозитория и клиента.
Например, для оператора в WSL:

```bash
python3 scripts/export-zone-package.py \
  --client /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1 \
  --operation /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1/legion-resource-operations/ID_ПРОВЕРЕННОЙ_ОПЕРАЦИИ \
  --output /mnt/e/WoWForEver-work/packages/Dalaran-launcher-candidate-v1 \
  --id legion-dalaran --name 'Dalaran (Legion)'
```

По умолчанию результат **experimental**, установка заблокирована. При изменении
IDX/поколений после операции экспорт откажет: нужен новый проверенный снимок.
Для назначения статуса `verified` оператор после реального теста изображения,
входа на карту и подготовки серверной части передаёт `--validation` с JSON:

```json
{
  "format": "wowforever-zone-validation-v1",
  "candidate_build_info_sha256": "SHA256_ПРОВЕРЕННОЙ_BUILD_INFO",
  "client_render_verified": true,
  "server_ready": true
}
```

Это запись результатов оператора, привязанная к конкретной `.build.info`,
а не автоматическое доказательство работы карты. Для текущего Даларана эти
результаты ещё не получены; выставлять их заранее нельзя. Полученные игровые
файлы остаются локально в `WoWForEver-work/packages` и не добавляются в Git.
