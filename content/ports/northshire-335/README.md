# Пробный перенос из TrinityCore 3.3.5: Североземье

Это отдельная тестовая копия квеста **Kobold Camp Cleanup (7)** и NPC
**Marshal McBride (197)**. Оригинальный квест Forever и его NPC не заменяются.

Источник: [официальная TDB335.26091](https://github.com/TrinityCore/TrinityCore/releases/tag/TDB335.26091),
архив `TDB_full_world_335.26091_2026_09_09.7z`.
SHA-256: `ed0c50177da912b50c9f386ba8a26254cecfb997ca7fd2e992c25b344e11274f`.
Исходные строки сохранены в `source.json`; лицензия GPL-2.0, как у исходного
TrinityCore (см. LICENSE репозитория и COPYING проекта-источника).
Игровые файлы клиента в перенос не включены.

## Что перенесено и адаптировано

- Английские тексты задания, требования 3.3.5: убить 8 Kobold Vermin (entry 6).
- 25 медных монет, 90 медных на максимальном уровне, параметры XP и репутации
  Штормграда из 3.3.5. Фактические выплаты зависят также от серверных rates и уровня.
- Тексты диалога при сдаче и незавершённом задании.
- Уровень квеста 2, минимальный уровень 1. Предварительная цепочка снята для теста.
- Копия маршала использует рабочую модель и параметры Forever; это не прямой
  импорт его старой creature_template, чья схема существенно отличается.
- Параметры ContentTuning и совместимости клиента наследуются от работающего
  квеста 7 Forever. Денежная награда и уровни записаны в специальные Classic-таблицы ядра.
- Английский текст сохранён для сравнения с источником; перевод клиента не добавлялся.

| Объект | Новый ID |
|---|---|
| Квест | 900007 |

NPC появляется рядом с оригинальным маршалом в аббатстве Североземья (карта 0).
Имя и название квеста начинаются с `[335 test]`. Точка взята из существующего
спавна маршала со смещением на 1.5 по X/Y; положение на полу нужно проверить в игре.
Существующие кобольды используются как цели, новые противники не добавляются.

## Установка на своём ПК

Сначала завершите первый импорт БД. Выйдите из игры; Docker Desktop оставьте
включённым. В Ubuntu, в каталоге проекта:

```bash
git pull --ff-only
bash scripts/northshire-port.sh status
bash scripts/northshire-port.sh apply
```

Скрипт проверяет, что все четыре службы запущены, временно останавливает сайт и
игровые процессы, делает бэкап четырёх баз и конфигурации в игнорируемый Git каталог
`backups/`, затем применяет SQL и запускает процессы снова. Бэкап содержит пароли
и ключи: не публикуйте его. Убедитесь, что на диске есть свободное место.
При ошибке SQL изменения данных откатываются транзакцией; служебные таблица и
процедура могут сохраниться, повторная попытка пересоздаёт процедуру.

Пересборка Docker и новая сборка лаунчера не нужны. Дождитесь `worldserver ready`
в логах после перезапуска, затем войдите в игру.

## Проверка в игре

1. Человеком Альянса уровня 1+ дойдите до маршала Макбрайда в аббатстве Североземья.
2. Найдите рядом `[335 test] Marshal McBride`.
3. Возьмите `[335 test] Kobold Camp Cleanup`: в журнале должно быть **0/8**.
4. Убейте 8 Kobold Vermin и сдайте квест тестовому NPC.
5. Проверьте деньги, опыт, репутацию; выйдите и войдите, проверьте сохранение.
6. Проверьте, что исходные NPC/квесты продолжают работать.

Это перенос одной записи старого квеста, уже существующего и в Forever,
с отличающимся числом целей (8 вместо 10). Он проверяет конвертацию данных,
но не добавляет зоны WotLK или новые механики. Вход и бой на клиенте 70532
пользователь уже проверил, а этот новый квест в игре пока не проверен.

## Откат

Выйдите из игры; если тестовый квест ещё в журнале, сначала откажитесь от него.

```bash
bash scripts/northshire-port.sh rollback
```

Откат удаляет только записи этого порта из world; персонажи, полученные награды
и запись о завершении квеста сохраняются. Поэтому после повторной установки
завершивший квест персонаж не сможет взять его снова. Для полного повторного теста
используйте нового персонажа. Полный откат прогресса потребует восстановления
предварительного бэкапа и отменит остальные изменения после его создания.

## Проверки разработки

SQL проверен в отдельном MySQL 8.0 на таблицах официальной базы Forever
`forever-tdb-2026-10-14`: установка, повторная установка, откат, повторный откат,
защита от занятых ID и восстановление установки после отката. Оригинальные
данные сравниваются до/после. Оболочка проверяется `bash -n`.
Ни игровой тест нового NPC, ни выполнение helper-скрипта на машине пользователя
не выполнялись автоматически. При обновлении ядра нужна повторная проверка схемы.
