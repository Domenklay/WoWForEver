# Forever Ascension на текущем сервере 70658

Пользователь разрешил вернуть собранную систему мультиклассов на готовый
сервер 70658. Переносится актуальный Forever Ascension 1.11.0 / протокол 3,
а не снятый с поддержки ForeverSubclass. Базовое ядро остаётся
b4e7b940593f6402a822d4fbcdf31331d16f73b6; клиент не переключается на 70707.

## Установка сервера

Из актуального checkout этой ветки в Ubuntu/WSL:

```bash
python3 scripts/enable-clean-advancement.py install --jobs 2
```

Инструмент работает с `~/WoWForEver-clean/state.json` и приватным Compose
этого сервера. Не запускайте старый `advancement-mod.sh update`: он управляет
другим Compose-проектом. Для этой установки клиент и архивы CASC не читаются
и не изменяются; текущая загрузка 84,6 ГиБ может продолжаться.

Сначала собирается отдельный образ на том же ядре. Используются кеш сборки
чистого сервера и копия его runtime-образа. Полная линковка обязательна до
остановки сервисов. Изменение Player.h требует пересборки зависимых файлов;
это может занять значительное время на двух потоках.

После успешной сборки останавливаются worldserver, bnetserver и web.
MySQL и его том остаются на месте. Приватный сжатый снимок четырёх баз,
прежний Compose, состояние, controller и привязки только собственных скриптов
сохраняются в `~/WoWForEver-clean/advancement/<id>/`. Затем добавляются пять
таблиц прогресса модуля и его world-привязки. Таблицы аккаунтов, персонажей,
предметов и прочего прогресса не заменяются. Обычный автоимпорт базы отключён.

Только worldserver получает новый образ и включение модуля. Его ресурсы,
сертификаты, порт 8085, realm 70, билд 70658, MySQL, образ bnetserver и web
сохраняются. Готовность проверяется по живому TCP, online realm и сообщениям
текущего процесса о каталоге и протоколе 3 / 1.11.0. Число аккаунтов и
персонажей сравнивается до и после. При ошибке возвращаются прежние привязки,
образ и настройки; созданные таблицы прогресса не удаляются.

```bash
python3 scripts/enable-clean-advancement.py status
python3 scripts/enable-clean-advancement.py rollback --backup "$HOME/WoWForEver-clean/advancement/<id>/install.json"
```

Полный SQL-дамп, install.json и Compose содержат секреты и остаются локальными.
Сохраните checkout инструмента: обновлённый server.sh использует его путь.
Управление по-прежнему: `~/WoWForEver-clean/server.sh start|stop|restart|status`.
Переход на 70707 с включённым модулем потребует отдельного проверенного релиза;
старый маршрут обновления блокируется по версии базы, а не удаляет модуль.

## Автоустановка аддона в Multi 1.6

После успешной авторизации лаунчера, до записи параметров запуска и создания
процесса WoW, Multi проверяет семь файлов `Interface/AddOns/ForeverAscension`
в выбранной папке игры. Отсутствующий или повреждённый набор скачивается из
зафиксированной ревизии нашего GitHub-репозитория по HTTPS. Имена, размеры
и SHA-256 записаны в поставляемом манифесте лаунчера. Готовая исправная папка
не требует обращения к сети при следующих запусках.

Скачивание идёт во временную папку. Прежний аддон перемещается в
`<папка игры>/.forever-multi/addon-backups/<id>/ForeverAscension` только после
полной проверки нового набора. При ошибке замены он возвращается на место.
Другие аддоны, SavedVariables, WTF, EXE и Data не меняются. Ссылки/junctions
не принимаются. Если обязательный аддон скачать не удалось, WoW не запускается,
а журнал показывает причину и позволяет повторить попытку.

Дождитесь окончания текущей загрузки игры в Multi 1.5.1 перед заменой лаунчера.
Multi 1.6 сохраняет настройки и формат управляемого хранилища 70658; повторная
полная загрузка клиента для обновления лаунчера не требуется. При необходимости
пауза старого загрузчика сохраняет контрольные точки для продолжения.

После загрузки клиента подключите его и нажмите «Играть». Первая установка
аддона произойдёт автоматически. В игре откройте его командой `/ascension` или
`/fa`. Проверяйте получение каталога, выбор подкласса, покупку доступного навыка,
расход ресурсов, таланты и сохранение после повторного входа.

Перенос сохраняет ограничения существующей системы: работают только нативные
совместимые способности/таланты. Кастомный Mana-forged Barrier 701463 остаётся
заблокированным до реализации эффектов. Установка аддона не подтверждает
полноту игровых ресурсов и не заменяет тест входа в мир.


## Проверенная сборка

Multi 1.6.0: [скачать ZIP](https://github.com/Domenklay/WoWForEver/actions/runs/42233852826/artifacts/13511325368)
(для GitHub Actions нужен вход в GitHub). Архив, контрольные суммы EXE, архитектура,
исходники GPL-загрузчика и неизменность публичного CA проверены.

[Проверки ядра 70658](https://github.com/Domenklay/WoWForEver/actions/runs/42234269575):
401 Python-тест, 28 пропусков по условиям окружения, ошибок нет. На Ubuntu 24.04
с реальными заголовками ядра и CMake-флагами компилируются адаптер и четыре
изменённых файла ядра без зависимости от PCH. Windows: 56 тестов лаунчера,
220 тестов отдельного загрузчика, успешная сборка NSIS и portable.

Это не отчёт об установленном на ПК пользователя сервере или успешной покупке
навыка в игре. Полную сборку/линковку нового runtime-образа выполняет серверный
установщик до остановки сервисов. Итог — `ASCENSION ACTIVE`; затем необходим
реальный вход и проверка мультиклассов. Подробности: validation-70658.json
в mods/forever-advancement.
