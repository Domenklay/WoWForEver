# Извлечение оригинальных файлов запуска предзагрузки

Локальная проверка пользователя подтвердила европейский Wow.exe и общий
wow_loader.dll из пакета 70707: оба полностью прочитаны из локального CASC,
проверены по BLTE/EKey/CKey и отличаются от текущих файлов 70658. В INSTALL
выбрано 39 файлов Windows x86_64/EU. Источник всё ещё активен как 70658.

`scripts/stage-client-preload.py` извлекает **все выбранные INSTALL-файлы**,
включая EXE/DLL и вспомогательные файлы, в **новую отдельную папку**.
Он не запускает EXE и не использует исходные распакованные файлы как замену
отсутствующим данным предзагрузки. Для каждого файла нужны целевой ENCODING,
проверенная локальная копия CASC, совпадение CKey и размера; после записи
проверяется повторное чтение. Отчёт содержит также SHA-256.

Затем Windows PowerShell читает строковые FileVersion и ProductVersion
сохранённого Wow.exe. Обе версии должны однозначно указывать 1.60.1.70707.
Строковые версии нужны потому, что 70707 не помещается в 16-битное поле
фиксированного PE-ресурса версии. Код игры при этом не выполняется.

Скрипт не скачивает данные, не делает hardlink, не меняет источник, Data,
.build.info, .flavor.info, WTF, настройки лаунчера или сервер. Он не
переносит аккаунты/персонажей и не изменяет базы. Существующая папка назначения
всегда отвергается. Изменение метаданных/размеров/времени архивов источника
во время операции даёт отказ. Варианты CN и другие архитектуры исключаются
именованными масками, а не выбором первой записи Wow.exe.

## Выполнение в Ubuntu/WSL

Закройте игру и ForeverLauncher и дождитесь окончания фоновых загрузок.
Нужна Windows PowerShell interop и свободное место под выбранные файлы
(не под вторую полную копию Data). В этом примере папка на E: обеспечивает
доступ Windows к EXE для чтения версии:

```bash
(
set -euo pipefail
cd "$HOME/WoWForEver"
git fetch origin codex/preload-audit-20261106
preload_tools=$(mktemp -d "$HOME/WoWForEver-preload-tools.XXXXXX")
git worktree add --detach "$preload_tools" FETCH_HEAD
stage_parent='/mnt/e/WoWForEver-work/staging'
mkdir -p "$stage_parent"
stage_destination="$stage_parent/client-70707-$(date +%Y%m%d-%H%M%S)"
python3 "$preload_tools/scripts/stage-client-preload.py" \
  --client '/mnt/e/WoW_Forever' --region EU \
  --destination "$stage_destination"
)
```

Ход выводится в терминал, JSON — в терминал и в `stage-report.json` в новой
папке. При успехе `phase: bootstrap-staged`, `exe_version_verified: true`,
а `native_exe_versions` содержит фактически прочитанные версии EXE.
`activated` остаётся false. При нехватке файла или отказе проверки версии
папка остаётся с `phase: incomplete` и описанием причины; существующий
клиент не затрагивается. Повторный запуск требует новую папку и не стирает
предыдущий результат.

**Это ещё не игровая установка.** Не выбирайте папку staging в Multi и
не запускайте из неё Wow.exe: в ней нет Data и активных метаданных клиента.
Успех подтверждает набор файлов запуска и версию EXE, но не полноту
моделей/карт, не протокол сервера и не исчезновение зависания. Полная
установка в независимую копию и согласование CASC должны быть отдельным
этапом, после чего возможен описанный в SERVER-UPGRADES.ru.md переход
сервера/БД. Текущий сервер пока сохраняется на 70658.
