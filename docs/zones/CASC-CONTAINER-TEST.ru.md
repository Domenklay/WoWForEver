# Тест пустого служебного сегмента

Предыдущий ресурсный `casc-copy-canary.py apply` остаётся заблокированным.
Здесь другой, более узкий опыт: проверить, принимает ли WowB.exe добавление
пустого сегмента с исходным форматом служебных записей. Даларан ещё не добавляется.

## Что проверено

Пакет пользователя содержит 16 IDX и заголовки 48 архивных частей: 768
служебных записей по 30 байт. Для всех совпали ключи, местоположения, флаг 1
и обе контрольные суммы. Второй контрольный код включает номер сегмента
в младших 32 битах общего адреса и абсолютное выравнивание маски адреса.
Предыдущая лабораторная реализация этих правил полностью не воспроизводила.
CascLib не проверяет этот код при обычном чтении; соответствующий код её
debug-функции также содержит отключённые assert. Это объясняет границы прежних
проверок и выявляет расхождение, но не доказывает единственную причину отказа игры.

Модуль `casc_native_container.py` воспроизводит исходные IDX без добавлений
побайтово. В кандидатах сохраняются все исходные записи, размер выделенного
файла и нулевое заполнение; в каждой корзине добавляется одна служебная запись
нового сегмента. Правила расширения IDX за пределы прежнего выделения не
выводятся: если места не хватает, опыт останавливается. Поддерживаются только
проверенный профиль смещений и номера сегментов до 255.

Облачный интеграционный тест открывает синтетическое хранилище настоящим
CascLib до/после установки и отката. Это не запуск WowB.exe. Сводка реального
пакета: `content/donors/legion-735/real-container-v2-review.json`.

## Установка опыта

Закройте игру и все лаунчеры. Восстановленная копия должна запускаться без
старого canary. Сервер продолжает работать, пересобирать его не требуется.

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/casc-container-canary.py apply \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1
```

Подготовка всех 16 IDX на Python может занять несколько минут. Успешное завершение:
`EMPTY SEGMENT VERIFIED`. Оно означает, что контрольные ресурсы читаются через
CascLib, а не что игра уже приняла контейнер.

В копию добавляются 480-байтный `data.048` и новые поколения всех 16 IDX.
В копии `shmem` меняются только наблюдаемые поля поколений. `.build.info`,
ROOT, ENCODING, DOWNLOAD, игровые ресурсы и существующие `data.NNN` скрипт
не изменяет. Сам WowB.exe при запуске может менять состояние копии.
Скрипт работает только в подготовленной независимой копии, исходный клиент
не изменяет. Свободное место проверяется.

Перед установкой все прежние IDX, `shmem` и LRU сохраняются с проверкой байтов
в `casc-container-operations/<идентификатор>/before` внутри копии. Журнал
`operation.json` фиксирует контрольные суммы и прежние поколения. При ошибке
после начала записи скрипт пытается выполнить откат автоматически.

## Проверка игры

1. В лаунчере оставьте папку
   `E:\WoWForEver-work\experiments\Forever-Legion-client-v1\_classic_beta_`.
2. Запустите копию, войдите персонажем в обычную локацию, затем закройте игру
   и лаунчер.
3. Проверьте, что опыт остался установленным:

   ```bash
   python3 scripts/casc-container-canary.py verify \
     /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1
   ```

Успех — `EMPTY SEGMENT STILL VERIFIED`. Проверяется сохранность нового сегмента,
новых IDX, активных поколений, исходной `.build.info` и контрольных ресурсов.
Если клиент изменил кандидаты, проверка об этом сообщит. Не повторяйте apply:
сохраните вывод и результат запуска. Поле успешного запуска не ставится скриптом
автоматически: это отдельное наблюдение пользователя.

## Откат

Если игра снова сообщает об ошибке установки, закройте игру и лаунчер:

```bash
python3 scripts/casc-container-canary.py rollback \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1
```

Откат восстанавливает все сохранённые служебные файлы, даже если клиент удалил
старые IDX или создал маркер ремонта. Текущее состояние и созданный сегмент
сохраняются в папке `after-<идентификатор>` рядом с резервной копией. Постороннее
изменение `.build.info` останавливает откат с объяснением. Если процесс был
принудительно завершён, используйте ту же команду и сохранённый журнал.
Игра не проверяется и не ремонтируется через сторонний лаунчер.
