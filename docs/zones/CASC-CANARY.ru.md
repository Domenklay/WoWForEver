# Контрольный импорт в проверенную копию клиента

После `COPY VERIFIED` проверяем добавление собственного текстового файла
в настоящее хранилище копии. Это ещё не установка Даларана и не проверка
запуска WowB.exe. Цель — проверить согласованную запись ROOT, ENCODING,
DOWNLOAD с 30 тегами, TVFS, нового data-сегмента и локальных IDX.

## Запуск

Закройте игру и лаунчер. Серверные контейнеры могут продолжать работать.
Нужен ранее собранный образ `forever-legion-casc-probe:local`: он использовался
для предыдущих проверок CKey. Скрипт использует его компилятор и CascLib,
чтобы собрать только небольшой checker во временном контейнере. Ядро сервера
повторно не собирается. Если образ недоступен или исходная проверка не пройдёт,
импорт останавливается до записи данных.

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/casc-copy-canary.py apply \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1
```

Работа идёт только с папкой, содержащей корректный `legion-client-copy.json`,
с исходным build key `ad1802f4455e427ed8b7769aab25b0c0` и неизменённой
`.build.info` из проверенной копии. Символические и жёсткие ссылки на данные
не принимаются. Пути к рабочему клиенту не перенастраиваются.

Скрипт сначала проверит четыре контрольных файла: `1120838`, `1120853`,
`1379264`, `1379316`. Их размеры и SHA-256 уже подтверждены на клиенте пользователя.
Потом он подготовит новый ресурс **16777214** с собственным коротким текстом,
согласованные манифесты и новые поколения IDX. Старые файлы в `Data` сохраняются;
единственный заменяемый существующий файл — `.build.info` внутри копии.

Потребуется несколько сотен мегабайт для новых метаданных плюс 256 MiB запаса.
Свободное место проверяется. Полные 48 GiB повторно не копируются.
Подготовка больших ENCODING/ROOT может занять время.

После записи отдельный контейнер CascLib снова откроет копию и прочитает
новый FileDataID и прежние четыре файла. Проверяются размеры, SHA-256 и
неизменность масок тегов контрольных ресурсов. Для собственного canary явно
задан пустой список тегов; из этого не выводятся правила для игровой геометрии.

Успех:

```text
CANARY VERIFIED: new FileDataID and existing control files read correctly.
Report: .../casc-canary-operations/<идентификатор>/result.json
```

Пришлите **result.json по напечатанному пути**. Он содержит исходный/новый
build key, параметры нового ресурса и результаты чтения до/после импорта,
включая реальные маски тегов моделей Даларана и исходные группы ROOT этих
FileDataID (локали, флаги, CKey). Это данные для выбора политики пакета;
автоматически она по ним не назначается. Файл не содержит игровых ресурсов.

## Ошибка или отмена

При ошибке после начала записи скрипт возвращает исходную `.build.info` копии
и удаляет только созданные им файлы. Если процесс был принудительно завершён,
для восстановления используется сохранённый журнал:

```bash
python3 scripts/casc-copy-canary.py rollback \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1
```

Повторное применение к уже изменённой копии запрещено до отката. Если файл
операции изменён посторонним процессом, откат остановится с объяснением,
сохраняя этот файл для разбора. Журнал и результаты остаются в
`casc-canary-operations` внутри копии. Запускайте rollback с закрытой игрой.

## Границы проверки

- Успешное чтение CascLib не доказывает, какие пути метаданных использует
  WowB.exe: библиотека может выбирать TVFS или переходить к legacy ROOT.
- На этом этапе Map/Area, серверные maps/vmaps и игровые ресурсы Даларана
  не устанавливаются. `dalaran_installed` и `wow_client_runtime_verified`
  остаются `false` в отчёте.
- После положительной проверки можно готовить пакет первого тайла Даларана
  с реальными тегами ресурсов, затем заниматься записью карты и геометрией.

Облачные тесты используют собственное синтетическое хранилище: смешанные
именованные/enUS и hashless/ruRU группы ROOT, 30 тегов с единицами в padding,
контрольные файлы с ненулевой маской тегов. Настоящий CascLib проверяет
новый FileDataID, сохранность исходных файлов и тегов, ручной/автоматический
откат и восстановление после имитации прерывания. Настоящая 48-GiB копия
находится на компьютере пользователя и в облаке не запускалась.
