# Результаты анализа образца Даларана

Проверен пользовательский `Legion-Dalaran-sample.zip` (2 836 279 байт).
ZIP CRC и SHA-256 всех 21 вложенных файлов совпали с sample-index.json;
18 исходных ресурсов также привязаны к ранее переданному манифесту.
Сам архив и игровые ресурсы в Git не добавляются.

## Что удалось прочитать

- WDT: MVER=18, MPHD=32 байта, MAIN=32768, MAID=131072.
- Для тайла 23_33: root ADT FileDataID **957774**, obj0 **956360**,
  obj1 **957241**, tex0 **956397**, lod **1250154**.
- ADT: все 256 уникальных MCNK и 256 MCVT, по 145 высот в каждой ячейке;
  AreaID 7502 (255 ячеек) и 8445 (1 ячейка).
- Рельеф под городом: −139.46…−78.02 по Z. Это не поверхность летающего Даларана.
- В obj0: 75 размещений M2 и 2 размещения WMO.
- dalaran2.wmo (FileDataID **1120838**): MVER=17, 125 базовых групп;
  в GFID 625 слотов LOD, из них 334 ненулевых. Все 334 ID перечислены в sidecar
  как экспортированные группы, и в полном отчёте есть 334 файла групп dalaran2.
  В маленьком образце физически проверены только группа 000 и её LOD1/LOD2.
- В группе 000 читаются MOVT, MOVI, MOPY и прочие подчанки геометрии.
- M2-образец: MD21 + SFID + TXID; отдельный SKIN имеет ожидаемый заголовок.
- CSV размещения указывает высоту основного WMO около **729.46**.
  Это координата размещения модели, не проверенная безопасная точка появления игрока.

## Проверка кодом Forever

В облачной машине собран небольшой C++ harness с неизменённым
`src/tools/map_extractor/loadlib.cpp` из коммита ядра
`91d49b230f89c3ab4719f5b2b2d1e70ed36613c4`.
Для чтения обычных файлов вместо CASC применён отдельный файловый shim.
Чтение WDT/ADT, MAIN/MAID, 256 уникальных MCNK/MCVT и диапазона высот прошло
в обычной сборке с проверками harness. Это подтверждает структурную читаемость,
но не полный запуск mapextractor, не сборку vmaps и не работу клиента.

Дополнительный запуск с sanitizer не является чистой проверкой: UBSan сообщает
о packed STL-полях в исходном loadlib.h, а LeakSanitizer в этом sandbox завершается
с ошибкой ptrace. Эти результаты не выдаются за прошедшую sanitizer-проверку.
Исходники ядра в рамках этой проверки не менялись.

## Локальная проверка ресурсов клиента 70532

Отсутствие карты 1220 в Map.db2 ещё не доказывает отсутствие каждого общего
ресурса в CASC. Перед подготовкой клиентского дополнения проверим конкретные
FileDataID и их SHA-256 внутри собственного клиента.

В Ubuntu:

```bash
cd ~/WoWForEver
git pull --ff-only
mkdir -p /mnt/e/WoWForEver-work/reports
docker compose --profile tools build legionprobe
docker compose --profile tools run --rm -T legionprobe \
  > /mnt/e/WoWForEver-work/reports/Forever-Legion-CASC.tsv
```

Собирается отдельный диагностический образ. Он использует исходники/CascLib
обычной build-стадии и её кэш, если он сохранился и параметры совпадают.
При отсутствии кэша сборка может заново компилировать ядро. Рабочие службы
этой командой не останавливаются и не пересоздаются.

Проба работает с `network_mode: none`, read-only корнем и монтированием клиента
только для чтения, без Linux capabilities. Не скачивает дополнительные ключи,
не включает ONLINE, не подменяет зашифрованные данные нулями; чтение происходит
с CASC_STRICT_DATA_CHECK. Хеш вычисляется после полного чтения файла.
Для одного файла установлен предел чтения 64 МиБ.

- READ_OK: файл полностью прочитан локально. Хеш нужно сравнить с донором:
  одинаковый FileDataID сам по себе не гарантирует одинаковые байты в двух сборках.
- OPEN_FAILED: файл не удалось открыть в текущем хранилище, см. код CascLib.
- READ_FAILED: ошибка чтения, включая отсутствие локальных блоков/ключа;
  это не доказательство, что ресурс вообще отсутствует на CDN.
- LOCAL_STORAGE_OPEN_FAILED: диагностика не смогла открыть сам клиент;
  сначала нужно разобраться с путём/продуктом/доступностью CASC.

Команда возвращает ненулевой код, если сама проверка не смогла запуститься.
Отсутствующие отдельные файлы записываются как результаты, поэтому код 0
не означает, что все ресурсы найдены.

Исходники пробы собраны с полным списком исходников CascLib из текущего ядра.
Конфигурация Compose проверена. Пользователь собрал Docker target и передал
результат чтения своего клиента; результаты ниже.

После отчёта выбирается доставка недостающих ресурсов и проверяется карта/area
через hotfix-таблицы. Подтверждённого пути подключения RAW к клиенту 70532 пока нет.
Простой перенос папки в Data и телепорт до подготовки коллизий не предусмотрены.

этой пробой не проверялись.

В переданном Forever Map.db2 среди 73 доступных записей нет Map 1220.
Остальные 8 записей находятся в недоступных секциях, их ID не подтверждены.
Сервер также отвечает «No maps found!» на поиск карты 1220.
Запись 3217 «Dalaran Skycuter» имеет WdtFileDataID=0; использовать её как

## Проверка конфигурации клиента 70532

В пользовательском Forever-CASC-config.zip четыре файла: .build.info и три
конфигурации Data/config. ZIP CRC корректны, MD5 каждой конфигурации совпал
с именем файла. Активный продукт — wow_classic_beta, версия 1.60.1.70532,
build-name WOW-70532patch1.60.1_Beta.
Сводка: [client-config-review.json](../../content/donors/legion-735/client-config-review.json).
Исходные конфигурации в Git не добавлены.

В build config одновременно есть legacy ROOT и vfs-root, а также 582 записи
vfs-N. Декодированный верхний TVFS-каталог занимает 37324 байта.
Сама конфигурация не содержит заголовок ROOT и не доказывает его версию.
Forever CascLib сначала пробует TVFS, но для WoW может перейти к legacy ROOT
через ERROR_REPARSE_ROOT. Успешный тест CascLib поэтому ещё не доказывает,
каким именно каталогом пользуется WowB.exe при загрузке новых файлов.

В проверенном TACT.Net (commit 57618c47dc0cfef1bfc0e7585bf335ced7218389)
нет реализации TVFS; RootHeader.Version 2/3 направляются в RootBlockV2,
отдельная реализация заголовка группы формата 58221 не найдена.
Использовать этот writer на рабочем клиенте без проверки форматов нельзя.
Запрос небольшого TVFS-манифеста к указанному в конфигурации зеркалу из облака
получил HTTP 403, поэтому далее проверяем локально.

### Прочитать метаданные локально

Обновлённый legionprobe принимает два CKey из переданной конфигурации.
Он читает первые 64 байта legacy ROOT и весь верхний vfs-root (не более 64 КиБ).
Игровые файлы и дочерние TVFS-манифесты этим режимом не выгружаются.
Первые 64 байта ROOT не являются проверкой целостности всего ROOT.
Сборка клиента и .env должны оставаться теми же, для которых передан архив.

```bash
cd ~/WoWForEver
git pull --ff-only
docker compose --profile tools build legionprobe
mkdir -p /mnt/e/WoWForEver-work/reports
docker compose --profile tools run --rm -T legionprobe \
  /wow wow_classic_beta --manifest-metadata \
  6e2657526d320facacb6f3dfff62d8a2 \
  64e9f21d6280d51d5949a63926874f53 \
  > /mnt/e/WoWForEver-work/reports/Forever-CASC-metadata.tsv
```

Передать нужно только Forever-CASC-metadata.tsv, содержимое клиентского Data
повторно архивировать не надо. Ожидаются строки PREFIX_READ_OK и FULL_READ_OK.
При ошибке чтения отчёт всё равно сохраняется, но команда возвращает код 1.
Изоляция контейнера прежняя: сеть отключена, клиент смонтирован только для чтения.
Команда собирает отдельный образ диагностики; повторное использование кэша
зависит от сохранности кэша и совпадения параметров build-стадии.

### Проверка нового режима разработчиком

Обновлённый probe собран с 31 исходником CascLib из текущего ядра.
Контролируемый C++ harness проверяет hex CKey, чтение префикса 64 байта,
полное чтение 37324 байт, предел 64 КиБ, пустой файл, короткое чтение
и ошибку открытия. Вывод проверен как TSV с настоящими разделителями.
Это проверка логики диагностики, а не запись CASC или запуск карты в клиенте.

```bash
c++ -std=c++20 -I/path/to/TrinityCore/dep/CascLib/src \
  tools/legion-casc-probe/test-metadata.cpp -lcrypto -o /tmp/test-casc-metadata
/tmp/test-casc-metadata > /tmp/test-casc-metadata.tsv
```
