# Включение тестового Даларана через hotfix

Проверка геометрии на компьютере пользователя прошла: один файл рельефа,
1093 модели столкновений, 101 попадание в поверхность города. Девять файлов
столкновений относятся к пересечениям моделей с соседними ячейками; полноценный
рельеф есть только у ячейки X=33, Y=23.

Этот этап включает карту на сервере и объявляет её клиенту через штатный механизм
hotfix. Клиент получает запись Map 1220 при следующем входе. Исходный Map.db2,
его зашифрованные секции и контейнеры CASC не заменяются. Фактический приём нового
Map hotfix клиентом 70532 ещё требует проверки в игре.

## Установить

Закройте игру и лаунчер. Сборка сервера не нужна. Docker должен работать, а
`worldserver` — завершить загрузку и сообщить `ready`.

```bash
cd ~/WoWForEver
git pull --ff-only

python3 scripts/activate-legion-map.py apply \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1 \
  --geometry /mnt/e/WoWForEver-work/geometry/Legion-Dalaran-tile-v1
```

Установщик проверяет 8655 ресурсов тестовой копии, контрольные суммы геометрии,
соответствие локальной Map.db2, схему hotfix и отсутствие карты 1220. Он создаёт
папку `backups/legion-map-*` в репозитории, изолирует имена моделей и проверяет
полученные столкновения настоящим серверным кодом. Файлы `.vmtileidx` тоже
проверяются и переносятся: они необходимы этому ядру, хотя старый отчёт извлечения
их не перечислял.

Затем на время останавливаются `worldserver`, `bnetserver` и сайт, сохраняется
архив четырёх баз, добавляются новая геометрия и строки Map/hotfix/телепорта.
Старые модели и общий `GameObjectModels.dtree` не перезаписываются. Навигационная
сетка отсутствует, поэтому требуется существующая настройка `MMAP_PATHFINDING=0`.
Бэкап содержит приватные данные: оставьте его локально.

При ошибке после остановки выполняется автоматический откат. Если откат не смог
завершиться, установщик явно сообщает это и путь к сохранённой копии. После
успеха должны появиться строки `MAP 1220 ENABLED ON SERVER` и `Backup/report`.

## Войти и проверить

Запустите **тестовую копию** через лаунчер:

```text
E:\WoWForEver-work\experiments\Forever-Legion-client-v1\_classic_beta_
```

Войдите персонажем в существующий мир. Затем в WSL:

```bash
cd ~/WoWForEver
python3 scripts/activate-legion-map.py visit KAY
```

Это команда серверной консоли через SOAP; права GM персонажу не нужны.
Тестовый телепорт размещает персонажа на два метра выше выбранной точки
столкновения. Она проверена лучом, но успешное появление и возможность ходить
пока не подтверждены. Оставайтесь возле места прибытия: за пределами одного
тайла рельеф ещё не перенесён. НПС и монстры не добавляются этим установщиком.

Если нужно вернуться домой, выполните в WSL:

```bash
python3 scripts/activate-legion-map.py home KAY
```

Команда поддерживает и персонажа вне игры. Если клиент не принял hotfix или
телепорт не сработал, пришлите ответ команды и вывод:

```bash
python3 scripts/activate-legion-map.py status
```

## Откатить

Закройте игру и лаунчер:

```bash
cd ~/WoWForEver
python3 scripts/activate-legion-map.py rollback
```

Откат удаляет только добавленные файлы и собственные строки базы. Персонажи,
оставшиеся на карте 1220, возвращаются к своим точкам привязки; прочий прогресс
не откатывается. Сервер объявляет удаление тестовой карты новым hotfix, который
клиент получает при следующем входе. Резервные копии сохраняются.

## Проверено в облаке

Переименование моделей и сохранение индексов проверены на собственной геометрии
без игровых ресурсов: серверный VMapManager по-прежнему возвращает ожидаемую
высоту в 110 точках. В отдельном MySQL 8 проверены установка, русское имя карты,
откат, сохранение посторонних строк и возврат персонажей из тестовой карты.
Эти проверки не заменяют тест приёма hotfix и телепортации клиентом пользователя.

## Ошибка потоковой загрузки WOW51900322

На компьютере пользователя hotfix Map 1220 получил `VALIDATION_RESULT_VALID`,
но при загрузке карты клиент запросил отключение и показал WOW51900322.
Успешная телепортация и ходьба не подтверждены. Код не называет конкретный файл;
ошибку нельзя считать доказательством неисправности сервера или архива CASC.

Верните персонажа через `home KAY`, закройте игру и лаунчер и соберите отчёт
о типах ресурсов. Уже установленный пакет использовал общую группу ROOT;
проверка сравнивает её с метаданными файлов рабочего мира. Роли вспомогательных
WDT и разных ADT определяются по слотам MPHD/MAID, поскольку одного расширения
файла недостаточно.

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/audit-legion-root-types.py \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1 \
  --resource-report /mnt/e/WoWForEver-work/packages/Legion-Dalaran-private-v2/report.json \
  --output /mnt/e/WoWForEver-work/reports/Dalaran-ROOT-types-v1.json
```

Пришлите `E:\WoWForEver-work\reports\Dalaran-ROOT-types-v1.json`.
Команда не меняет клиент или сервер и не обращается к CDN. Если файл отчёта уже
существует, используйте новое имя, например `Dalaran-ROOT-types-v2.json`.

## Исправить типы ROOT/TVFS

Полученный отчёт показал у всех 2912 приватных ID общую группу с типом 0.
Штатные WDT имеют тип 39, ADT — 34, TEX — 37, WDL — 38. Текстурные ADT имеют
другой набор флагов хранения, чем основные и объектные ADT.

Сначала выполните `python3 scripts/activate-legion-map.py home KAY`, затем
закройте игру и лаунчер. После обновления Git выполните:

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/repair-legion-root-types.py apply \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1 \
  --resource-report /mnt/e/WoWForEver-work/packages/Legion-Dalaran-private-v2/report.json \
  --namespace-report /mnt/e/WoWForEver-work/reports/Legion-Dalaran-private-ids.json \
  --type-audit /mnt/e/WoWForEver-work/reports/Dalaran-ROOT-types-v1.json
```

Команда сохраняет служебные файлы и создаёт отдельный слой метаданных. Она
переписывает только приватные группы ROOT и их имена в TVFS, согласует ENCODING
и конфигурацию, создаёт новый сегмент с нативными заголовками и 16 IDX. Игровые
модели и текстуры не переписываются; сервер не перезапускается.

2441 профиль берётся из записи исходного ID, 12 — из проверенных слотов WDT
рабочего мира, 459 — из преобладающего профиля того же вида модели/текстуры.
Для последней группы проверяется сигнатура данных; корни WMO и группы WMO
различаются. Отсутствующие или неоднозначные профили останавливают операцию.
Все старые группы ROOT и посторонние ссылки TVFS сохраняются. Режим без имён
явно включается для новых ID, которые открываются по FileDataID.

После записи проверяются содержимое всех 8655 ID настоящим CascLib и профили
в активном ROOT по каждому новому ID. CascFileFullInfo иногда возвращает флаги
первой записи с одинаковым CKey, поэтому одного этого API для проверки типов
недостаточно. При ошибке восстанавливаются предыдущие метаданные и указатель
на исходную операцию установки ресурсов.

Дождитесь `ROOT TYPES REPAIRED AND READ VERIFIED`. Пришлите указанный в конце
`result.json`. Затем запустите тестовую копию и проверьте вход в прежний мир.
Если тестовая карта ещё включена на сервере, повторите `visit KAY`. Если её
отключали, команда `apply` из начала документа теперь принимает ресурсный слой
с исправленными типами и проверяет его связь с исходной геометрией.

Это исправление известного отличия метаданных. Устранение WOW51900322 и ходьба
по карте должны быть подтверждены повторным тестом клиента.

Отменить только исправление типов (игра и лаунчер закрыты):

```bash
python3 scripts/repair-legion-root-types.py rollback \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1
```

Этот откат оставляет исходные 2912 ресурсов установленными. Для отключения
карты на сервере используется отдельная команда `activate-legion-map.py rollback`.

После этого исправления WOW51900322 сохранилась. Игровой UI показал зелёную
область для нового ID текстуры при работающем исходном ID. Следующий этап:
[проверка правильного вложенного каталога TVFS на одной текстуре](LEGION-TVFS-TEXTURE.ru.md).
