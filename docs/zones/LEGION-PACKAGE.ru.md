# Подготовка пакета одного тайла Даларана

На тестовой копии пользователь подтвердил запуск WowB.exe и последующий `verify`
после добавления пустого сегмента, затем собственного текстового ресурса с
новыми ROOT/ENCODING/DOWNLOAD/TVFS. Это проверка записи CASC, а не Legion-карты.
Следующий инструмент готовит ресурсы и отчёт для первого тайла.

## Одна команда подготовки

В WSL:

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/prepare-legion-zone.py \
  /mnt/e/WoWForEver-work/exports/Legion-Dalaran-raw-v2 \
  --tile 23_33 \
  --output /mnt/e/WoWForEver-work/packages/Legion-Dalaran-tile-23_33-v1
```

Выходная папка создаётся автоматически и должна быть новой. При повторном
запуске укажите `-v2` в конце её имени, чтобы сохранить прежний результат.
Папка RAW остаётся неизменной. Скрипт не обращается к клиенту и серверу,
не устанавливает патч и не скачивает игровые файлы. Нужен только Python 3.

Результаты:

- `report.json` — хеши, сопоставления FileDataID, разобранные ссылки,
  ненайденные зависимости и ограничения. **Пришлите только этот файл.**
- `tile-candidate.zip` — локальный пакет найденных ресурсов и его индекс.
  Его размер может составлять сотни MiB: весь Даларан ссылается на многие
  модели и текстуры. ZIP с игровыми ресурсами в Git не добавляем и в чат
  без отдельной необходимости не пересылаем.

Ненулевой список `missing_from_export` — результат проверки, а не признак
неудачного запуска команды. Такие FileDataID могут уже присутствовать в
Forever, но это проверяется отдельно. Подготовка считается завершённой после
печати путей ZIP и отчёта; это не означает готовность карты к установке.

## Что делает инструмент

1. Находит root ADT выбранного тайла, проверяет 256 уникальных MCNK и координаты
   начала тайла. Сверяет порядок осей с WDT и справочником FileDataID.
2. Привязывает root/obj0/obj1/tex0/lod из выбранной записи MAID и дополнительные
   файлы MPHD. Создаёт в пакете копию WDT, в которой MAIN и MAID оставляют
   только одну клетку. Исходный WDT не изменяется.
3. Разбирает MDDF/MODF, MDID/MHID, GFID/MODI/MOMT, M2/SKEL-чанки
   SFID/TXID/SKID/BFID/AFID/PFID/RPID/GPID/SKPD. Обходит зависимости рекурсивно,
   включая все указанные группы и наборы декораций WMO. Поэтому пакет может
   быть значительно больше одного terrain ADT.
   В MODI выбирает модели, на которые ссылаются реальные размещения MODD
   (все наборы). Неиспользованные ID записывает отдельно в
   `unplaced_wmo_model_ids`, не изменяя таблицу или её индексы в самом WMO.
   Если MODD отсутствует, сохраняет консервативный обход всей MODI.
4. Использует sidecar-файлы wow.export и небольшой справочник имён
   `content/donors/legion-735/export-filedata.csv`. Для WMO поддерживает
   относительные пути из виртуального каталога модели. При неоднозначности
   отказывается угадывать. Обычные `unknown/<FileDataID>.<тип>` тоже распознаются.
5. Проверяет SHA-256 файлов при разборе и упаковке, повторно читает ZIP,
   записывает CKey (MD5 распакованных байтов). Изменение исходного ресурса
   во время работы останавливает подготовку; неполная выходная папка удаляется.

Справочник — только открытые ID и имена из community-listfile, используемого
wow.export. В Git сохранён отфильтрованный набор для текущей выгрузки;
источник, хеш полного справочника и хеш поднабора записаны рядом в
`export-filedata-source.json`. Справочник не подтверждает сборку или
содержимое файла. Для другой зоны можно передать свой CSV через `--catalog`;
номер карты и сборка задаются `--map-id` и `--build`.

`known_reference_closure` относится только к разобранным ссылкам.
`full_dependency_closure_proven` и `installable` остаются `false`: не все
встроенные/устаревшие ссылки разобраны. Необработанные MLMD/MLMX, legacy
MD20/именованные WMO и вспомогательные карты указываются в `coverage_limits`.
Даже отсутствие ненайденных ссылок не доказывает совместимость с Forever.
Остаются проверка форматов и политики ROOT/тегов, коллизий FileDataID,
клиентская/серверная запись Map, серверные maps/vmaps и безопасная точка входа.

## Исправление прежнего порядка осей

В раннем разборе sample был неверно выбран raw-индекс `23*64+33`.
Исходники wow.export `WDTLoader.js` транспонируют native-таблицу, а
`ADTExporter.js` записывает имя `tileY_tileX`. Поэтому файл `23_33` относится
к x=33, y=23 и native-индексу `33*64+23 = 2135`.
Это дополнительно подтверждают начало MCNK (-533.333984375, 4800) и открытый
справочник имён.

| Файл выгрузки | Правильный FileDataID |
|---|---:|
| troll raid_23_33.adt | 957382 |
| troll raid_23_33_obj0.adt | 956935 |
| troll raid_23_33_obj1.adt | 956745 |
| troll raid_23_33_tex0.adt | 957702 |
| troll raid_23_33_lod.adt | 1250383 |
| troll raid.wdt | 957721 |

Исторические ID-запросы 957774/956360/956397 относились к другой клетке.
Их `OPEN_FAILED` нельзя приписывать исправленным ID. Результаты запросов
точных CKey/хешей исходных файлов сохраняют силу, потому что не зависели
от выбора FileDataID. Исторические отчёты помечены этим уточнением, цели
новых исходных probe/audit исправлены. Уже собранный старый probe-образ
сам от изменения исходников не обновляется; текущий упаковщик его не использует.

## Разбор полной выгрузки пользователя

Полученный пакет содержит 7104 файла, 535850698 байт до сжатия, без ошибок
разбора. Из 77 ненайденных ID 74 относятся к MODI здания dalaran2.wmo,
но не упоминаются ни одним из 9545 размещений MODD. Проверен SHA-256 WMO:
он совпал с ранее присланным образцом, в котором удалось разобрать все
индексы. Эти 74 ID не считаются зависимостями размещённых декораций;
это не доказательство того, что любой путь загрузки клиента игнорирует
неиспользованные записи. Сам WMO остаётся неизменным.

Остаются три ссылки WDT: 952131 (мини-карта), 1246678 и 1246679
(текстуры отображения местности). Сначала проверяем их в исходном Forever:

```bash
bash scripts/check-client-casc.sh /mnt/e 952131 1246678 1246679
```

Нужен тот же локальный образ CascLib, который использовался при canary.
Небольшой checker компилируется из текущего исходника; серверное ядро не
пересобирается. Проверка выполняется с read-only mount и без сети, читает
файлы порциями по 64 KiB, до 64 MiB на файл, печатает размеры и SHA-256.
`READ_OK` подтверждает локальное чтение, но без сравнения с донором не
подтверждает совпадение его версии. `OPEN_FAILED` не нужно заменять
случайной текстурой. Большой ZIP пока повторно собирать не требуется.

Результаты разбора: `content/donors/legion-735/full-tile-package-review.json`.
Восемь оставшихся разделов с неполным разбором ссылок по-прежнему указаны
в `coverage_limits`. Установка карты на этом этапе не заявляется.

## Сопоставление всего пакета с Forever

Пользователь подтвердил `READ_OK` для всех трёх текстур в исходном клиенте.
Далее проверяем, какие ресурсы уже совпадают и какие FileDataID конфликтуют:

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/plan-legion-client.py \
  /mnt/e/WoWForEver-work/packages/Legion-Dalaran-tile-23_33-v1/report.json \
  --client /mnt/e \
  --output /mnt/e/WoWForEver-work/reports/Legion-Dalaran-client-plan.json
```

Проверяется хеш существующего ZIP и совпадение отчёта с его внутренним индексом.
Большой пакет не пересобирается. Для точного исторического отчёта v1 используется
проверенное уточнение MODI из разбора выше: 74 неразмещённых модели не попадают
в список недостающих ресурсов. К произвольному другому отчёту это исключение
не применяется; новый упаковщик уже записывает их отдельно.

Один контейнер CascLib без сети и с read-only mount читает все требуемые
FileDataID, считает SHA-256 и печатает CKey, маску локалей, ContentFlags и
TagBitMask. Python сверяет каждый результат и показывает прогресс. Нужен
прежний образ `forever-legion-casc-probe:local`; серверное ядро не собирается.

В JSON различаются:

- `identical`: размер и SHA-256 совпали с пакетом; ненулевой native CKey тоже
  должен совпасть. Такие ресурсы можно рассматривать для повторного использования.
- `source_matches_but_package_transformed`: локальный файл совпал с исходником,
  но пакет содержит производную версию. В частности, WDT обрезан до одного тайла.
- `different_content_same_id`: ID существует, но содержимое другое. Автоматическая
  замена не выполняется; требуется явная схема переназначения или замены.
- `not_readable_requires_ROOT_check`: локальное открытие не удалось. Это не
  доказательство, что ID свободен во всех вариантах ROOT.
- `read_error` / `inconsistent_native_ckey`: проверка не завершена либо
  отпечатки противоречат друг другу; эти случаи не считаются отсутствием файла.
- `not_locally_resident`: актуальный checker получил ошибку CascLib 1007 при
  запросе размера/чтении, выбранные данные недоступны локально. Отдельный
  `size_limit_not_checked` обозначает защитный предел 64 MiB. Старый checker
  объединял два случая в SIZE_FAILED, поэтому исторический отчёт уточняется
  по ENCODING/IDX, а не объявляется повреждением текстур.

У трёх внешних текстур выводятся локальные отпечатки, но их совпадение с донором
не утверждается: в экспортном пакете их байтов нет. Профили ROOT/тегов собираются
только для ресурсов, совпавших по отпечатку. Они ещё не назначаются новым файлам.
`.build.info` проверяется до и после обхода; смена сборки останавливает публикацию
отчёта. Клиент не изменяется, существующий выходной JSON не перезаписывается.

Пришлите только `E:\WoWForEver-work\reports\Legion-Dalaran-client-plan.json`.
План остаётся `installable: false`: геометрия сервера, запись Map и политика
изменения FileDataID — отдельные этапы.

## План отдельных ID для изменённых ресурсов

В сравнении пользователя совпали 5175 файлов (около 370.8 MiB). Ещё 564
отличаются, 471 ID не открылся, 894 текстуры получили SIZE_FAILED/1007.
Три внешние текстуры доступны. Сводка —
`content/donors/legion-735/client-comparison-review.json`.

Одной замены 1929 несовпавших/непроверенных ресурсов недостаточно: ссылки на
новые ID затронут и часть совпадающих моделей. По графу понадобятся отдельные
ID как минимум для 2912 ресурсов, включая 983 дополнительных родителя.
Это нижняя граница, пока наличие данных в самой тестовой копии не проверено.

Закройте игру и лаунчер, затем выполните в WSL:

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/plan-legion-namespace.py \
  /mnt/e/WoWForEver-work/reports/Legion-Dalaran-client-plan.json \
  --package-report /mnt/e/WoWForEver-work/packages/Legion-Dalaran-tile-23_33-v1/report.json \
  --target /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1 \
  --output /mnt/e/WoWForEver-work/reports/Legion-Dalaran-private-ids.json
```

Скрипт проверяет, что сравнение относится к исходной сборке этой копии.
Читает ROOT/ENCODING и локальные IDX из тестовой копии, без сети и Docker.
Подготовка на Python может занять несколько минут. Архив не пересобирается.

Планировщик учитывает все группы ROOT, включая другие локали и отсутствующие
локально файлы. Проверяет согласованность поколений IDX с `shmem`. Отбирает
свободные ID в диапазоне 0x00F00000..0x00FFFEFF, исключая все зарезервированные
и входные ID; это ниже проектных canary-ID. При нехватке диапазона отказывается
продолжать. Если меняется дочерняя ссылка, родителю и его изменяемым алиасам
тоже назначается отдельный ID. Прежние ID не перезаписываются.

В отчёте есть исходные группы ROOT, CKey/EKey-варианты и признаки наличия в
IDX. Они помогают отличать отсутствующие файлы от занятого ID с недоступными
данными. Само наличие префикса EKey в IDX ещё не считается полным чтением:
перед установкой нужен финальный контроль данных в целевой копии.
Для нескольких общеизвестных файлов Azeroth/Kalimdor проверяются доступные
нативные чанки как источники наблюдаемых профилей WDT/ADT; профили не угадываются
и пока не назначаются новым ресурсам.

Исходный `.build.info`, целевые `.build.info`/`shmem` и выбранные IDX проверяются
до и после обхода. При изменении снимка план не публикуется. Скрипт не меняет
клиент, не переписывает ссылки и не устанавливает карту. Результат:
`E:\WoWForEver-work\reports\Legion-Dalaran-private-ids.json` — пришлите этот файл.
После него можно готовить согласованное переписывание ссылок в приватном
пакете, с учётом оставшихся `coverage_limits`, записи Map и серверной геометрии.

## Сборка ресурсов с приватными ID

План пользователя проверен по 917 группам ROOT и 1 250 957 уникальным ID:
2912 ресурсов получили приватные ID, 4192 остаются кандидатами на использование
исходного ID. Включены родители изменяемых зависимостей: недостаточно перенести
только конфликтующую текстуру, нужно переписать ссылку в модели и её родителях.
Свободные ID относятся к конкретному снимку тестового клиента, не ко всем сборкам.

Теперь создаём отдельный пакет с фактическими заменами ссылок:

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/rewrite-legion-package.py \
  --package-report /mnt/e/WoWForEver-work/packages/Legion-Dalaran-tile-23_33-v1/report.json \
  --private-plan /mnt/e/WoWForEver-work/reports/Legion-Dalaran-private-ids.json \
  --output /mnt/e/WoWForEver-work/packages/Legion-Dalaran-private-v1
```

Ожидаются 2912 приватных файлов; ссылки требуют изменения в 1171 файле.
Инструмент читает уже собранный ZIP, проверяет его хеш и индекс, меняет только
типизированные поля FileDataID в поддержанных чанках WDT/ADT/WMO/M2/SKEL.
Координаты, размеры чанков и индексы MODD не изменяются. Для каждой замены
сохраняются смещение, старый и новый ID; результат повторно разбирается.
Необнаруженная ссылка, которую требуется переписать, останавливает сборку.

Результат — `private-resources.zip` и `report.json` в новой папке.
ZIP включает приватные ресурсы; в отчёте также остаются хеши кандидатов на
совместное использование. **Пришлите только новый `report.json`.**
Папки исходного экспорта, старого пакета, клиента и сервера не изменяются.
Временная выходная папка удаляется при неудачной сборке.

Это уже переписанные ресурсы, но ещё не устанавливаемая карта. Восемь разделов
с неполным разбором сохраняются в отчёте без заявления о полной замкнутости
зависимостей. Перед импортом нужны повторная проверка ROOT и чтение используемых
байтов в тестовой копии, корректные ROOT/теги, клиентская и серверная запись Map,
серверная геометрия и откатываемая установка CASC. Наличие записи в IDX само по
себе не доказывает успешного чтения файла.

## Map.db2: отдельный кандидат записи карты

Отчёт v2 содержит 5363 замены в 1174 файлах. На присланных исходных TEX/WDL
удалось независимо повторить 1102 замены ключей TEX и одну ссылку WDL,
сравнив итоговые SHA-256 с отчётом. Проверены все 8686 уникальных ключей TXBT:
каждое смещение указывает на существующий TXMD. Такие встроенные текстуры
не следует считать тысячами отсутствующих внешних файлов.

В WDL остаются три ссылки на внешние ресурсы, которых нет в пакете:

Создаём кандидат Map 1220 с WDT 15730590 из существующего пакета и одновременно


Пришлите только `E:\WoWForEver-work\packages\Legion-Dalaran-map-v1\report.json`.
Файл `Map.db2` рядом с ним — кандидат, который пока не копируем в клиент или
серверные `dbc`. CascLib проверяет внешние ID только на чтение, без сети.
Успешное чтение не доказывает совпадение с донором или наличие всех дочерних
ресурсов этих трёх моделей. Неудачное чтение записывается в отчёт, не маскируется.

Адаптер поддерживает конкретную структуру Map WDC5, layout `D43AFAC3`:
проверяет разделы, границы строк/палитр и занятые ID, добавляет значение WDT
в существующую палитру без расширения битовых полей. Добавляет раздел записи
после первого открытого раздела, корректирует относительные строковые указатели
ранних открытых записей и сохраняет байты всех непрозрачных разделов.
Map 0 остаётся первой записью: это важно для встроенной коррекции ID в ядре.
В конце добавляется раздел новых строк без записей.

На ранее загруженном Map.db2 реальный загрузчик TrinityCore прочитал 74 записи
вместо 73; все поля каждой старой доступной записи остались прежними. Новая
запись использует настройки Map 0 как экспериментальный шаблон с очищенным ZMP,
новым каталогом `ForeverDalaran` и приватным WDT. Это проверка файлового формата,
а не полноценной настройки карты. Принятие файла WowB.exe, настройки мира,
совпадение таблицы с текущим клиентом, установка CASC и серверная геометрия
ещё не подтверждены. Результаты исследования сохранены в
`content/donors/legion-735/private-resource-stage-v2-review.json`.

Серверный экспорт может содержать нулевые байты вместо недоступных секций.
Поэтому его наличие и успешный разбор не означают побайтового совпадения с
Map.db2 клиента. Скрипт дополнительно запрашивает FileDataID 1349477 через
CascLib и сравнивает SHA-256 с экспортом. `source_build_match_verified` становится
`true` только при полном совпадении; ошибка чтения или отличия остаются блокером
импорта, несмотря на успешную подготовку отдельного кандидата.


## Языковой вариант Map.db2 при проверке CascLib

Пользователь подтвердил READ_OK для трёх внешних ID WDL; это подтверждает
чтение корневых файлов, но не совпадение с донором и не полный обход зависимостей.
Map.db2 1349477 при прежнем запросе всех локалей вернул SIZE_FAILED/1007.
В используемой CascLib 1007 — ERROR_FILE_OFFLINE: выбранная запись не имеет
доступного локального файла. Для локализованной таблицы это ещё не результат
проверки конкретного ruRU-варианта.

Теперь checker поддерживает `CASC_CHECK_LOCALE=all|ruRU|enUS` (по умолчанию all).
Маска применяется при открытии хранилища и файла, передаётся внутрь контейнера.
При SIZE_FAILED выводится выбранный CKey, полученный из метаданных до чтения;
это не хеш успешно прочитанных байтов. Проверка остаётся без сети и без записей
в клиент. Языковые варианты не подменяются друг другом при ошибке.

```bash
cd ~/WoWForEver
git pull --ff-only
CASC_CHECK_LOCALE=ruRU bash scripts/check-client-casc.sh \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1 \
  1349477
```

На собственном синтетическом CASC проверен случай одного FileDataID с двумя
языковыми вариантами: enUS намеренно отсутствует в IDX и возвращает 1007 с
правильным CKey; ruRU читается и совпадает с ожидаемыми байтами. Это тест
выбора языка, а не утверждение об успешном чтении Map.db2 пользователя.

## Результат ruRU: граница защищённой секции

Пользователь получил для 1349477 с `locale_mask=2000`:
`READ_FAILED`, 11546 прочитанных байт, ошибка 1005. В закреплённой CascLib
1005 — `ERROR_FILE_ENCRYPTED` (поток не нашёл ключ файла), а не ошибка
целостности. В ранее присланном серверном экспорте первая непрозрачная секция
начинается ровно с 11546; три таких секции описывают восемь записей.
Совпадение границы объясняет остановку, но без полного хеша не подтверждает
побайтовое совпадение двух таблиц.

Следующий шаг — команда раздела «Map.db2: отдельный кандидат записи карты».
`prepare-legion-map-record.py --check-client` сохраняет ошибку чтения в отчёте,
оставляет `source_build_match_verified=false` и создаёт отдельный кандидат.
Непрозрачные секции экспортного файла сохраняются без расшифровки и без изменения
их байтов. Это не означает восстановления недоступных секций исходного CASC.
Полученный Map.db2 пока не устанавливается: прежде нужны проверка политики
клиентской таблицы, установка CASC с откатом и серверная геометрия.
