# Подготовка пакета одного тайла Даларана

На тестовой копии пользователь подтвердил запуск WowB.exe и последующий `verify`
после добавления пустого сегмента, затем собственного текстового ресурса с
новыми ROOT/ENCODING/DOWNLOAD/TVFS. Это проверка записи CASC, а не Legion-карты.
Следующий инструмент готовит ресурсы и отчёт для первого тайла.

## Одна команда подготовки

В WSL:

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/prepare-legion-zone.py \
  /mnt/e/WoWForEver-work/exports/Legion-Dalaran-raw-v2 \
  --tile 23_33 \
  --output /mnt/e/WoWForEver-work/packages/Legion-Dalaran-tile-23_33-v1
```

Выходная папка создаётся автоматически и должна быть новой. При повторном
запуске укажите `-v2` в конце её имени, чтобы сохранить прежний результат.
Папка RAW остаётся неизменной. Скрипт не обращается к клиенту и серверу,
не устанавливает патч и не скачивает игровые файлы. Нужен только Python 3.

Результаты:

- `report.json` — хеши, сопоставления FileDataID, разобранные ссылки,
  ненайденные зависимости и ограничения. **Пришлите только этот файл.**
- `tile-candidate.zip` — локальный пакет найденных ресурсов и его индекс.
  Его размер может составлять сотни MiB: весь Даларан ссылается на многие
  модели и текстуры. ZIP с игровыми ресурсами в Git не добавляем и в чат
  без отдельной необходимости не пересылаем.

Ненулевой список `missing_from_export` — результат проверки, а не признак
неудачного запуска команды. Такие FileDataID могут уже присутствовать в
Forever, но это проверяется отдельно. Подготовка считается завершённой после
печати путей ZIP и отчёта; это не означает готовность карты к установке.

## Что делает инструмент

1. Находит root ADT выбранного тайла, проверяет 256 уникальных MCNK и координаты
   начала тайла. Сверяет порядок осей с WDT и справочником FileDataID.
2. Привязывает root/obj0/obj1/tex0/lod из выбранной записи MAID и дополнительные
   файлы MPHD. Создаёт в пакете копию WDT, в которой MAIN и MAID оставляют
   только одну клетку. Исходный WDT не изменяется.
3. Разбирает MDDF/MODF, MDID/MHID, GFID/MODI/MOMT, M2/SKEL-чанки
   SFID/TXID/SKID/BFID/AFID/PFID/RPID/GPID/SKPD. Обходит зависимости рекурсивно,
   включая все указанные группы и наборы декораций WMO. Поэтому пакет может
   быть значительно больше одного terrain ADT.
4. Использует sidecar-файлы wow.export и небольшой справочник имён
   `content/donors/legion-735/export-filedata.csv`. Для WMO поддерживает
   относительные пути из виртуального каталога модели. При неоднозначности
   отказывается угадывать. Обычные `unknown/<FileDataID>.<тип>` тоже распознаются.
5. Проверяет SHA-256 файлов при разборе и упаковке, повторно читает ZIP,
   записывает CKey (MD5 распакованных байтов). Изменение исходного ресурса
   во время работы останавливает подготовку; неполная выходная папка удаляется.

Справочник — только открытые ID и имена из community-listfile, используемого
wow.export. В Git сохранён отфильтрованный набор для текущей выгрузки;
источник, хеш полного справочника и хеш поднабора записаны рядом в
`export-filedata-source.json`. Справочник не подтверждает сборку или
содержимое файла. Для другой зоны можно передать свой CSV через `--catalog`;
номер карты и сборка задаются `--map-id` и `--build`.

`known_reference_closure` относится только к разобранным ссылкам.
`full_dependency_closure_proven` и `installable` остаются `false`: не все
встроенные/устаревшие ссылки разобраны. Необработанные MLMD/MLMX, legacy
MD20/именованные WMO и вспомогательные карты указываются в `coverage_limits`.
Даже отсутствие ненайденных ссылок не доказывает совместимость с Forever.
Остаются проверка форматов и политики ROOT/тегов, коллизий FileDataID,
клиентская/серверная запись Map, серверные maps/vmaps и безопасная точка входа.

## Исправление прежнего порядка осей

В раннем разборе sample был неверно выбран raw-индекс `23*64+33`.
Исходники wow.export `WDTLoader.js` транспонируют native-таблицу, а
`ADTExporter.js` записывает имя `tileY_tileX`. Поэтому файл `23_33` относится
к x=33, y=23 и native-индексу `33*64+23 = 2135`.
Это дополнительно подтверждают начало MCNK (-533.333984375, 4800) и открытый
справочник имён.

| Файл выгрузки | Правильный FileDataID |
|---|---:|
| troll raid_23_33.adt | 957382 |
| troll raid_23_33_obj0.adt | 956935 |
| troll raid_23_33_obj1.adt | 956745 |
| troll raid_23_33_tex0.adt | 957702 |
| troll raid_23_33_lod.adt | 1250383 |
| troll raid.wdt | 957721 |

Исторические ID-запросы 957774/956360/956397 относились к другой клетке.
Их `OPEN_FAILED` нельзя приписывать исправленным ID. Результаты запросов
точных CKey/хешей исходных файлов сохраняют силу, потому что не зависели
от выбора FileDataID. Исторические отчёты помечены этим уточнением, цели
новых исходных probe/audit исправлены. Уже собранный старый probe-образ
сам от изменения исходников не обновляется; текущий упаковщик его не использует.
