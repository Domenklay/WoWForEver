Дата проверки: 28 октября 2026. Это отдельное исследование доноров, а не
возобновление установки Даларана в CASC. Аддон и работающий сервер не менялись.

нужными картами, размещениями NPC и сценариями не найдено.

## Реальная проба извлечения и конвертации

Из серверного архива релиза `v1.0.0` wow-server-data потоком извлечён
`maps/5303324.map`: по соглашению имён AzerothCore это Map 530, сетка 33/24.
Прочитано около 9.54 MiB сжатого потока из архива размером около 1.28 GB.
Весь архив и его завершающая gzip-проверка не проверялись; для конкретных
извлечённых байтов вычислены SHA-256. Принадлежность тайла не подтверждена
независимой сверкой с исходным клиентом.

Образец имеет формат `MAPS` версии **9**, build **12340**. Закреплённое ядро
Forever ожидает целочисленную версию **10** и отклоняет версию 9. Помимо номера
версии обнаружено реальное различие: отверстия рельефа занимают 512 байт
в доноре и 2048 байт в Forever. Простая замена номера оставила бы неверный блок.

Добавлен офлайн-конвертер `scripts/convert-335-terrain.py`:

- Проверяет границы, непрерывность блоков, размеры высот и допустимые флаги.
- Сохраняет блоки областей и высот побайтово и сохраняет исходный build 12340.
- Расширяет отверстия 4×4 → 8×8 по правилу `TransformToHighRes` экстрактора Forever.
- Отказывается от тайлов с жидкостью: соответствие типов и флагов ещё не реализовано.
- Создаёт отдельный кандидат и отчёт `installable=false`; ничего не устанавливает.

В облаке создан кандидат:
`/workspace/scratch/ascension-map-review/forever-outland-terrain-v1/maps/0530_33_24.map`.
Исходный SHA-256:
`d6664c5ba1a1cb2acd80a75e517526bb67a8f2754c41f9278598ae3f0497e2f6`.
Кандидат:
`cb8af589cf57b2ee7d34379e4d80a5815105aefc54c3be642feb3cf70b4ed181`.
Реальные бинарные карты находятся только в исследовательской папке вне Git.

## Что не готово

Это конвертация **одного серверного тайла рельефа**, а не перенос игровой локации.
Последующая проверка `GridMap::loadData` и высот описана ниже.
Для полноценной локации ещё нужно проверить AreaTable, извлечь/адаптировать VMAP для зданий и столкновений,
проверить покрытие остальных тайлов и ресурсы клиента: запись Map, WDT, ADT,
модели, текстуры и зависимости. MMAP понадобится для корректного поиска пути.

Наличие готовых `.map` в пакете сервера не добавляет землю и текстуры в клиент.
Прочитанный ранее Map.db2 Forever не содержит доступной записи Map 530. Пока
это не решено, добавлять телепорт или hotfix карты на рабочий сервер преждевременно:
получение `.map` само по себе не устраняет прежнюю проблему загрузки CASC.

Открытый модуль классов не даёт серверную базу Ascension. Для его особых NPC,
квестов, достижений и боссов по-прежнему нужны отдельные проверенные данные.

Машиночитаемые результаты и ревизии:
`content/donors/ascension-style/map-donor-review.json`.

## Следующая проверка: настоящий GridMap Forever, 29 октября

Собрана отдельная программа `tools/terrain-335/check-gridmap.cpp`, которая
вызывает **неизменённый** `GridMap::loadData` закреплённого ядра Forever и его
`getHeight`. Клиент, worldserver и база для этой проверки не запускаются.
Сборка использует исходники ядра, кешированные common/G3D-библиотеки и удаление
неиспользуемых секций при линковке; код чтения рельефа не заменён заглушкой.
Исходные файлы закреплены SHA-256 в `tools/terrain-335/source-profile.json`.
Воспроизводимая сборка: `tools/terrain-335/build-probe.py` в подготовленном
окружении с исходниками, `compile_commands.json` и библиотеками ядра.

### Проверка на компьютере пользователя

Нужен уже использованный для Даларана локальный Docker-образ
`forever-legion-casc-probe:local`. Скрипт не собирает и не перезапускает сервер,
не меняет его базу, не копирует рельеф и не включает телепорт. Временная
компиляция маленькой программы выполняется внутри контейнера без сети;
клиент подключён только для чтения. Все результаты сохраняются отдельно:

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/outland-readiness.py /mnt/e \
  --output "/mnt/e/WoWForEver-work/reports/Outland-readiness-$(date +%Y%m%d-%H%M%S)"
```

Скрипт проверяет runtime-запись Map 530, перечисляет образцы серверной геометрии
и пытается прочитать по именам WDT Запределья и ADT пробного тайла. Для тайла
серверной сетки 33/24 основной кандидат клиентского ADT — `24_33`; обратный
вариант также включён как диагностическая проверка. Контрольный запрос — WDT
Восточных королевств.

Пришлите **`report.json` из напечатанной папки**. При ошибке сборки полезен также
`client.stderr.log` из той же папки. Неудача поиска по имени не доказывает
отсутствие ресурса по FileDataID; если не читается даже контроль, по этой пробе
нельзя заключать, что клиент не содержит Запределье. Успешное чтение нескольких
файлов не доказывает полноту зависимостей и не подтверждает работу WowB.exe.

## Разбор отчёта пользователя и проверка по FileDataID, 30 октября

В первом отчёте сервер вернул `No maps found!` для Map 530; проверка серверной
геометрии не вывела подходящих файлов. CASC-хранилище открылось, но **все запросы
по имени, включая контрольный Azeroth.wdt, вернули OPEN_FAILED/2**. Поскольку
Восточные королевства у пользователя работают, эта проба не устанавливает
отсутствие файлов Запределья: поиск по именам не дал положительного контроля.
`runtime.stderr.log` содержит обычный INFO о SOAP HTTP 200, не ошибку запуска.

| 782779 | Контроль: Kalimdor.wdt, также подтверждён присланным Forever Map.db2 |

Ревизия содержимого справочника закреплена SHA-256 в
`content/donors/ascension-style/outland-fileid-probe.json`. Наличие ID в общем
справочнике не означает наличия соответствующего ресурса в клиенте Forever.
Обновлённый `check-client-paths.cpp` выполняет запросы по этим ID независимо
от результата поиска по имени, полностью читает доступные файлы и считает SHA-256.

У пользователя рабочая ветка `feat/forever-ascension` и изменённый Dockerfile.
Для обновления только диагностики, без переключения ветки и изменения Dockerfile:

```bash
cd ~/WoWForEver
git fetch origin main
git restore --source=FETCH_HEAD --worktree -- \
  scripts/outland-readiness.py \
  tools/terrain-335/check-client-paths.cpp
python3 scripts/outland-readiness.py /mnt/e \
  --output "/mnt/e/WoWForEver-work/reports/Outland-fileids-$(date +%Y%m%d-%H%M%S)"
```

Пришлите новый `report.json`. Если отсутствует контроль и по ID, сначала нужно
разобрать чтение хранилища; если контроль читается, а ID Запределья не открываются,
появится отдельное свидетельство недоступности этих конкретных записей в выбранном
ROOT/локали. READ_FAILED означает другую проблему, чем OPEN_FAILED: запись может
находиться, но её данные не удаётся прочитать. Проверка не доказывает замыкание
зависимостей, правильность всей карты или её загрузку игровым движком.
