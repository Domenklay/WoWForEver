# Инкрементальное обновление копии CASC

Реализован updater **существующего синтетического хранилища**. Он читает
манифесты и индексы исходной лаборатории, создаёт новую копию и добавляет
пакет ресурсов. Новый кандидат больше не генерируется с нуля.
Рабочий клиент Forever этим updater пока не поддерживается.

## Что проверено

- ROOT v2: старые группы сохраняются байт в байт, включая name hashes,
  варианты локали и отдельные ContentFlags. Новая группа добавляется в конец,
  счётчик обновляется; занятый FileDataID отклоняется.
- ENCODING v1: проверяются MD5 всех страниц, их первые ключи и порядок записей.
  Старые записи CKey/EKey и варианты кодирования сохраняются; новые записи
  сливаются в отсортированном порядке с перестроением нескольких страниц.
  Учтён EOF-маркер EKey-таблицы. Self-ESpec описывает новый однокадровый N-BLTE.
- TVFS v1 flags=7: сохраняются прежние пути и поля span, меняется ссылка .root,
  добавляются ссылки на новые ресурсы. Перестраиваются ширины полей CFT/VFS
  при переходе через границу размера таблицы.
- Локальные IDX v7: читаются guarded и paged записи, проверяются native
  двухзначные Jenkins checksum и вариант Blizzget. Новые поколения записываются
  отдельно; прежние IDX и сегменты данных копируются без изменения.
- Уже присутствующее кодирование переиспользуется только после сверки полного
  EKey, MD5 кадров, CKey и самих байтов. Совпадения девятибайтового префикса мало.
- DOWNLOAD пока поддержан только tagless/checksumless v1 лаборатории.
  Новые записи добавляются без удаления старых; build config и .build.info
  переключаются на новые согласованные ключи.

Пакет привязан к точному base_build_key и содержит SHA-256 каждого исходного
файла. Предел лабораторного пакета: 100 файлов, 64 МиБ на файл, 128 МиБ суммарно.
Метаданные читаются с проверкой BLTE N/Z, EKey, кадров и CKey; зашифрованные
кадры не подменяются нулями. Для чтения одного манифеста предел 256 МиБ.

Исходная папка не записывается. Кандидат готовится во временной папке рядом
с назначением и появляется под конечным именем после завершения. С --checker
до этого проверяются все известные ресурсы настоящим CascLib. При сбое временная
папка удаляется. Существующий каталог назначения и каталог внутри исходника
не принимаются. Для следующего обновления нужен base_build_key предыдущей копии.

### Результаты

В исходную лабораторию с одним файлом добавлены **70 FileDataID**:
CascLib прочитал все 71 ресурса с ожидаемыми SHA-256. Затем в эту же полученную
копию добавлен ещё один FileDataID с переиспользованием уже имеющегося тела:
прочитаны все **72 ресурса**. ROOT вырос до трёх групп, CKey-таблица — до четырёх
страниц. Новые сегменты — data.001 и data.002; старые data.000/data.001
сохранились байт в байт. Хеши исходной папки и первой копии не изменились.

Финальная копия дополнительно прочитана в Docker: network=none, read-only root
и mount, UID/GID 1000, cap-drop ALL, no-new-privileges. Все 72 SHA-256 совпали;
хеши файлов после чтения не изменились. Это проверка CascLib, не WowB.exe.
Сводка: [incremental-storage-review.json](../../content/donors/legion-735/incremental-storage-review.json).

Все 43 теста прошли с реальными native checker/probe. Проверяются также
конфликты ID/ключей, испорченные страницы/кадры, неверный базовый build key,
выход путей за пакет, неуспешная native-проверка и сохранность исходника.

## Разработчику: формат пакета

```json
{
  "format": "wowforever-casc-resource-package-v1",
  "base_build_key": "точный MD5 build config исходной лаборатории",
  "resources": [
    {
      "file_data_id": 16777201,
      "path": "new.txt",
      "sha256": "SHA-256 содержимого new.txt"
    }
  ]
}
```

Пути считаются относительно JSON-пакета. Исходную лабораторию создаёт
build-casc-sandbox.py; конкретный build key находится в baseline/lab.json.
После подготовки собственного текста и пакета:

```bash
python3 scripts/update-casc-sandbox.py \
  --source /path/to/experiments/baseline \
  --package /path/to/package/package.json \
  --output /path/to/experiments/updated \
  --checker /path/to/check-storage
```

Реальный клиент не имеет обязательного synthetic lab marker и этим инструментом
не принимается. Подменять marker в клиенте не следует: профиль его DOWNLOAD,
фильтры групп ROOT, потоковая доставка и WowB.exe ещё не проверены.

## Следующий шаг на клиенте 70532: только чтение

Для проверки профиля нужны все страницы настоящего ENCODING и группы ROOT,
а не только их заголовки. Добавлен audit-casc-client.py: он читает нужные
локальные записи через IDX, проверяет полные BLTE/CKey, все страницы ENCODING,
группы ROOT и верхний TVFS. Для DOWNLOAD проверяются заголовок, границы таблицы
записей, имена/типы всех тегов и полные битовые карты их принадлежности.
Назначение тегов новым ресурсам ещё не определено, поэтому профиль с тегами
остаётся неподдержанным для updater. Дочерние TVFS-манифесты не обходятся.

Перед запуском закройте игру и лаунчер, чтобы манифесты не менялись в процессе.
Серверные контейнеры останавливать не нужно.

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/audit-casc-client.py /mnt/e \
  --output /mnt/e/WoWForEver-work/reports/Forever-CASC-full-audit.json
```

Нужен только получившийся JSON, исходные манифесты передавать не надо.
Скрипт ничего не скачивает, не получает ключи и не пишет в Data/.build.info.
Он читает сотни мегабайт локальных метаданных; это может занять время.
При неизвестном формате останавливается и сохраняет причину в JSON.
Успешный audit не означает готовность клиентского патча: installation_supported
остаётся false до проверки настоящего профиля и запуска WowB.exe.

## Полученный аудит клиента 70532

Пользовательский `Forever-CASC-full-audit.json` проверен 27 октября 2026 года.
Все страницы ENCODING и 916 групп ROOT прошли предусмотренные проверки;
16 локальных IDX содержат 1 036 707 уникальных префиксов. TVFS ссылается
на ожидаемый ROOT. Три исследуемых Legion FileDataID (957774, 956360, 956397)
не найдены ни в одном из проверенных профилей ROOT.

Реальный DOWNLOAD v1 содержит **30 тегов**. Лабораторный updater пока работает
только с профилем без тегов, поэтому применять его к игровому клиенту ещё нельзя.
Добавлен разбор тегов; следующий шаг — проверить настоящий профиль и определить
правила назначения тегов, затем реализовать их сохранение с тестами на
изолированной копии. Компактный результат прежнего аудита без игровых ресурсов сохранён в
`content/donors/legion-735/real-manifest-audit-review.json`.
Мультиклассовый аддон устанавливается отдельно и не требует изменения CASC.

## Даларан: уточнить теги DOWNLOAD

После успешного полного аудита его не обязательно повторять: отдельный режим
читает только DOWNLOAD через локальные IDX, проверяет BLTE/CKey и разбирает
все теги. Клиент и лаунчер должны быть закрыты; сервер продолжает работать.

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/audit-casc-client.py /mnt/e --download-only \
  --output /mnt/e/WoWForEver-work/reports/Forever-DOWNLOAD-tags.json
```

Пришлите получившийся JSON. Он содержит названия, числовые типы, количество
записей и хеш битовой карты каждого тега. Дополнительно выводится принадлежность
ENCODING и верхнего TVFS к тегам, если их EKey найдены в DOWNLOAD. Это
метаданные; сами игровые файлы и битовые карты в отчёт не включаются.

Режим `--download-only` не перепроверяет все страницы ENCODING и группы ROOT;
это явно указано в `audit_scope`. Даже при `tags_parsed=true` остаются
`installation_supported=false` и `tag_assignment_policy_verified=false`.
Типы и имена тегов не превращаются автоматически в правила назначения.

Исходная выгрузка Даларана остаётся в
`E:\WoWForEver-work\exports\Legion-Dalaran-raw-v2`. После уточнения профиля
готовится отдельная экспериментальная копия клиента и пакет одного тайла.
Установка в рабочий клиент будет отдельным этапом после испытаний.

Парсер сверялся с `CaptureDownloadHeader`, `CaptureDownloadTag` и порядком
битов из закреплённого CascLib. Тесты включают 30 тегов, MSB-first битовые карты,
неиспользуемые биты последнего байта, v1/v2/v3, обрезанные данные и проверку
неизменности исходного хранилища. Синтетическое хранилище с 30 тегами также
открыто настоящим CascLib через `check-storage`; это не тест WowB.exe.

## Полученные теги и подготовка копии клиента

Проверен `Forever-DOWNLOAD-tags.json` для того же build key
`ad1802f4455e427ed8b7769aab25b0c0`. MD5 DOWNLOAD совпал с полным аудитом.
Все 30 тегов разобраны: платформы (тип 1), архитектуры (2), локали (3),
регионы (4), speech/text (5), Alternate/HighRes/Talebound (16384).
Сводка — `content/donors/legion-735/download-tags-review.json`.

У каждой битовой карты **пять неиспользуемых младших битов равны 1**:
2 208 563 записи не заполняют последний байт. Простое добавление записей
переиспользовало бы эти биты и ошибочно присвоило теги, в том числе пустой
Talebound. Добавлен `append_download`: преобразование байтов DOWNLOAD v1,
которое сохраняет принадлежность прежних записей, очищает неиспользуемые биты
и требует явный список тегов для каждой новой записи. Этот список не выбирается
по имени тега автоматически. Пустой список тоже должен быть задан явно.

В отчёте ENCODING и верхний TVFS не найдены в таблице DOWNLOAD. Это не считается
повреждением и не даёт образца тегов для новых метаданных. Отчёт сам по себе
не определяет правила тегов для ресурсов Даларана. Чистое преобразование
используется отдельным [контрольным импортом в подготовленную копию](CASC-CANARY.ru.md).
Установщик игровых ресурсов Даларана пока не готов.

Следующий локальный шаг — **независимая копия** для экспериментов. Закройте игру
и лаунчер. Серверные контейнеры продолжают работать.

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/prepare-legion-client.py /mnt/e \
  --output /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1
```

Скрипт проверяет активный Classic Beta build key, наличие WowB.exe и свободное
место. Из корня диска берутся только `.build.info`, `Data` и `_classic_beta_`.
Остальной диск, каталог экспериментов и донорская выгрузка не копируются.
В `_classic_beta_` исключены Cache, Logs, Errors, Screenshots, GPUCache,
ShaderCache и файлы `.tmp`/`.temp`/`.log`/`.dmp`. Эти временные данные игра
создаёт заново. Исключения не распространяются на `Data`: её файлы проверяются
строго, ошибка чтения не замалчивается.
Исходные файлы открываются для чтения; каждый новый файл после записи
перечитывается и сверяется по SHA-256. Жёсткие ссылки не создаются,
символические ссылки не принимаются. Изменение исходного клиента во время
копирования прерывает операцию. Готовая папка появляется только после проверок;
существующая папка назначения не перезаписывается.

При прерывании сохраняется папка `Forever-Legion-client-v1.partial` рядом
с будущей копией. Повторите **ту же команду**: скрипт сверит build key,
состояние исходных файлов и SHA-256 уже завершённых копий, затем докопирует
остальное. Повреждённые или изменившиеся файлы копируются повторно; место
рассчитывается под оставшиеся данные. Контрольная точка атомарно обновляется
после проверки каждого файла. Незавершённый отдельный файл копируется заново.
Блокировка в Linux `/tmp` предотвращает одновременные запуски для одного пути.

В первой версии копировался и Cache, а временная папка удалялась при любой
ошибке. Пользовательская попытка остановилась на исчезнувшем файле
`Cache/ADB/ruRU/CollectableSourceEncounterSparse32288.tmp` после примерно 48 GiB.
Та версия не оставляла контрольных точек, поэтому первый запуск исправленной
версии потребует полного копирования. Дальнейшие прерывания сохраняют прогресс.

Скопированному объёму требуется место плюс 256 MiB запаса. Скрипт показывает
размер до копирования и ход операции. Дождитесь `COPY VERIFIED` и передайте
последние строки вывода. `legion-client-copy.json` с хешами остаётся внутри
копии. Её `.build.info` и CASC пока идентичны исходным: карта, клиентские DB2,
серверная геометрия и настройки лаунчера на этом шаге не меняются.
Копирование не докачивает отсутствующие ресурсы потоковой установки.

Преобразование битов дополнительно проверено настоящим CascLib через
`check-download-tags.cpp`: `CascGetFileInfo(CascFileFullInfo)` вернул ровно
заданные тестом маски, включая нулевую, без унаследованных единиц из padding.
Это проверка синтетических ресурсов, не подтверждение правил тегов для Legion.
Для повторения разработчиком с уже собранным CascLib:

```bash
g++ -std=c++20 -O2 -I/path/to/CascLib/src \
  tools/legion-casc-probe/check-download-tags.cpp /path/to/libcasc.a \
  -lz -lcrypto -o /path/to/check-download-tags
CASC_DOWNLOAD_TAG_CHECKER=/path/to/check-download-tags \
  python3 -m unittest discover -s tests -p test_casc_download.py -v
```
