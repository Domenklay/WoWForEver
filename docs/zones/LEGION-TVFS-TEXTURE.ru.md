# Проверка вложенной записи TVFS на одной текстуре

После исправления ROOT пользователь проверил текстуры в игровом UI:
исходный ID 123086 отображается, приватный ID 15728640 даёт зелёную область.
Таким образом, проверка чтения через CascLib ещё не подтверждает доступ
игрового движка к новым ID.

Штатный `vfs-root` содержит имена виртуальных каталогов из 16 символов,
которые ссылаются на дочерние манифесты. Внутри них находятся имена из
FileDataID и CKey. Предыдущий установщик добавлял полные имена с двоеточием
непосредственно на верхний уровень. Кроме того, перенос флагов legacy ROOT
в имена TVFS не был подтверждён по штатному расположению файлов.

Стандартная сборка CascLib при открытии этого каталога возвращается к legacy
ROOT (`ROOT (reparsed)`): её успешное чтение не проверяло прохождение по этим
вложенным каталогам. Теперь проверяем именно размещение в штатных дочерних
манифестах, без вывода новых правил из чисел флагов.

## Установить одну пробную запись

На компьютере должен быть установлен проверенный слой исправления типов.
Верните Кая домой через `python3 scripts/activate-legion-map.py home KAY`,
затем закройте игру и лаунчер.

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/repair-legion-tvfs-entry.py apply \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1
```

Скрипт читает штатные RU-каталоги TVFS и ищет записи исходной текстуры 123086.
Все найденные варианты добавляются с новым ID 15728640 в те же дочерние
манифесты. Новый путь ссылается на ту же строку VFS, что и исходный путь.
Таблицы VFS/CFT/EST и их расположение в файле сохраняются побайтно; новая
таблица путей дописывается в конец файла. Исходные записи сохраняются; новые типы файлов
не угадываются. Прежняя плоская запись удаляется только для этого приватного ID.

Манифесты, служебный ENCODING и конфигурация получают новый слой с резервной
копией. Старые записи `vfs-N` сохраняются; для изменённых дочерних манифестов
добавляются новые. ROOT, модели, текстуры и сервер не меняются. При ошибке
проверки восстанавливается предыдущий слой клиента и указатель его журнала.

Дождитесь `NATIVE TVFS ENTRY CANARY INSTALLED`. Служебный `result.json`
остаётся рядом с резервной копией; ZIP с его копией и журналами автоматически
сохраняется в `E:\WoWForEver-work\reports`. Для копии вне папки `experiments`
можно явно задать `--report-dir`. Автоматический архив помечен как собранный
до игрового теста: он подтверждает установку метаданных, не отрисовку.

## Повторить сравнение

Запустите тестовую копию, войдите в обычный мир и выполните в игровом чате:

```lua
/run LRT=CreateFrame("Frame",nil,UIParent);LRT:SetSize(440,220);LRT:SetPoint("CENTER");for i,id in ipairs({123086,15728640}) do local t=LRT:CreateTexture();t:SetSize(200,200);t:SetPoint("LEFT",(i-1)*220,0);t:SetTexture(id) end
```

Слева исходная текстура, справа — приватный ID. Пришлите скриншот и свежий ZIP.
После проверки соберите его одной командой:

```bash
python3 scripts/collect-legion-report.py \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1
```

Повторная установка для этого не требуется. Архив появится в
`E:\WoWForEver-work\reports\Dalaran-TVFS-texture-ДАТА-ВРЕМЯ-идентификатор.zip`.
В нём находятся `result.json`, журнал активной операции, выбранные свежие
клиентские логи и сводка. Сводка показывает, активна ли пробная запись TVFS,
совпадает ли конфигурация с журналом, последний номер архива из Tact.log и,
если PowerShell доступен, пути запущенных WowB.exe. Командные строки процессов
не собираются. Большие логи ограничены последними 8 МиБ с отметкой в сводке.
Игровые архивы, исполняемые файлы и настройки аккаунта в ZIP не включаются.

До результата этой проверки не повторяйте телепортацию: этот скрипт намеренно
исправляет только один ID. Остальные 2911 записей ещё требуют переноса в
правильные дочерние каталоги.

Закрыть панель:

```lua
/run if LRT then LRT:Hide() end
```

## Откатить только эту проверку

Закройте игру и лаунчер:

```bash
python3 scripts/repair-legion-tvfs-entry.py rollback \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1
```

Исправление типов ROOT и ранее установленные ресурсы сохраняются.

В облаке проверены чтение и пересборка вложенных каталогов на собственных
данных, сохранение исходных записей, чтение CASC после установки и точный
откат, включая искусственную ошибку проверки. Отрисовка игровым движком
остаётся проверкой пользователя.

Первый запуск остановился на `Patched CFT records are not supported` ещё до
записи нового слоя. Это ограничение декодера CFT, а не подтверждение повреждения
клиента. Путь с новым ID теперь добавляется без разбора патч-записей. Обычный
декодер по-прежнему явно отклоняет неизвестные патч-записи, если вызывается
для анализа содержимого CFT.

Для повторного запуска с сохранением текста установки:

```bash
cd ~/WoWForEver
git pull --ff-only
mkdir -p /mnt/e/WoWForEver-work/reports
set -o pipefail
python3 scripts/repair-legion-tvfs-entry.py apply \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1 \
  2>&1 | tee /mnt/e/WoWForEver-work/reports/Dalaran-TVFS-install.log
```

## Возобновление Даларана, 30 октября 2026

Работа с Далараном возобновлена по запросу пользователя. Перенос Запределья
отложен; это не изменение аддона из соседнего чата.

Последний сохранённый архив `Dalaran-TVFS-texture-20261028-130501-nj2pxuvu.zip`
относится к операции `c1b5a4c38e7d4558ba439dc98eec31bb`. Он подтверждает установку
и совпадение `.build.info` в момент сбора, но помечен
`immediately_after_install_before_game_test`. В нём логи заканчиваются раньше
установки, запущенных процессов нет, а Tact.log перечисляет архивы до 51 при
добавленном `data.052`. Эти данные **не устанавливают**, читала ли игра новый
слой после установки. Пользовательская зелёная текстура остаётся отрицательным
игровым результатом, причину которого ещё предстоит установить.

Сборщик теперь отдельно показывает:

- совпадает ли текущая `.build.info` с активной операцией;
- соответствует ли путь работающего WowB.exe тестовой копии и есть ли другая копия;
- старше ли Client.log/Tact.log текущей `.build.info`;
- неизвестность результата, если Windows не разрешил прочитать путь процесса.

Наличие свежих логов и правильного процесса само по себе не подтверждает
отрисовку приватной текстуры. Сборщик не записывает игровые файлы, не меняет
настройки лаунчера, не устанавливает новый слой CASC и не запускает телепорт.

```bash

  scripts/collect-legion-report.py scripts/legion_reports.py
```

В лаунчере выбрать **тестовую** папку:
`E:\WoWForEver-work\experiments\Forever-Legion-client-v1\_classic_beta_`.
Войти в обычный мир; пока не телепортироваться в Даларан и не переустанавливать
TVFS-canary. Оставив игру открытой, собрать текущее состояние:

```bash
python3 scripts/collect-legion-report.py \
  /mnt/e/WoWForEver-work/experiments/Forever-Legion-client-v1
```

Пришлите ZIP, указанный в строке `Report ZIP:`. Он сохраняется в
`E:\WoWForEver-work\reports`. Если клиент не запускается или сборщик сообщает
об отсутствии журнала, пришлите текст ошибки: не требуется восстановление
изначального состояния клиента ради выполнения этой команды.
