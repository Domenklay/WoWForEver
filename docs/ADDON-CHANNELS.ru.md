# Multi 1.9.0: утверждённые и тестовые аддоны, управление обновлениями

Единый рабочий список: **`addons/channels.json` в ветке `main`**.
Лаунчер читает `https://raw.githubusercontent.com/Domenklay/WoWForEver/main/addons/channels.json`
при запуске игры с включёнными обновлениями аддонов. Правки Lua публикуются
в исходном коммите; список ссылается на его полный SHA, каждый файл имеет размер
и SHA-256. Пересборка лаунчера для выпуска нового совместимого набора не нужна.

## Пользователь

В **Настройки → Обновления игры**:

- «Разрешить загрузку и исправление WoW» управляет операциями Multi с файлами
  игры: загрузкой, исправлением, восстановлением и пакетами ресурсов. При
  выключении остаются проверка без изменений и запуск. Battle.net управляет
  собственными обновлениями отдельно; Multi его настройки не меняет.

В Multi 1.9 откройте отдельную вкладку **Игровые аддоны** в левой панели
(в Multi 1.8 эти параметры были в настройках):

- «Обновлять аддоны перед запуском» включает установку выбранного комплекта.
  Выключение полностью пропускает проверку/скачивание/установку аддонов, включая
  отсутствующие папки. Незавершённая установка блокирует запуск до восстановления.
- Набор «Утверждённые» (`stable`) или «Тестовые» (`testing`) применяется на следующем
  запуске. Обе папки проверяются как один комплект. Для возврата выберите
  «Утверждённые» и запустите игру.
- «Разработка аддонов» сохраняет существующие локальные папки даже с неполным
  кодом; отсутствующие устанавливаются из выбранного сохранённого списка.
  Для тестирования полного опубликованного комплекта выключите разработку.
- «Обновить список версий» только читает метаданные и обновляет список в настройках.
  Она не устанавливает аддоны. На главной странице видны выбранный режим и пауза.

Сначала скачиваются и проверяются ВСЕ изменённые аддоны, затем выполняется замена.
Ошибка скачивания не меняет ни одной рабочей папки. Ошибка замены возвращает
прежний комплект. Прерванный процесс восстанавливается по журналу на следующем
запуске; другая копия лаунчера не может одновременно менять эти папки.

Резервные копии: `<gameDir>/.forever-multi/addon-backups/<id>/<имя>`.
Код нового набора, сохранённый при откате незавершённой установки:
`<gameDir>/.forever-multi/addon-failed/<id>/<имя>`.
Другие аддоны, SavedVariables и CASC не входят в замену аддонов.
Ссылки/junction по пути установки не поддерживаются.

Если GitHub недоступен, применяется последний проверенный список из
`%APPDATA%/forever-launcher-app/addon-cache/channels.json`, а при его отсутствии —
список из сборки. В журнале указаны источник списка, канал и release.
Повреждённый/несовместимый список блокирует обновление; тестовый канал не
подменяется утверждённым. Кешированный набор не обязательно самый новый.

## Разработчик: выпустить тестовый комплект

Рабочие исходники: `codex/native-cdn-70658-20261106` (см. CURRENT-SERVER.ru.md).
Не менять `main` целиком на рабочую ветку: там также сохранён старый код сервера.
В `main` публикуются центральный список и документация; изменения аддона могут
находиться в любом доступном коммите ЭТОГО репозитория.

1. Измените аддон в `mods/forever-advancement/addon/ForeverAscension` или
   `mods/living-encyclopedia/addon/ForeverEncyclopedia`. Обновите `## Version:`
   в его TOC. Проверьте совместимость с действующим сервером и протоколом.
2. Закоммитьте и отправьте исходники в Git. Сохраните полный SHA исходного коммита.
3. Подготовьте список из Git-объекта, а не из незакоммиченных рабочих файлов:

   ```bash
   python3 scripts/update-addon-channel.py pin \
     --channel testing --addon ForeverEncyclopedia \
     --commit ПОЛНЫЙ_SHA_КОММИТА --version ВЕРСИЯ_ИЗ_TOC \
     --release testing-70658-НОМЕР
   python3 scripts/update-addon-channel.py check
   ```

   Для второго аддона повторите `pin`, сохранив один согласованный release.
   Неизменённый аддон остаётся закреплённым на прежней версии. Оба всегда входят
   в полный комплект. Для Git-объекта сначала выполните fetch, если его нет локально.
4. Проверьте diff `addons/channels.json`: канал, обе версии, commit, полный список
   файлов, размеры и хеши. Утилита требует совпадения версии с TOC. При наличии
   всех исходных Git-объектов доступна полная проверка:

   ```bash
   python3 scripts/update-addon-channel.py check --verify-git
   ```

5. Опубликуйте **этот файл** в `main/addons/channels.json` и синхронизируйте его в
   рабочей ветке. Коммит исходников должен быть доступен раньше списка. До
   публикации можно подготовить несколько изменений; пользователи увидят только
   целый опубликованный JSON. Проверьте raw URL после публикации. Workflow
   **AddOn release catalogue** проверяет именно этот JSON и все файлы из точных
   исходных коммитов. Изменение только списка запускает проверку метаданных,
   а не сборку нового Windows-лаунчера.
6. В Multi включите обновления аддонов, выключите разработку, выберите тестовый
   комплект, сохраните и запустите игру. Проверьте `/fa` и `/ency`, повторный
   вход, покупки/открытия, ошибки Lua и сохранность прогресса.

## Утвердить проверенный комплект

```bash
python3 scripts/update-addon-channel.py promote --release stable-70658-НОМЕР
python3 scripts/update-addon-channel.py check
```

`promote` копирует ВЕСЬ `testing` в `stable`, не отдельный аддон. Опубликуйте
центральный JSON в `main` и рабочей ветке. Для отката верните прежний корректный
JSON обычным Git-коммитом; старые исходные коммиты не удалять.

Проверка Python: `python3 -m unittest discover -s tests -p test_addon_channels.py -v`.
UI: `node tests/fixtures/launcher-content-ui.js .`. Rust: `cargo test --locked --lib`
в `app/src-tauri`. Действующий сервер и клиент не используются как тестовые фикстуры.

## Автоматический вход в игру

В «Настройки → Игра» включено «Входить в игру под аккаунтом лаунчера».
Multi 1.8.0 включает это и для `Wow.exe` 70658: после подготовки аддонов обменивает
сохранённую серверную сессию на свежий login ticket, проверяет аккаунт ответа,
передаёт билет клиенту и запускает с `-launcherlogin`. На Windows билет хранится
в Launch Options/WoW как DPAPI-защищённый WEB_TOKEN. Выбирается legacy-ветка
Blizzard Entertainment или новая Custom Game Server Dev по строкам выбранного
EXE. Билет передаётся без пароля и без токена в
командной строке. Выбирается первый игровой аккаунт авторизованного пользователя.
Пустой список аккаунтов не заменяется выдуманным WoW1: запуск остановится с причиной.

Если сессия истекла, нужно снова войти в лаунчер. Игровой пароль не сохраняется
в WTF. Чекбокс можно выключить для ручного входа. Вход в аккаунт не означает
автоматический выбор персонажа. Реальный вход на ПК пользователя требует
отдельного подтверждения после установки новой сборки.

## Установленные версии и журнал в Multi 1.9

Во вкладке «Игровые аддоны» кнопка «Прочитать установленные версии» читает папки
`Interface/AddOns` выбранной игры и версии TOC, включая сторонние аддоны. Для наших
аддонов контрольные суммы сравниваются с квитанцией **установленного**, а не только
выбранного будущего набора. Отличаются статусы: совпадает, изменён/неполный, сторонний/
без квитанции. Одно совпадение номера версии не подтверждает содержимое файлов.
Чтение списка не устанавливает и не восстанавливает файлы.

Переключатель набора, обновления и режим разработки находятся на этой же вкладке.
Нажмите «Сохранить»: изменения применятся перед следующим запуском игры. Для
установки всего testing включите обновления и выключите режим разработки.

«Журнал» открывает отдельную страницу с прокруткой и явным пустым состоянием.
События текущего процесса сохраняются при переходах между страницами; сообщения
не записываются в публичный каталог аддонов.

[Catalogue CI текущего комплекта 0.9.15](https://github.com/Domenklay/WoWForEver/actions/runs/42376895223) проверяет опубликованные источники и контрольные суммы. [Lua и Legacy CI](https://github.com/Domenklay/WoWForEver/actions/runs/42376750280) прошёл синтаксис, два варианта штатного окна, верхнее перекрытие, FDF-запросы и сохранность четвертой страницы «Классических». Реальную картинку в клиенте и работу серверной телепортации предстоит проверить отдельно.
