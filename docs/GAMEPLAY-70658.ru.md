# Наши игровые модули на текущем сервере 70658

Состав: Forever Ascension 1.11.0 / протокол 3, Forever Encyclopedia
0.9.8-v2.1-smartai-abilities и Forever Scaling 0.2.0. Ядро остаётся
`b4e7b940593f6402a822d4fbcdf31331d16f73b6`, EXE — 70658.

Энциклопедия взята из `feature/living-encyclopedia-v0` на ревизии
`ed0ce9b9bed2ecd6ff13c36b49700b66ad979b52`, масштабирование — из
`feature/forever-scaling`, `8661b88f65126e17f9208628a06b01b1ae76eeba`.
Здесь они подключаются вместе с актуальным мультиклассом. Старые
`install-dev.sh`, `forever-scaling-mod.sh` и корневой Docker Compose
не управляют текущим `~/WoWForEver-clean` и для этой установки не используются.

## Сервер

Из актуального checkout этой ветки в Ubuntu/WSL:

```bash
python3 scripts/enable-clean-gameplay.py install --jobs 2
```

Поддерживается как готовый чистый сервер, так и этот же сервер с уже включённым
Ascension. Сначала собираются и линкуются новые бинарники на том же ядре;
работающий сервер в это время доступен. Только после успешной сборки
останавливаются worldserver, bnetserver и web. MySQL остаётся запущенным.
Сохраняются приватный сжатый снимок четырёх баз, предыдущие Compose/state,
controller и собственные spell-привязки. Резервная копия находится в
`~/WoWForEver-clean/advancement/<id>/`; её путь выводится установщиком.

Схема добавляет собственные таблицы мультикласса и пять таблиц энциклопедии.
Прогресс, аккаунты, персонажи, предметы и данные других модулей сохраняются.
Меняется только образ worldserver и флаги модулей; сертификаты, bnet/web-образы,
порты, MySQL-том, ресурсы сервера и клиентские архивы сохраняются.
Автоматический импорт баз выключен. Готовность проверяется по живому TCP,
realm 70 / build 70658, меткам образа и сообщениям текущего процесса о модулях.

При ошибке установщик возвращает предыдущие образ, настройки и spell-привязки.
Новые таблицы и прогресс модулей при откате не удаляются. Команды:

```bash
python3 scripts/enable-clean-gameplay.py status
python3 scripts/enable-clean-gameplay.py rollback --backup "$HOME/WoWForEver-clean/advancement/<id>/install.json"
```

Сохраните checkout установщика: `server.sh` ссылается на его controller.
Снимки SQL, приватный Compose и `install.json` содержат секреты и остаются локально.

## Клиент и лаунчер

Multi 1.7.0 перед запуском автоматически проверяет и устанавливает два аддона:
`ForeverAscension` и `ForeverEncyclopedia`. Каждый набор закреплён на неизменной
ревизии GitHub, файлы сверяются по размеру и SHA-256. Энциклопедия занимает
89 070 байт и содержит TOC плюс все семь загружаемых Lua-файлов.
Исправные аддоны используются без сети. Заменяемая папка сохраняется отдельно
в `.forever-multi/addon-backups/<id>/<имя аддона>`; при ошибке замены возвращается.
SavedVariables, прочие аддоны, WTF и CASC при установке дополнений не изменяются.

Полностью распакуйте новый Multi, выберите уже работающий клиент 70658 и
нажмите «Играть». Повторная загрузка клиента для этих модулей не требуется.
Мультикласс: `/ascension` или `/fa`. Энциклопедия: `/ency`.
Scaling работает на сервере через штатные поля уровня/здоровья клиента;
отдельного аддона ему не нужно.

## Что означает автолевел в этом комплекте

Это существующий Forever Scaling: виртуальный уровень враждебного NPC для
каждого персонажа равен `max(исходный уровень NPC, уровень игрока − 9)`,
с текущим ограничением 70. Сам уровень персонажа модуль не повышает.
Два игрока могут видеть одного противника на разных уровнях, сохраняя общий
бой и процент здоровья. PvP и управляемые игроками существа исключены.
Проверка: персонажи 20 и 60 против исходного NPC уровня 6 должны видеть
уровни 11 и 51. Старшие противники не должны становиться слабее.

Если scaling пока не нужен, установите профиль без его включения:
`python3 scripts/enable-clean-gameplay.py install --jobs 2 --no-scaling`.
Изменение уже активного профиля выполняется через сохранённый откат.

## Проверка после установки

Дождитесь `GAMEPLAY ACTIVE`, затем проверьте вход в мир, открытие обоих аддонов,
покупку навыка мультикласса, открытие существа/зоны в энциклопедии, распределение
знаний, призыв спутника и сохранение прогресса после повторного входа.
Логику и внешность спутника нужно проверить на реальном 70658. В существующем
RuntimeV5 используется стандартный шаблон существа 1933 как диагностическая
модель; подходящий DisplayID летающей книги на этой сборке ещё не подтверждён.
Это не заявление о готовности всех косметических обликов или всего каталога
умений Ascension: прежние ограничения этих модулей сохраняются.
