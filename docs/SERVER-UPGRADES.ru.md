# Обновления клиента, ядра, ресурсов и базы

Механизм `scripts/upgrade-forever-server.py` обновляет существующий clean-сервер
без удаления аккаунтов и персонажей. Он не является загрузчиком/активатором
игры. Исходная установка, EXE, CASC и .build.info доступны только для чтения.

## Текущее состояние: предзагрузка ещё не активна

6 ноября пользователь уточнил, что скачивал через **ForeverLauncher.exe
2.0.5 (Nvord)**. Проверка самой `E:\WoW_Forever\_forever_\Wow.exe` показала
**1.60.1.70658**, активная .build.info также содержит **1.60.1.70658**.
Следовательно, подтверждённого установленного EXE 70707 пока нет. Проверка
старой v4 дополнительно сравнивала её с источником той же версии; найденные
различия архивов/индексов не подтверждают повреждение или активацию 70707.

Мигратор в этом состоянии откажет **до остановки сервера**. Подмена номера
в лаунчере, .build.info или auth.realmlist не выполняется. Установка/активация
нужна в исходном установщике; наличие предзагруженного build config не
подтверждает наличие всех ресурсов и нового EXE.

## Четыре независимо проверяемые версии

`releases/server-catalog.json` хранит проверенные описания релизов:

- точную сборку реального клиента и разрешённые CASC-продукты;
- неизменяемый commit ядра;
- отдельную свежую выгрузку ресурсов с EXE SHA-256 и build key;
- исходную/целевую версию базы и упорядоченный список SQL-миграций с SHA-256.

Начальный релиз 70707 использует прежнее чистое ядро b4e7b940593f, семейство
протокола 70658 и **не меняет схему базы**. Основание совместимости —
[открытый upstream PR 271](https://github.com/advocaite/TrinityCore/pull/271);
это ещё не проверка входа реальным клиентом. Его общий SQL не используется,
поскольку переводит миры на 70755. Регистрируется только 70707 в копии auth.

Неизвестная версия, неподдерживаемая исходная версия базы и изменённый хеш
миграции блокируются. Новые версии требуют нового описания релиза и проверки
протокола, схемы и ресурсов. Произвольный SQL или новая большая TDB из
интернета автоматически не применяются. Для будущих SQL-миграций уже есть
исполнитель на изолированной копии; переход на другую полную TDB требует
отдельного проверенного сценария, а не замены числа версии.

## Команды в Ubuntu/WSL

Получить инструменты, сохраняя этот checkout на время эксплуатации:

```bash
cd ~/WoWForEver
git fetch origin codex/forever-upgrades-70707-20261106
upgrade_tools=$(mktemp -d "$HOME/WoWForEver-upgrade-tools.XXXXXX")
git worktree add --detach "$upgrade_tools" FETCH_HEAD
python3 "$upgrade_tools/scripts/upgrade-forever-server.py" plan \
  --client '/mnt/e/WoW_Forever/_forever_' \
  --release forever-1.60.1.70707
```

Сейчас этот `plan` должен отклонить активный EXE 70658, не меняя сервер.
После успешной установки 70707 в исходном лаунчере план можно повторить.
Проверяется Windows FileVersion через WSL interop; декларация номера вместо
реального EXE не принимается. Версия EXE и активные метаданные должны совпасть.

Только после успешного планирования:

```bash
python3 "$upgrade_tools/scripts/upgrade-forever-server.py" prepare --jobs 2
python3 "$upgrade_tools/scripts/upgrade-forever-server.py" status
python3 "$upgrade_tools/scripts/upgrade-forever-server.py" apply
```

`prepare` извлекает данные в новый каталог, пока старый мир продолжает
работать. Нужны минимум 15 ГиБ свободного места; частичная выгрузка сохраняется
отдельно и не смешивается со свежей. Старый каталог data не изменяется.
Для извлечения закройте игру и остановите загрузки исходного установщика.

`apply` останавливает запись через worldserver/bnetserver/web и делает
проверенный gzip-дамп **auth, world, characters, hotfixes**. В новом Compose
проекте создаётся MySQL-копия на том же образе MySQL; исходный том не
переиспользуется. Перед переключением сравниваются схема и число
аккаунтов/персонажей, выполняются описанные миграции, проверяются сервер,
realm 70, порт мира и TLS. Обновления БД и AutoSetup при обычном запуске
этого поколения отключены: неожиданный автоимпорт не должен сбрасывать базу.
Нужен дополнительный диск для двух баз, дампа и старой/новой выгрузки.

После `ACTIVE RELEASE` можно выставить фактически установленную сборку
70707 в профиле Multi и выбрать новую установку. Полный тест включает
создание персонажа и вход в мир; автоматическая TCP/TLS-проверка этого
не заменяет. Текущую защиту клиентских файлов оставляйте включённой.

## Возврат и прерывания

При обычной ошибке apply прежние данные/базы восстанавливаются переключением
на старое окружение; старые тома вообще не удаляются. При обрыве процесса:

```bash
python3 "$upgrade_tools/scripts/upgrade-forever-server.py" rollback
```

После успешного перехода эта же команда сохраняет отдельный дамп прогресса
нового поколения и возвращает предыдущий сервер. Прогресс после перехода
остаётся в новом томе и `databases-after-*.sql.gz`; он автоматически не
сливается назад. Старые ресурсы и копии не очищаются автоматически.

Маркер незавершённого перехода блокирует start/restart до восстановления.
После ошибки с автоматическим возвратом создайте новый план: старый дамп
мог устареть после возобновления игры. Для выбора старого плана используйте
`--plan /полный/путь/к/plan.json`; без параметра используется последний план.

Обычное управление после завершения перехода сохраняется:
`~/WoWForEver-clean/server.sh status|start|stop|restart`.
Состояние, Compose и SQL-дампы содержат секреты/данные игроков, имеют закрытые
права и не должны публиковаться. В Git находятся только код и описания релизов.

## Проверки

Есть тесты отказа для EXE 70658 при предзагрузке 70707, несовпадающих
метаданных, чужого/устаревшего плана, копии БД с потерянными персонажами,
порядка снимка/переключения и возврата при сбое контрольной записи.
Отдельная CI-проверка использует реальные MySQL 8 с синтетическими четырьмя
базами: проверяет дамп, восстановление бинарных данных, сохранение схемы и
числа аккаунтов/персонажей, SQL-миграцию только копии и второй дамп прогресса.
Она не запускает TrinityCore или игру и не является развёртыванием на ПК.
