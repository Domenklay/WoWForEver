# Мультикласс Forever с изучением навыков в стиле Ascension Freepick

## Способности Freepick во вкладке «Кастомное»

Эта работа касается классового набора Freepick (модель `hero` в доноре),
а не отдельных классов Conquest of Azeroth (`coa`, Cultist и другие).
Имена файлов и каталог `src/server/coa/` сами по себе не определяют режим:
подтверждением служат соответствующие правила Freepick и SQL-привязки.

В аддоне `0.10.3-freepick-custom.1` и образе `0.4.2-freepick-custom.1`:

| Способность | Наше условие Freepick | Что подготовлено |
|---|---|---|
| 1463 — Щит маны | Два разных магических класса, уровень 10, 1 AE | Реализованы покупка, применение и расход общей маны; доступность проверяется по данным Forever при запуске |
| 982085 — Cold Seeking Missiles | Два магических класса, включая мага | Проверенный кандидат мистических чар Freepick; эффект ещё не перенесён |
| 278016 — Big Flaming Grimfire | Маг и чернокнижник | Проверенный кандидат мистических чар Freepick; эффект ещё не перенесён |
| 282083 — Lunar Synergy | Маг и друид | Проверенный кандидат мистических чар Freepick; эффект ещё не перенесён |

Магическими считаются **паладин, жрец, шаман, маг, чернокнижник и друид**.
Учитываются основной класс и классы купленных обычных способностей. Две
способности одного класса дают один класс; открытый каталог, изученный класс
без покупок и сами кастомные покупки классов не добавляют. Воин с Lesser Heal
и Frostbolt выполняет условие щита; паладину достаточно купленного Lesser Heal.
Условия и цена в таблице — правила нашего модуля, не извлечённые цены Ascension.

### Щит маны

Используется обычная цепочка Mana Shield 1463, фигурирующая в Freepick SQL донора,
а не выбранные по имени NPC-варианты или Щит Бездны Cultist. Наложение стоит
**7% общего максимума маны**; для персонажей с виртуальной маной это наш
адаптированный расход от общего запаса. Ёмкость, длительность, школа и множитель
маны за поглощение берутся из лучшего проверенного нативного ранга Forever для уровня персонажа. Перенос изменённого DBC
Ascension в DB2 Forever не выполняется, точное совпадение чисел с Ascension
не заявляется. Стоимость поглощения округляется вверх до целой маны.

Действует нативная обработка поглощения, журнал боя, GCD и ограничения применения.
Скрипт списывает нативную или виртуальную ману из того же запаса, что используют
остальные приобретённые заклинания; повторного нативного списания нет.
При нехватке маны поглощается только доступная часть урона, оставшийся урон
проходит. Ёмкость щита уменьшается; ресурсы не восстанавливаются от его отмены.
Обычные заклинания основного класса сохраняются: родной щит мага вне этого
механизма не получает ограничения двух классов и не заменяется кастомным.

Для покупки в «Кастомное» нужен левый клик. Выбранный щит применяется правым
кликом по карточке либо перетаскивается на панель как макрос `/fsubcast 1463`.
Такой макрос всегда проходит серверную проверку покупки и классов. Возврат
покупки удаляет принадлежащую модулю ауру; вернуть последний обычный навык
необходимого класса нельзя, пока не возвращена зависимая покупка.

Покупки восстанавливаются при входе сначала обычные, затем зависимые кастомные:
числовой порядок SQL не подходит, поскольку 1463 меньше 2050. Временно
недоступная реализация сохраняет владение для возврата, но не разрешает применение.
Активный кастомный щит не сохраняется в базу аур и не переносится Spellsteal:
для этого добавлен патч `0005-script-owned-runtime-auras.patch`. Патч
`0006-mana-shield-default-action.patch` разрешает отмену стандартного списания
маны в обработчике Mana Shield; это проверено на нативных методах AuraScript. Обычные ауры
сохраняют прежнее поведение. Сам щит после повторного входа нужно применить заново.

При запуске проверяются существование нативной ауры 1463, её эффекты и две
валидированные привязки скриптов. В логах появляется `Freepick custom Mana Shield:
available` либо `unavailable`. Во втором случае карточка остаётся недоступной;
один лишь совпадающий числовой ID не разрешает произвольное нативное заклинание.

- `Unit::CalcAbsorbResist`: исходный принцип поглощения за ману. Его нативный

Щит Бездны 502244 относится к Cultist и исключён из каталога. Варианты 2101610
и 2135451 не подтверждены как приобретаемые способности Freepick и также
исключены. Описания Power Surge 828574–828577 в архиве расходятся с контрактом
донорского SQL; его скрипт не переносился. Наличие исходника не доказывает
соответствие конкретной версии Freepick/Area 52.

Для остальных кандидатов пока нет исполняющего переноса в Forever. Их карточки
показывают «Требуется перенос», сервер отклоняет покупку и применение без
расходования AE/маны. Для точного переноса нужны согласованные определения
всех дочерних эффектов, условий, длительностей и значений из нужной версии
Freepick. Связанных DBC в приложенном архиве нет. Выводы записаны в
`content/donors/ascension-style/custom-spells-review.json`.

Пять изменённых файлов C++ скомпилированы на закреплённом Forever
`91d49b230f89c3ab4719f5b2b2d1e70ed36613c4`, адаптер и правила связаны через `ld -r`.
Проверки C++ и Lua покрывают поглощение, ресурсы, классы, порядок восстановления
покупок, карточки и макрос. Полные worldserver и bnetserver со стандартным набором статических скриптов
собраны и связаны; запуск обоих с `--version` прошёл. Повторная миграция и
восстановление привязок проверены на изолированной MySQL 8.0.46. Запуск
производственного Docker-образа с игровыми данными и игра клиентом 70532
ещё не проверены; на пользовательской машине установка не выполнялась.

Интеграция выполняется через `scripts/subclass-mod.sh install-freepick`, затем
`bash scripts/subclass-doctor.sh`. Установщик использует общий проверяющий модуль
`check-subclass-ready.py`: нужны готовность worldserver, правильный режим Freepick
и `Freepick custom Mana Shield: available` из текущего запуска контейнера.
При недоступном щите или переопределённом режиме установка откатывается.
Диагностика проверяет все таблицы Freepick и обе привязки щита. В этом режиме
экспериментальные строки native Rage/Energy мага должны отсутствовать; в прежнем
режиме подклассов сохранены исходные проверки этих строк.

Обновление выполняется обычной сборкой и установкой Freepick с резервной копией,
описанной ниже. Для проверки: купить щит при выполненных требованиях, получить
урон, проверить уменьшение щита и общего запаса маны; вернуть покупку; проверить
отмену ауры. После повторного входа покупка должна сохраниться, активная аура — нет.

Пользователь выбрал Freepick и уточнил модель: основной класс сохраняется,
дополнительные способности и таланты изучаются по выбору игрока. В общий объём
входят дополнительные системы, локации, квесты и достижения выбранного Ascension.
Это целевой объём проекта, а не утверждение о наличии всех исходников или
готовности полного переноса.

## Правила целевой системы

- Нативный класс персонажа остаётся постоянным: воин остаётся воином.
- Обычные уровни, классовые способности, таланты и прогресс основного класса
  сохраняются. Дополнительные покупки не должны удалять базовые навыки.
- Игрок собирает один набор чужих способностей из нескольких классов
  одновременно. Выбор класса в интерфейсе служит фильтром каталога.
- Свободное изучение способностей и талантов использует отдельные бюджеты
  (AE/TE как рабочая модель). Цены, уровни и ограничения задаются каталогом
  сервера; точные бюджеты требуют баланса под основной класс и лимит Forever.
- Нет обязательной случайной выдачи Wildcard. Возможные случайные режимы
  рассматриваются отдельно и не заменяют выбранный Freepick.
- Проверки владения, рангов, стоимости, ресурсов, дистанции, GCD и сохранения
  выполняются сервером. Аддон отображает состояние и отправляет запросы.
- Чужие заклинания с одинаковым ресурсом используют общий дополнительный
  запас этого ресурса, а не отдельную полную ману для каждого выбранного класса.

Первый проверяемый пример: **воин + лечение жреца + Frostbolt мага**,
доступные одновременно без переключения активного подкласса. Воин сохраняет
свои способности и ярость, оба дополнительных заклинания расходуют общий
серверный запас маны. Начальный тест использует определения и ресурсы,
которые уже присутствуют в клиенте Forever.

## Что необходимо изменить в текущем модуле

В `vendor/include/forever_subclass/SubclassSystem.hpp` состояние содержит
единственный `activeSubclass`. В `vendor/src/SubclassSystem.cpp` проверка
выбора сравнивает владельца заклинания с этим классом. Серверный адаптер
`server/ForeverSubclass.cpp` также привязывает доступность, масштабирование
и дополнительные ресурсы к одному активному подклассу.

Для целевой модели недостаточно добавить кнопки или расширить список навыков.
Нужны набор изученных способностей с владельцами из разных классов, отдельные
расходы AE/TE, требования изучения и расчёт ресурсов по всему активному билду.
Основной класс не должен изменяться ради обхода нативных ограничений заклинаний.

Существующие таблицы прогресса подклассов сохраняются. Перед включением нового
режима нужна явная миграция с резервной копией и откатом: старое «класс изучен»
не означает, что все его способности автоматически куплены в Freepick.
Текущая система отдельных уровней подклассов не считается согласованным
правилом Freepick; изменение её назначения требует отдельной реализации.

## Порядок переноса

1. **Основа мультикласса.** Набор способностей нескольких классов, учёт AE/TE,
   изучение и возврат, постоянный основной класс, сохранение после перезахода.
   Первый набор — две чужие способности на одном воине.
2. **Таланты и взаимодействия.** Каталог совместимых талантов, ранги и
   зависимости, пассивные эффекты, формы и питомцы по мере проверки нативных
   ограничений. Клиентские и серверные определения 3.3.5 сверяются с Forever.
3. **Дополнительные системы.** Сохранение билдов, усиления предметов и синергии,
   добыча, престиж/перерождение, испытания и варианты подземелий. Для каждой
   механики нужны определённые правила Freepick и проверенный источник.
4. **Контент в доступных локациях.** По одному комплекту NPC, противников,
   квестов и наград; затем достижение с действительным серверным условием
   выполнения. Проверяется получение, завершение, награда и повторный вход.
5. **Отсутствующие локации.** Клиентские ресурсы, геометрия сервера, размещения,
   фазы и сценарии переносятся как связанные пакеты после решения доступа
   игрового движка к новым ресурсам. Работа с ними поставлена на паузу.

Одинаковые числовые ID в двух проектах не доказывают одинаковые заклинания,
квесты, условия или достижения. Для нового контента нужны таблицы соответствий
и отдельный диапазон идентификаторов.

## Что требуется для полного контента Ascension

Клиент даёт часть моделей, карт, интерфейса и определений. Расстановки NPC,
логика квестов, условия достижений, таблицы добычи, события, сценарии и баланс
требуют серверных данных или самостоятельного восстановления по подтверждённым
материалам. Найденный открытый модуль не заменяет эти данные. Полный перенос
«всего Ascension» пока не подтверждён доступностью донора.

## Первый рабочий прототип: дополнительные способности

Режим включается отдельно через `ForeverSubclass.Freepick = 1`
(`SUBCLASS_FREEPICK=1` в Compose). По умолчанию остаётся прежний режим.
Установщик `install-freepick` сам включает флаг после резервного копирования.

В этой версии каталог намеренно ограничен **Lesser Heal жреца (цепочка 2050)**
и **Frostbolt мага (цепочка 116)**. Одновременно приобретённые навыки доступны
без переключения подкласса; лучшая доступная нативная ступень выбирается по
уровню основного персонажа. Школа слева — фильтр каталога. Выбранные навыки
другой школы остаются в выдаче сервера и на панели действий.

Начальный бюджет — **8 AE**, стоимость каждой цепочки — **1 AE**. Нажатие
на приобретённый навык возвращает это очко и запрещает последующее применение.
Покупка и возврат доступны с 10-го уровня, вне боя, в городе или таверне.
Весь обычный XP остаётся основному классу. Текущие нативные способности,
классовые таланты, броня и здоровье не заменяются. Если основной класс уже
жрец или маг, его собственная цепочка не продаётся как дополнительная.

Обе дополнительные цепочки используют один запас маны: нативную ману, если
у основного класса есть соответствующий слот, иначе общий серверный запас.
Для виртуальной маны база берётся из таблицы уровня жреца и интеллекта
персонажа. Мана не пополняется от смены каталога или возврата навыка;
остаток сохраняется между сеансами. Для чужих навыков в Freepick отсутствует
штраф за отдельный уровень подкласса. Дальность, время произнесения, GCD и
эффекты по-прежнему обрабатывает ядро через существующий адаптер.

**TE и покупка талантов пока не реализованы в Freepick.** Кнопка дополнительных
талантов отключена; прежние бонусы подклассов и питомцы не импортируются.
Это первый тест двух способностей, а не полный набор механик Ascension.
Исходники найденного донора в этот этап не копировались.

### Установка на работающий локальный сервер

Закройте игру. Выполните в WSL:

```bash
cd ~/WoWForEver
git pull --ff-only
bash scripts/subclass-mod.sh build
bash scripts/subclass-mod.sh install-freepick /mnt/e/_classic_beta_
bash scripts/subclass-doctor.sh
```

Установщик сохраняет образ работающего сервера, дамп баз, `.env` и аддон
в `backups/subclass-ДАТА-СУФФИКС`. Затем создаёт отдельные таблицы
`forever_character_freepick_state`, `forever_character_freepick_spells`,
`forever_character_freepick_resources`. Старые таблицы подклассов не переписываются,
автоматического переноса их покупок нет. Если готовность нового режима не
подтверждена, установщик восстанавливает образ, конфигурацию и аддон.
При переопределении флагов через `overrides/worldserver.conf` убедитесь, что
оно не отключает `ForeverSubclass.Enable` или `ForeverSubclass.Freepick`.

После успешной установки запустите обычный клиент через свой лаунчер.
Новые файлы CASC не нужны. Откройте `/fsub` у персонажа 10-го уровня или выше
в городе/таверне. Выберите жреца слева и нажмите **«Открыть каталог»**,
приобретите лечение; затем откройте каталог мага и приобретите Frostbolt.
Оба навыка должны оставаться выбранными. Перетащите их на панель действий.
Для воина: примените лечение к себе и Frostbolt к противнику; проверьте общий
расход маны, сохранение ярости, обычных навыков и получение опыта воином.
После перезахода проверьте сохранение обеих покупок; верните одну покупку и
убедитесь, что её кнопка больше не применяет навык, а AE освободилось.

Чтобы вернуться к прежнему режиму подклассов с сохранённым прогрессом:

```bash
bash scripts/subclass-mod.sh install /mnt/e/_classic_beta_
```

Это снова создаст резервную копию. Покупки Freepick останутся в своих таблицах.
Для отката образа и аддона используйте путь резервной копии, напечатанный
установщиком:

```bash
bash scripts/subclass-mod.sh rollback backups/subclass-ДАТА-СУФФИКС
```

Команда отката отключает модуль, сохраняя прогресс; она не восстанавливает все
игровые базы поверх новых действий персонажей. Полный дамп лежит в резервной
копии отдельно. Все эти команды запускаются на вашем компьютере; облачные
проверки не подтверждают фактическую установку или работу навыков в игре.

### Если `/fsub` не открывает окно

В аддоне `0.10.1-freepick.2` исправлена команда: пустой `/fsub` открывает
интерфейс и запрашивает состояние сервера. До исправления он только запрашивал
состояние. Экран талантов подгружается при необходимости; если он отсутствует,
открывается отдельное окно Forever. Серверная ошибка до создания окна также
выводится в чат без Lua-ошибки. Команды вроде `/fsub status` сохраняют своё назначение.

Закройте игру и обновите только аддон в папке **запускаемого** `WowB.exe`:

```bash
cd ~/WoWForEver
git pull --ff-only
python3 scripts/install-subclass-addon.py \
  --client /mnt/e/_classic_beta_ \
  --backup "backups/addon-freepick-ui-$(date +%Y%m%d-%H%M%S)"
```

Сборка образа и переустановка серверного режима для этого исправления не нужны.
Затем заново запустите клиент, войдите персонажем, выйдите из боя и введите
`/fsub`. Это собственное окно прототипа Forever; оригинальный интерфейс
Ascension пока не перенесён.
