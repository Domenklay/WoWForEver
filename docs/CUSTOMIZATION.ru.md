## Сначала совместимость клиента

Наш клиент: `1.60.1.70532`. Docker-комплект документирован для `1.60.1.70450`.
README ядра описывает 70338 и предварительную поддержку 70450.
Пользователь подтвердил вход в мир, бой и выполнение нескольких квестов на 70532.
Полная совместимость не подтверждена; в логах остаются ошибки отдельных пакетов.
`CLIENT_BUILD=70532` меняет записи build_info/realmlist, но не реализует новый
протокол, opcodes, структуры пакетов или форматы DB2.

Перед переносом контента нужно проверить вход, создание персонажа, вход в мир,
передвижение, NPC, бой, предметы и квесты на выбранной точной сборке.
Для запуска нужны данные из собственного клиента; их и приватные ключи в Git не добавляем.

## Что можно взять из 3.3.5

| Наработка | Как переносить |
|---|---|
| Квесты, NPC, спавны, маршруты, торговцы | Выборочная конвертация SQL в актуальную схему Forever с проверкой ID и связей |
| SmartAI и conditions | Проверка поддерживаемых событий, действий, параметров и условий; затем отдельная миграция |
| C++ скрипты | Адаптация под API текущего ядра и повторная сборка; готовые бинарные модули не совместимы |
| Предметы, заклинания, модели | Проверка наличия ID в клиентских DB2 и соответствия серверным данным |
| Аддоны | Адаптация Lua API, событий и интерфейса под клиент Forever |
| Карты и модели | Отдельный перенос клиентских ресурсов и повторное извлечение серверной геометрии |

Не импортировать полный world/auth/characters dump 3.3.5 поверх Forever.
Одинаковые названия таблиц не означают одинаковую структуру или семантику полей.
Для сторонних скриптов и SQL сохранять их лицензию и атрибуцию.

В README advocaite/TrinityCore уже описан vanilla-мир, конвертированный из
VMaNGOS, и контент Skyborne / Zephras Isle. Это пример возможности переноса,
но не универсальный конвертер для произвольной базы 3.3.5.

## Локации новых дополнений

Возможно как отдельный проект портирования. Сначала проверить, нет ли нужных
ресурсов уже в конкретной сборке клиента Forever: по версии игры это не определить.
Если отсутствуют, одной серверной SQL-команды или телепорта недостаточно.

1. Проверить совместимость ADT/WDT, WMO, M2, текстур и их зависимостей с целевым клиентом.
2. Подготовить клиентскую доставку ресурсов и корректные FileDataID/ссылки.
3. Согласовать Map, AreaTable и остальные необходимые DB2/hotfix-записи.
4. Из полученного клиента извлечь maps/vmaps; при использовании pathfinding — построить mmaps.
5. Добавить серверные настройки карты/инстанса, точки входа, спавны и скрипты.
6. Проверить загрузку, рельеф, коллизии, воду, line of sight, маршруты NPC и возврат после смерти.

Наличие геометрии не переносит автоматически механики дополнения, квесты и боссов.
Экспорт в OBJ/GLTF полезен для анализа и редактирования, но сам по себе не создаёт
играбельный патч клиента. Готовый проверенный конвейер для 70532 не найден.

## Общий конвейер переноса локаций

Цель — повторяемая установка пакетов совместимых локаций с профилем исходной
сборки и целевой сборки. Обещать перенос всех локаций из любой версии пока
нет оснований: закрытый клиент должен понимать полученные форматы и функции.
Наличие современного рендера само по себе эту совместимость не доказывает.

Общий механизм должен выполнять следующие операции:

1. Читать карту и собирать полную цепочку зависимостей: ADT/WDT, WMO и группы,
   M2/SKIN/анимации, текстуры и связанные DB2. Результат — манифест пакета.
2. Проверять форматы по профилю донора и 70532; конвертировать поддерживаемые
   различия и выдавать явный отказ для остальных. Экспорт 12.1.5 и данные
   сервера Legion 7.3.5 требуют отдельного согласования.
3. Сопоставлять FileDataID/MapID/AreaID и ссылки, находить конфликты,
   переиспользовать одинаковые ресурсы по хешу без замены старых данных.
4. На копии клиента согласованно обновлять ROOT, TVFS, encoding, IDX,
   download/build config. Проверять старые ресурсы и обеспечивать откат.
5. Подключать клиентские/серверные записи карты, извлекать maps/vmaps/mmaps,
   проверять загрузку в WowB.exe, поверхность, коллизии, воду и точки появления.
6. Отдельно переносить NPC, предметы, квесты и механики с адаптацией SQL/скриптов.

Общую упаковку и проверку можно использовать многократно. Для 3.3.5, Legion
и более новых доноров потребуются разные профили форматов/таблиц. Некоторые
локации могут потребовать ручной адаптации или неподдерживаемых клиентом функций.
Массовый запуск имеет смысл после успешного переноса нескольких разных
участков, включая WMO-интерьер и обычный ландшафт.

### Текущее состояние

| Этап | Подтверждённый результат |
|---|---|
| Данные донора | Получены пять тайлов участка Даларана; проверен небольшой RAW-образец, полный набор зависимостей не доказан |
| Ресурсы Forever | Четыре общие модели совпали; четыре CKey донорских WDT/ADT не открываются |
| Запись CASC | Синтетические baseline/candidate читаются по FileDataID через ROOT v2, TVFS, encoding и IDX; проверены ошибки и read-only Docker |
| Обновление существующего хранилища | Инкрементальный updater проверен на лабораторных копиях (70 + 1 FileDataID); профиль настоящего клиента ещё не проверен |
| Игра | Добавленная карта не загружалась в WowB.exe; Map/Area и коллизии Legion не установлены |
| Массовый импорт | Не реализован |

Подробности: [образец Даларана](zones/DALARAN-SAMPLE.ru.md) и
[сквозной CASC-стенд](zones/CASC-SANDBOX.ru.md).
Первый практический рубеж — загрузить небольшой участок в копии клиента,
пройти по нему с корректными коллизиями и подтвердить сохранность старого мира.

## Практический порядок

Сначала рабочий базовый сервер, затем один тестовый NPC/квест из старой базы,
затем небольшая изолированная зона. Резервная копия БД перед каждой миграцией.
Изменения ядра следует хранить в отдельном репозитории: этот Docker-проект
по умолчанию скачивает advocaite/TrinityCore, а не содержит исходники ядра.
Перед публикацией настраивать собственные пароли и сертификаты.
