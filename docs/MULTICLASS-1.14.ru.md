## Причины ошибок и исправления

Раньше отбор считал любую запись категории `CLASS` способностью персонажа.
В Forever туда входят также Mounts/Companions и семейства питомцев. Нулевая
семья заклинания дополнительно разрешала общие и служебные записи. Поэтому
в списке охотника и паладина появились лошади и волки из коллекции.

Теперь сервер использует только видимые школы персонажа, исключает pet-only
и скрытые навыки, проверяет классовую семью заклинания и отбрасывает ауру
ездового животного. Нулевая семья допускается только у перечисленных
базовых утилит охотника и проверенного исключения чернокнижника. Клиент
дополнительно отбрасывает ездовые заклинания через `C_MountJournal.GetMountFromSpell`.
Коллекция ездовых животных и родные выученные заклинания не удаляются.
Старые записи покупок остаются в БД; исключённые записи больше не занимают
новые слоты поддерживаемого каталога.

«Приручение зверя» — отдельная нативная способность охотника с каналом
на выбранного приручаемого зверя, а не список существ. Проверки цели, уровня,
свободного места и необходимые умения питомца остаются штатными. Приобретение
приручения не создаёт готового питомца; полный игровой сценарий ещё требует
проверки после установки сервера 1.14.

Деревья также смешивали навыки персонажа/питомца и два параллельных источника:
Trait* и fallback Talent.db2. Название выбиралось из посторонних skill-lines,
а координаты считались по чужому пространству дерева. В присланной диагностике
видимые узлы охотника имели **GridX 50–53**, то есть находились вне панели.

Исправлено:

- Школа берётся из нативного `SkillLineXTraitTree` и школ самого класса.
  Пет-деревья исключены. Trait* и Talent.db2 не смешиваются для одного класса.
- Ветка имеет один ключ школы; повторы «Свет», «Защита», «Выживание» объединены.
  Неопознанное pet-дерево не переименовывается в «Повелителя зверей» наугад.
- Координаты нормализованы отдельно внутри школы. Клиент также исправляет
  полученные абсолютные колонки 50–53 и не рисует узлы за пределами панели.
- Перед маркером готовности сервер проверяет **три школы каждого из девяти
  классических классов**. Неудачный аудит блокирует готовность кандидата;
  испытание не позволяет переключить рабочий сервер на неполные данные.
- Фоны — настоящие `talents-background-<class>-<specialization>` из клиента,
  с предпочтением его `ClassTalentUtil.GetVisualsForSpecID`. Используются
  нативные кнопки веток и панели. Нет замены фона большой тусклой иконкой класса.
- Узлы, связи, ранги, покупка/возврат используют прежнюю нативную проверку
  `TraitMgr::ValidateConfig`. Неподдерживаемые ресурсы/эффекты остаются заблокированы.

Дополнительные поля `TREE` несут ID школы и дерева; `SCHOOLS 1` отмечает новый
каталог. Протокол остаётся 3. Аддон совместим со старым сервером, но **полное
исправление состава каталога требует серверного обновления**.

## Сначала собрать и испытать копию

В Ubuntu/WSL. Рабочий сервер во время подготовки остаётся доступен:

```bash
(
set -euo pipefail
cd "$HOME/WoWForEver"
git fetch origin c13cdbff6cc0623e24a8667d42f343b80f8005a8
talent_tools=$(mktemp -d "$HOME/WoWForEver-talent-tools.XXXXXX")
git worktree add --detach "$talent_tools" FETCH_HEAD
python3 "$talent_tools/scripts/upgrade-clean-gameplay.py" prepare \
  --root "$HOME/WoWForEver-clean" \
  --baseline /mnt/e/WoWForEver-work/reports/baseline-70658-20261107-003902 \
  --jobs 2
)
```

Это новая серверная версия, первая сборка необходима. Предыдущий готовый образ
1.13 не содержит исправлений каталога. `--reuse-built-image` при повторе принимает
только образ с точными новыми метками и контрольными суммами.

Ожидаются `CANDIDATE SERVICES VERIFIED`, затем `PREPARED GAMEPLAY UPGRADE` с
**точным** путём новой `transition.json`. Сохраните папку инструментов и путь.
В диагностике нового мира должен быть `player school audit passed`.
При ошибке этого аудита не обходите проверку; пришлите причину и итог подготовки.

Испытание использует собственные БД, файлы и внутреннюю Docker-сеть, без портов
хоста и рабочих bind mounts. Проверяет мир, модули, realm, login TLS и web,
затем удаляет только свой стенд. SQL и приватные отчёты в Git не публикуются.

## Применение после успешного prepare

Команды ниже — **шаблон**. Подставьте checkout и запись именно своего `prepare`:

```bash
python3 /home/Kayter/WoWForEver-talent-tools.ИМЯ/scripts/upgrade-clean-gameplay.py \
  apply --record /home/Kayter/WoWForEver-clean/advancement/ИДЕНТИФИКАТОР/transition.json
```

Перед переключением делается свежий дамп четырёх БД, проверяются аккаунты,
персонажи и десять таблиц модулей. SQL только добавляет отсутствующую preferences.
Для текущего 1.13 меняются образ мира, его версия/отпечатки и controller;
**environment мира, Scaling 0.4, Dungeon Finder 0.2, остальные службы, порты,
тома, TLS и прогресс сохраняются**. Не используйте старую запись `347c815174f8`
для этого обновления и не удаляйте действующий dungeon-upgrade checkout.

Откат той же новой записи:

```bash
python3 /home/Kayter/WoWForEver-talent-tools.ИМЯ/scripts/upgrade-clean-gameplay.py \
  rollback --record /home/Kayter/WoWForEver-clean/advancement/ИДЕНТИФИКАТОР/transition.json
```

Возвращается предыдущий runtime/controller, старый SQL поверх прогресса не
импортируется. Отмена только подготовленной записи не останавливает службы.

Аддон обновляется отдельно через Multi: обновления включены, разработка выключена,
набор «Тестовые», обновить список версий, сохранить и перезапустить игру.
Версия Ascension — **1.14.0**, в TOC семь файлов с `TalentSchools.lua`.
Независимый pin энциклопедии и stable не меняются. После установки проверить
три ветки/фоны, видимость всех рядов, приручение реальной цели и сохранение
питомца после входа, а также действующие соло/групповые подземелья.
