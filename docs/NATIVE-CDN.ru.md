# Загрузка клиента 70658 из CDN и вход на наш сервер

Multi 1.5 добавляет отдельный экран «Загрузка игры». Источники содержимого
и сервер входа независимы. Источники взяты из предоставленного журнала Nvord
ForeverLauncher 2.0.5/2.0.7: cdn.nvord.com, dl.nvord.com, mirror.nvord.com,
перечисленные в журнале зеркала и fallback CDN Blizzard. Файлы запрашиваются
по нативному пути tpr/wow/config или tpr/wow/data с хешем и HTTP Range.
launcher.json обновляет сторонний лаунчер и не используется как манифест игры.

Для wowf **70658** зафиксированы BuildConfig
165410aca770316ea0f88100bb4830c2 и CDNConfig
f0fcf03baf658e38f2f6c96a77798a2c, подтверждённые исходной установкой.
Live-версии и предзагрузка не меняют эту сборку. Установщик сервера и четыре
его базы не вызываются загрузчиком. 70707 остаётся отдельным подготовленным
набором, а не заменой исходной установки.

## Использование

1. Распакуйте **весь** ZIP Multi 1.5 либо установите NSIS-пакет. Рядом с portable
   WoWForeverMulti.exe нужен forever-casc-worker.exe; в пакете также лицензия
   и полный исходный код отдельного GPL-загрузчика.
2. Откройте «Загрузка игры». Выберите **новую пустую папку**, например
   E:\WoWForEver-work\clients\70658. Не указывайте E:\WoW_Forever или v4.
3. Выберите Русский, при необходимости HD, нажмите «Скачать / продолжить 70658».
   Загружается весь выбранный манифест, а не только priority-0/Critical.
4. Дождитесь итоговой проверки. Пауза сохраняет checkpoints; продолжение
   пропускает уже сохранённые объекты. При неполном плане, ошибке хеша или
   отсутствующих объектах полная готовность не объявляется.
5. Нажмите «Подключить этот клиент». Multi проверит настоящий FileVersion,
   метаданные и совпадение со сборкой сервера, затем сменит только папку игры
   и язык. Наш адрес, портал trinity.actual.battle.net, CA и публичный ключ
   сохраняются. Вход выполняется нашим аккаунтом, не аккаунтом Nvord.

«Полная проверка» читает каждый индексированный CASC-объект, проверяет BLTE
и хеши блоков, отдельно проверяет INSTALL-файлы и наличие выбранных ресурсов
манифеста. Метаданные для плана кешируются отдельно от проверяемой установки.
Непроверяемые patch-объекты подсчитываются отдельно, не удаляются как повреждённые.
Это проверка файлов; запуск/вход в игру на Windows всё ещё требуют реального
пользовательского теста.

«Восстановить управляемый клиент» работает только с папкой, созданной этим
загрузчиком. Повреждённые записи индекса исключаются после повторной проверки
снимка, индексы сохраняются в резервную папку, затем нужные объекты скачиваются
и проверяются вновь. Неповреждённые архивы не пересобираются из разрозненных
файлов; исходные установки не принимаются как управляемые. Защиту исходного
клиента в настройках отключать не требуется.

## Архитектура и границы проверки

Самостоятельный forever-casc-worker — GPL-3.0-or-later адаптация TACT/CASC
модулей Lightforge commit 360ff4c8dce06b9cedbb863088fdfc8842a6c521. Обмен с
Multi идёт через JSON lines; серверные логины, токены, CA и ключи в запрос
загрузки не входят и отвергаются схемой. Полный соответствующий исходный код,
происхождение и изменения находятся в tools/forever-casc-worker и включаются
в worker-source.zip. Игровые файлы в Git и в дистрибутив не добавляются.

HTTP-зеркала проверяются по цепочке хешей BuildConfig → манифесты → объекты.
Сертификат нашего игрового сервера не используется как доверие к чужому CDN.
Зашифрованные объекты могут проверяться по закодированным блокам без их
расшифровки; это не утверждение о проверенном игровом протоколе или всех
возможных пользовательских модах.

Отчёт сохраняется в %APPDATA%\forever-launcher-app\workshop\reports\native-*.json.
Он содержит выбранную сборку, счётчики, путь клиента и диагностический журнал
работника. Старое «сравнение с оригиналом» в мастерской остаётся отдельной
операцией и не заменяет проверку нативных CASC-объектов.
