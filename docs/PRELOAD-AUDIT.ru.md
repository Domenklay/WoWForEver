# Проверка предзагрузки перед реализацией активации

После успешной проверки локальных EXE/DLL переходите к
[отдельному извлечению оригинальных INSTALL-файлов](PRELOAD-STAGING.ru.md)
и проверке их настоящей версии. Сам читающий аудит ничего не активирует.

В Multi 1.4 пока нет функции активации клиентской предзагрузки. Сравнение
v4 с E:\WoW_Forever показало настоящий EXE **70658 в обеих папках**.
Подготовленный ранее механизм обновляет сервер/БД после подтверждения нового
клиента; он не устанавливает EXE/DLL клиента. Это разные операции.

Сам Nvord пишет «70707 подготовлена, используется прежний клиент». В
[описании разработчика](https://forum.nvord.com/d/476-vyshel-forever-launcher-20)
предзагрузка описана как скачивание следующей версии заранее. Наличие новой
Data/config не доказывает, что распакованы новые файлы запуска.

`scripts/audit-client-preload.py` делает **только читающую** проверку
манифеста пакета 70707 с ключом 7feb61f3c994bcb168526b8db521514a:

- проверяет MD5 BuildConfig и его build-name/build-uid;
- читает целевые INSTALL и ENCODING из существующего CASC, проверяя BLTE,
  полные EKey/CKey и контрольные суммы блоков;
- выбирает Windows x86_64 через MSB-битовые маски INSTALL;
- сравнивает хеши текущих Wow.exe/wow_loader.dll с хешами манифеста 70707;
- проверяет, можно ли прочитать и подтвердить их предзагруженные копии;
- проверяет, что источник не менялся во время чтения.

Скрипт не скачивает, не извлекает на диск и не активирует файлы. Оригинальная
установка, .build.info, индексы и архивы не изменяются. Отчёт выводится в
терминал. Целевой манифест и локальная копия EXE не доказывают целостность
всех моделей/текстур или совместимость сервера. Неподдерживаемый формат или
отсутствующие локальные метаданные дают явный отказ/неполный аудит.

## Запуск в Ubuntu/WSL

```bash
cd ~/WoWForEver
git fetch origin codex/preload-audit-20261106
preload_tools=$(mktemp -d "$HOME/WoWForEver-preload-tools.XXXXXX")
git worktree add --detach "$preload_tools" FETCH_HEAD
python3 "$preload_tools/scripts/audit-client-preload.py" --client '/mnt/e/WoW_Forever' --region EU
```

Перед чтением закройте игру и завершите загрузки исходного установщика,
чтобы они не меняли проверяемые архивы. Выполняется только последний вызов
Python, никаких install/repair/activate/server-команд в этом блоке нет.
Если ENCODING отсутствует, аудит так и сообщит; сетевой подмены не будет.
Этапы печатаются в терминал. Манифест ENCODING этой предзагрузки занимает
около 141 МБ; его чтение и проверка могут занять время, это не скачивание.

Результат нужен для следующего этапа установки клиента: из какого проверенного
манифеста брать файлы запуска и чего нет локально. `activation_ready` всегда
false: полноценный установщик и проверка запуска ещё не реализованы этим
скриптом. Наличие манифеста не является поводом менять номер сервера.

## Если проверка не смогла выбрать Wow.exe

В первом отчёте пользователя INSTALL прочитан, но проверка остановилась с
`Ambiguous or missing Windows x64 Wow.exe in install manifest`. Этот результат
не доказывает отсутствие EXE в предзагрузке: прежний скрипт предполагал номера
категорий тегов Windows=1 и x86_64=2 и скрывал список записей при отказе.

В `audit_revision: 2` выбор использует именно именованные маски Windows и
x86_64, независимо от номеров категорий. Раздел `install_manifest` показывает
имена и категории тегов, количество выбранных записей и до 64 кандидатов
EXE/wow_loader.dll с их путями, хешами и тегами. Диагностика сохраняется при
отказе выбора. Другое имя или вложенная папка не превращаются автоматически
в корневой Wow.exe. Повторный запуск нужен для фактического манифеста;
исправление скрипта ещё не подтверждает причину первого отказа или успешную
активацию клиента. Клиент и сервер по-прежнему не изменяются.

Повторный отчёт установил реальную причину отказа: в INSTALL **два**
Windows x86_64 файла с именем Wow.exe. Один помечен CN, второй —
EU/KR/TW/US. Категории Windows=1 и x86_64=2 в этом конкретном манифесте
были корректны; первая правка предположения о категориях не устраняла
региональную неоднозначность.

В `audit_revision: 3` выбор требует маски Windows, x86_64 и указанного
региона (`--region EU` по умолчанию). Для присланного манифеста EU выбирает
CKey `753e09cce90875e466bbf55c3d3ce169`, размер 85 829 840 байт; CN имеет
другой CKey `606df11c09fe22c9456b951a89848329`, размер 109 949 136 байт.
Общий wow_loader.dll: CKey `bff1efe594682fd926c51bacf701bf40`, 41 311 952
байта. Эти значения прочитаны из манифеста, а не из распакованного EXE.
Версия его PE/Windows-ресурса и наличие полного игрового содержимого ещё
не установлены. Не переносите номер пакета в профиль сервера на основании
этого выбора.

`selected_install_tags` показывает критерии, `selected_install_entries` —
количество региональных записей. В диагностике каждого кандидата появляется
`selected_for_region`. Отсутствие нужного региона или оставшиеся дубликаты
дают отказ; скрипт не подставляет первый EXE, не меняет регион исходной
установки и не переключает сервер. Это исправление аудита, не лечение
зависания игры или готовый механизм установки обновления.
