# Проверка загрузчика клиента, 5 ноября 2026

**ForeverLauncher из advocaite/foreverlauncher-releases не подходит как готовый
модуль скачивания и восстановления WoW.** В проверенной сборке 2.5.0 обновляется
сам лаунчер, а кнопка Client update запускает серверный скрипт. Это отдельный
продукт от использовавшегося пользователем лаунчера Nvord 2.0.5 с движком
forever-casc 0.1.0.

## Что проверено

- [README TrinityCore, ветка forever](https://github.com/advocaite/TrinityCore/tree/forever#readme)
  действительно ссылается на отдельные релизы ForeverLauncher.
- [Репозиторий лаунчера](https://github.com/advocaite/foreverlauncher-releases)
  явно описывает себя как релизные сборки без исходников.
- Скачаны Windows EXE, его отдельная подпись и Linux Python-скрипт из
  [релиза v2.5.0](https://github.com/advocaite/foreverlauncher-releases/releases/tag/v2.5.0).
  Файлы остаются вне нашего Git.
- Размер Windows EXE: 253440 байт. SHA-256:
  `2cca1687865375861a8feafe896aa4f2862b74a7b797b8e0c0ef400129b90d6a`.
  Совпадает с опубликованным в релизе и в метаданных GitHub.
- Отдельная подпись согласуется с EXE: RSA PKCS#1 v1.5 / SHA-256.
  Публичный ключ взят из самого EXE: это проверка согласованности файлов,
  а не независимое подтверждение доверия к издателю.
- EXE является управляемой сборкой .NET/WPF. Прочитаны метаданные типов,
  строки интерфейса и ссылки вызовов IL; Windows GUI не запускался.
- Выполнен `python3 forever-launcher-linux.py --help`. В коде и справке
  перечислены настройка portal, публичного ключа, группы региона и запуск
  либо подключение к уже запущенному клиенту. Команд установки/ремонта нет.

## Что означают найденные кнопки и методы

| Функция | Наблюдаемое поведение |
|---|---|
| `Updater.Latest` | Читает GitHub Releases для самого лаунчера; выбирает `ForeverLauncher.exe` и `ForeverLauncher.exe.sig`. |
| `Updater.Download` | Скачивает EXE и подпись, проверяет подпись и сохраняет новую версию лаунчера. |
| `Updater.InstallAndRestart` | Заменяет лаунчер и перезапускает его с `--updated`. |
| Client update | Обработчик `LocalServerView.<Build>b__1e` передаёт `setup\add-client-build.bat` в `RunRepackScript`. |
| Setup | Подготавливает сервер по установленному клиенту: извлечение данных, сертификат и учётная запись. |
| Запуск игры | Выбирает уже существующий Wow.exe, пишет отдельный WTF и настраивает подключение. |

В проверенных типах, методах и зависимостях не найден модуль установки или
ремонта CASC. Это результат статической проверки конкретного релиза, а не
проверка загрузки игры в Windows и не утверждение о будущих версиях.

## Что нужно WoW Forever Multi

Встроенной загрузки клиента в Multi 1.1.0 пока нет. Для неё нужен отдельный
модуль TACT/NGDP/CASC, который:

1. Читает установленный продукт и точную сборку из `.build.info` и конфигов.
2. Строит план по манифестам этой сборки и выбранному языку/набору ресурсов.
3. Различает отсутствующий ресурс, повреждение и неподдерживаемый формат;
   хеш самого data.NNN не заменяет проверку объектов внутри CASC.
4. Загружает нужные диапазоны с доступного CDN, проверяет их хеши, поддерживает
   докачку и согласованно обновляет локальные индексы/метаданные.
5. Блокирует одновременное обслуживание хранилища игрой или другим лаунчером
   и повторно проверяет результат после восстановления.

Для текущего эксперимента исходная цель — **wowf 1.60.1.70658**. Последняя
официальная сборка и сборка, поддерживаемая новым upstream-сервером, могут быть
другими; проверка файлов не должна незаметно менять версию. Существующие
скопированные v2/v3 и исходная установка должны оставаться раздельными.

В присланном `Tact.log` наблюдались `mirror.nvord.com` и серверы Blizzard.
Адрес зеркала сам по себе не определяет путь продукта, доступность старой
сборки, формат манифестов или правила выбора HD/locale; эти данные ещё нужно
получить из профиля соответствующей установки/загрузчика и проверить.

**Хранить всю игру в Git не требуется.** В Git достаточно кода и настроек
загрузчика. Игровые данные можно получать с CDN, если нужная сборка там
доступна. Если потребуется собственное хранение, для больших файлов нужен
отдельный HTTP/S3-сервис с проверяемыми манифестами, а не история исходников.
Доступность нужной сборки на CDN в этой проверке не установлена.

Эта проверка не изменяла пользовательский клиент, Docker, базы и сервер.
Она не подтверждает причину зависания на выборе персонажей и не подтверждает
его устранение.
