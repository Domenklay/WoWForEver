# Мультикласс 1.12.0: опыт 90/10 и штатный каталог Forever

Рабочая ветка: `codex/native-cdn-70658-20261106`. Клиент и ядро остаются 70658.
На ПК пользователя пока подтверждён сервер 1.11.0. Наличие этого кода и CI
не означает установку новой серверной версии или проверку каждой способности в игре.

## Опыт

При активном подклассе по умолчанию 90% награды получает подкласс, 10% — персонаж.
Отключение «Передавать 90% опыта подклассу» сохраняет активный подкласс и отдаёт
100% опыта персонажу. Команды аддона: `/fa xpshare 0`, `/fa xpshare 1`.
Настройка отдельная для каждого персонажа, сохраняется между входами и не требует
снятия купленных способностей. Её можно менять в бою.

Сотые доли сохраняются: сто наград по 1 XP дают 90 XP подклассу и 10 персонажу.
Подкласс ограничен `min(40, уровень персонажа)`. Если он не может принять свою долю,
остаток идёт персонажу, включая награду, на которой достигнут предел.
Неактивный подкласс опыт не забирает. Существующие уровни/XP не сбрасываются.

Добавляется таблица `characters.forever_advancement_preferences` с `guid`,
`xp_enabled`, `xp_remainder`. Старые таблицы не переименовываются и не очищаются.

## Заклинания и таланты

Рабочее меню получает SpellID и принадлежность классу из загруженных **нативных**
`SkillLineAbility`, `SkillLine`, `SkillRaceClassInfo` и `SpellMgr` текущего сервера.
Это охватывает 13 классов; отсутствие поддержки вторичного ресурса не превращает
такую способность в доступную покупку. Ранги одной нативной цепочки занимают один
слот; показывается ранг, подходящий уровню подкласса.

Старые имена/деревья Ascension не подставляются вместо отсутствующих заклинаний.
Кастомная вкладка и Barrier 701463 убраны из меню. Исходный донорский каталог
остаётся в Git для происхождения и аудита, но его `Catalog.lua`/`CustomRules.lua`
не загружаются новым TOC. Совпадение имени без нативной принадлежности классу
не даёт права изучать заклинание.

Старые покупки остаются в БД. Для способности с точным нативным SpellID, классом
и подтверждённым именем добавляется связь с новым ID каталога. Неоднозначная старая
покупка не заменяется похожим заклинанием и не занимает новый доступный слот.
Возврат покупки снимает также старый связанный ID, чтобы покупка не возникла
заново при входе. Старые ранги талантов сохраняются для истории/отката.

**Таланты 3.3.5 скрыты.** В правой части показываются реальные записи классовых
деревьев `SkillLineXTraitTree` / `TraitNode` / `TraitNodeEntry` / `TraitDefinition`
и `Talent.db2` из Forever (без повторов одних и тех же SpellID), с нативными иконками и описаниями. Это **просмотр**, не готовая
раскладка талантов подкласса. Старые пассивные эффекты не переносятся автоматически
на новые узлы. Распределение должно отдельно учитывать условия, валюты, связи,
выборы, специализацию и замену способностей штатного `TraitMgr`; нельзя объявлять
дерево рабочим только по наличию SpellID. Основной класс продолжает использовать
штатное окно талантов игры.

Способность, допущенная по ID/классу/стоимости, ещё требует игровой проверки
эффектов, оружия, форм, питомцев и проков. Поддержка ресурсов пока ограничена
маной/яростью/энергией; остальные варианты видны при «Все умения» и заблокированы.

Аддон 1.12.0 совместим с протоколом 3 действующего сервера 1.11.0: он строит меню
из уже проверенных сервером SpellID. Без нового сервера чекбокс опыта скрыт,
а полный новый каталог/просмотр талантов ещё не поступает. Не считать отсутствие
чекбокса в этом случае ошибкой лаунчера.

## Проверка на копии перед переключением

Не запускайте `enable-clean-gameplay.py install` поверх другого активного
fingerprint и не откатывайте рабочий сервер ради обхода этой проверки.
Используйте отдельный переход `scripts/upgrade-clean-gameplay.py`.

В Ubuntu/WSL:

```bash
(
set -euo pipefail
cd "$HOME/WoWForEver"
git fetch origin codex/native-cdn-70658-20261106
multiclass_tools=$(mktemp -d "$HOME/WoWForEver-multiclass-tools.XXXXXX")
git worktree add --detach "$multiclass_tools" FETCH_HEAD
python3 "$multiclass_tools/scripts/upgrade-clean-gameplay.py" prepare \
  --baseline /mnt/e/WoWForEver-work/reports/baseline-70658-20261107-003902 \
  --jobs 2
)
```

`prepare` сначала проверяет действующий профиль 1.11.0, собирает новый образ
(либо использует совпавший по контрольным суммам), затем поднимает его на **копии**
сохранённых файлов/четырёх БД. У стенда внутренняя Docker-сеть, собственные тома,
нет портов хоста и рабочих bind mounts. Новая SQL-таблица создаётся только в копии.
Проверяются world/три модуля/realm/login TLS/web; ресурсы стенда удаляются.
Рабочий сервер продолжает работать. Нужны место для распаковки копии и сборки.

В каталоге отчёта остаётся `native-catalog.tsv`: нативные/старые SpellID, класс
и причина включения/отказа, а также записи штатных талантов. Сам отчёт из данных
установки не публикуйте в Git. Конкретные количества появятся после этой проверки;
облачные фикстуры не содержат полного набора DB2 пользователя.

Ожидаемый итог — `CANDIDATE SERVICES VERIFIED`, затем `PREPARED GAMEPLAY UPGRADE`
с **точным путём** `.../advancement/<12 hex>/transition.json`. Сохраните этот путь
и папку инструментов; не выбирайте запись по принципу «последняя по дате».
`--reuse-built-image` разрешает только готовый образ с совпавшими метками источников.

## Применение и откат

После успешного `prepare`, из **того же** checkout, с напечатанным абсолютным путём:

```bash
python3 /home/Kayter/WoWForEver-multiclass-tools.ИМЯ/scripts/upgrade-clean-gameplay.py \
  apply --record /home/Kayter/WoWForEver-clean/advancement/ИДЕНТИФИКАТОР/transition.json
```

Это шаблон, замените обе части данными своего `prepare`. Перед переключением
останавливаются world/login/web, сохраняется **свежий** дамп четырёх БД и контрольные
суммы содержимого десяти таблиц модулей. Меняются только образ worldserver,
его запись состояния и controller; порты, mounts, MySQL, bnet, web, TLS и учётные
данные сохраняются. SQL только добавляет preferences. Готовность и сохранность
прогресса проверяются до возобновления login/web.

Ошибка возвращает прежние runtime-файлы/образ. Ручной возврат:

```bash
python3 /home/Kayter/WoWForEver-multiclass-tools.ИМЯ/scripts/upgrade-clean-gameplay.py \
  rollback --record /home/Kayter/WoWForEver-clean/advancement/ИДЕНТИФИКАТОР/transition.json
```

Старый SQL-дамп **не импортируется** поверх прогресса. Дополнительная preferences
остаётся для следующего обновления. Отмена только подготовленного кандидата не
останавливает рабочие службы. После возврата старый сервер не использует новые
нативные покупки, но их записи не удаляются. Не используйте старый модульный
`install.json` как запись этого перехода.

После установки выберите тестовый комплект во вкладке Multi «Игровые аддоны»;
список и версии: [ADDON-CHANNELS.ru.md](ADDON-CHANNELS.ru.md). Подтвердите в игре
90/10, отключение без деактивации подкласса, предел уровня, повторный вход,
изучение/возврат/книгу/панели и оба вида серверов до продвижения в stable.
