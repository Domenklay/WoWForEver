# Проверка обновления worldserver 70658: подземелья, Scaling 0.4 и Multi 1.13

Документ описывает **кандидата**, а не выполненное обновление компьютера.
Рабочий сервер `forever-clean` по последнему подтверждённому снимку
использует Ascension 1.11.0, Scaling 0.2.0 и исходный gameplay-image
`forever-trinitycore:gameplay-70658-4530bd4e14a1`.
Каталог Multi не обновляет серверные C++-модули.

## Состав нового образа

- Forever Ascension **1.13.0** — по текущей рабочей ветке 70658;
  additive preferences.sql для распределения опыта.
- Forever Scaling **0.4.0** — персональный нижний предел
  `игрок - 3` (вместо `игрок - 9`), поддержка атакуемых
  нейтральных NPC с исходного уровня 10, исключения для мирных.
- Dungeon Scaling: фиксация размера группы 1–5 при начале боя;
  HP и исходящий урон для одиночного прохождения; рейды не меняются.
- Forever Dungeon Finder server **0.2.0** — `FDF SOLO:<mapId>`
  и `FDF GROUP:<mapId>` только из одобренного списка 19 карт;
  лидер / состояние каждого участника проверяются сервером.
- UI подземелий обновляется отдельно через Multi,
  команда `/fd`. Клиентские интерфейсы не перепаковываются.

## Блокирующие условия

Нельзя начинать переход без реального успешного `prepare`.
Проверки и образ Docker в GitHub — НЕ установка на ПК.
`prepare` требует, чтобы `~/WoWForEver-clean` был в фазе ready
и исходный `state.json` соответствовал Scaling 0.2/Ascension 1.11 либо 1.12.
Перед тестами должны быть закрыты все игровые сессии для `apply`.
Не публиковать `state.json`, приватный Compose, дампы SQL, session.json
и сертификаты.

## Шаг 1 — собрать и проверить кандидата, не меняя текущий сервер

В Ubuntu/WSL на том компьютере, где запущен `forever-clean`:

```bash
set -euo pipefail
git -C "$HOME/WoWForEver" fetch origin feature/dungeon-gameplay-upgrade-70658
git -C "$HOME/WoWForEver" worktree add --detach \
  "$HOME/WoWForEver-dungeon-upgrade-70658" \
  origin/feature/dungeon-gameplay-upgrade-70658
python3 "$HOME/WoWForEver-dungeon-upgrade-70658/scripts/upgrade-clean-gameplay.py" prepare \
  --root "$HOME/WoWForEver-clean" \
  --baseline "/mnt/e/WoWForEver-work/reports/baseline-70658-20261107-003902" \
  --jobs 2
```

Ожидаемые конечные строки:

```text
CANDIDATE SERVICES VERIFIED: .../report.json
PREPARED GAMEPLAY UPGRADE: .../advancement/<12hex>/transition.json
```

При этом мир на ПК продолжает работать; новая сборка
тестируется на изолированной внутренней сети с копией четырёх баз.
Стандартные игровые порты/тома `forever-clean` не изменяются.
Проверяются TLS, web, TCP, новый мир и успешная регистрация
`ForeverScaling v0.4` и `ForeverDungeonFinder (enabled=true)`.
Тест не заменяет фактическую проверку персонажами в клиенте.

**Worktree `~/WoWForEver-dungeon-upgrade-70658` после перехода
не удалять:** скрипт управления `server.sh` будет ссылаться
на исходники нового контроллера.

## Шаг 2 — переключение после успешной проверки

Скопировать **точный** путь `transition.json`, который вывел `prepare`.
Не использовать чужую запись или находить произвольную «последнюю».

```bash
python3 "$HOME/WoWForEver-dungeon-upgrade-70658/scripts/upgrade-clean-gameplay.py" apply \
  --root "$HOME/WoWForEver-clean" \
  --record "/home/Kayter/WoWForEver-clean/advancement/<12hex>/transition.json"
"$HOME/WoWForEver-clean/server.sh" status
```

Замените `<12hex>` на идентификатор из своего `PREPARED`.
`apply` проверяет источник и SHA образа ещё раз, останавливает
только игровые сервисы, **делает свежий дамп четырёх текущих баз
и контрольные суммы прогресса**, добавляет таблицу настроек XP,
сменяет только образ worldserver и его флаги (Scaling, Dungeon Scaling,
Dungeon Finder). Данные и сертификаты не перезаписываются.
После запуска сверяет готовность модулей и прогресс,
затем возвращает остановленные сервисы. При ошибке
восстанавливает прошлый runtime; старый SQL поверх текущих
персонажей не импортируется.

Новые флаги после успешного обновления:

```text
FOREVER_SCALING_ENABLED=1
FOREVER_SCALING_MIN_OFFSET=-3
FOREVER_DUNGEON_SCALING_ENABLED=1
FOREVER_DUNGEON_FINDER_ENABLED=1
```

## Шаг 3 — игровые испытания

1. **Одиночный вход:** один персонаж, `/fd` → Огненная пропасть
   или Мёртвые копи → «Войти соло». Проверить телепорт,
   обычную точку входа, возможность перемещаться внутри.
   Попробовать подземелье с более высоким исходным уровнем,
   если штатные требования карты допускают вход.
2. **Уровень и XP:** низкоуровневый атакуемый красный NPC
   должен иметь персональный уровень не ниже `игрок-3`,
   атакуемые жёлтые NPC исходного 10+ — тоже;
   гражданские NPC, тренеры и нейтральные исходного 5-го
   уровня не меняются. Проверить реальный XP после убийства
   (система не создаёт XP для NPC, которым он запрещён).
3. **Соло-бой:** сравнить обычного NPC, элиту, босса:
   HP-факторы 40% / 50% / 55%, входящий по персонажу урон
   масштабируется по правилам; обычная игра/лут не ломаются.
4. **Группа:** 2–5 онлайн, вне боя, лидер нажимает «Группой»;
   участники попадают в один инстанс. Не-лидер и группа
   с офлайн-участником получают отказ, рейды не допускаются.
   На первом контакте размер группы фиксируется до конца боя.
5. **Сброс, смерть, повторный вход:** после wipe/evade/respawn
   здоровье NPC и босса возвращается к правильным значениям.
   Выход/вход не копирует предметы или опыт. Проверить
   возможность выйти, нормальный hearthstone и сохранение прогресса.

Известные ограничения кандидата: нестандартные механики
боссов и награды не масштабируются автоматически; некоторые
ванильные ограничения инстансов могут запрещать одиночный вход,
даже если сервер получил корректный запрос. В этом случае
зафиксировать сообщение мира и карту (mapId), не отключать
штатные проверки безопасности обходным патчем.

## Откат, если обнаружится поломка

```bash
python3 "$HOME/WoWForEver-dungeon-upgrade-70658/scripts/upgrade-clean-gameplay.py" rollback \
  --root "$HOME/WoWForEver-clean" \
  --record "/home/Kayter/WoWForEver-clean/advancement/<12hex>/transition.json"
"$HOME/WoWForEver-clean/server.sh" status
```

Этот откат возвращает старый образ и настройки, **но не откатывает
персонажей во времени**. Новый SQL-дамп и запись перехода
остаются в приватном месте; никакие базы не пересоздаются.

**Запрещено:** `docker compose down -v`, удаление
`mysql-data`, `scripts/enable-clean-gameplay.py install`
поверх готового сервера, старый `forever-scaling-mod.sh install`,
изменение старого образа вручную и удаление рабочих
`*gameplay-tools*`/`*clean-tools*` bind-директорий.
