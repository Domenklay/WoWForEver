# Подготовка к предзагрузке 1.60.1.70707

Уточнение 6 ноября: скачивание выполнено через ForeverLauncher.exe 2.0.5.
В исходной E:\WoW_Forever активный EXE и метаданные всё ещё **70658**.
Переход до активации 70707 блокируется. Подготовлен версионный механизм
обновления с копией базы и возвратом: [SERVER-UPGRADES.ru.md](SERVER-UPGRADES.ru.md).

6 ноября пользователь выбрал предзагрузку 70707 через Battle.net. Текущий
чистый сервер остаётся на 70658. Скачивание, активация нового EXE и перевод
сервера — разные этапы. Multi 1.3 проверяет фактический EXE и блокирует
70707 при профиле сервера 70658. Защита игровых файлов остаётся включённой.

## Что проверено по исходникам

В [upstream PR 271](https://github.com/advocaite/TrinityCore/pull/271)
сборка 70707 описана как использующая тот же протокол, что 70658. На момент
проверки PR **открыт, не объединён**. Его SQL добавляет build_info 70707 и
70755, затем переводит миры на **70755**: применять весь этот SQL для 70707
нельзя. Изменения нумерации сообщений для 70755 также не нужны для 70707.

В текущем чистом ядре b4e7b940593f дополнительные сдвиги включаются начиная
с 70790; 70658 и 70707 проходят одинаковые ветки трансляции. Это согласуется
с PR, но не является проверкой входа реальным 70707-клиентом. Наш чистый
установщик пока разрешает только 70658 и 70790. Он не переключён на 70707
и не должен запускаться заново для удаления/пересоздания существующего мира.

## После завершения загрузки

Дождитесь полного окончания загрузки/обновления в Battle.net и закройте
игру. Состояние «Можно играть» и наличие файлов предзагрузки недостаточны.
В Multi выберите именно новую установку и нажмите «Проверить и подключить
установку». До реального перехода сервера сохраните его сборку 70658.

Для отдельного читающего отчёта используйте поставляемый скрипт
`scripts/inspect-forever-installation.ps1` в **Windows PowerShell**:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-forever-installation.ps1 -GameDirectory 'D:\Games\World of Warcraft' -ExpectedBuild 70707 -ServerBuild 70658
```

Замените пример пути каталогом своей новой установки; скрипт принимает
корень, папку `_forever_`/`_classic_beta_` или сам EXE. Жёстко заданных старых
путей нет. Он отдельно выводит реальную FileVersion и строки .build.info,
сохраняет новый JSON в Temp и не читает содержимое игровых архивов. Число
70707 в метаданных не принимается за обновлённый EXE. Отчёт не подтверждает
полноту CASC; перед отправкой проверьте содержащиеся в нём локальные пути.

## Что потребуется для серверного теста

После подтверждения реального EXE 1.60.1.70707 и продукта нужен отдельный
переход существующего clean-сервера: резервная копия состояния/auth-строк,
регистрация только 70707 в build_info, согласование realm 70 и серверных
данных с этой установкой, перезапуск bnetserver/worldserver и проверка
создания персонажа/входа в мир. Аккаунты, персонажи, TLS и старая извлечённая
база ресурсов сохраняются для возврата; смешивать извлечённые файлы двух
сборок нельзя. На ПК пользователя эти операции не выполнялись.
Новый мигратор описан в SERVER-UPGRADES.ru.md.
После фактического перехода выставляется 70707 в профиле
Multi. Изменение одного числа в лаунчере не переключает сервер.
