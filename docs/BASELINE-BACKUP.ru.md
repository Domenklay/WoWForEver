# Снимок работающего эталона 70658

`scripts/backup-clean-baseline.py` сохраняет активный сервер с тремя модулями.
Копирование выполняется на ПК пользователя; облачные тесты не создают его снимок.
Инструмент не выполняет восстановление, миграции, сборку или смену профиля.

Закройте WoW. Из нового checkout инструментов в Ubuntu/WSL:

```bash
python3 scripts/backup-clean-baseline.py create \
  --output "/mnt/e/WoWForEver-work/reports/baseline-70658-$(date +%Y%m%d-%H%M%S)"
```

Это кратковременно останавливает worldserver, bnetserver и web для согласованного
снимка. MySQL остаётся запущенным. При ошибке остановки/дампа или Ctrl-C сервисы
запускаются обратно через `finally`. При принудительном завершении процесса или
ошибке запуска остаётся `resume-required.json`; проверьте сервер командой
`~/WoWForEver-clean/server.sh status`, при необходимости выполните `start`.

После снимка баз сервисы запущены; большие архивы ресурсов и образов записываются
при работающем сервере. Нужное место оценивается до остановки. Старые копии не
перезаписываются. Для пути `/mnt/e/...` проверяется подключение Windows-диска E.
На время копирования удерживается общий lock управления сервером.

Состав приватной папки:

- `databases-current.sql.gz`: свежие auth/world/characters/hotfixes после установки;
- `server-files.tar.gz`: активные bind mounts четырёх сервисов, в том числе
  извлечённые ресурсы и сертификаты; текущие state/Compose/server.sh/overrides;
  текущая запись отката; отслеживаемые рабочие файлы checkout контроллера и
  инструмента резервирования. Git worktree pointer не копируется как репозиторий;
- `docker-images.tar`: точные ID образов четырёх работающих сервисов;
- `manifest.json`: версии, пути, ID образов, снимок счётчиков/схемы и SHA-256;
- `RESTORE.ru.txt`: назначение файлов и границы восстановления.

Клиент WoW, сырые MySQL-тома, журналы и вся история старых копий не включаются.
Прежний SQL в текущей записи отката остаётся старым снимком; новый дамп имеет
отдельное имя `databases-current.sql.gz`. Папка содержит пароли и закрытые ключи,
хранится приватно. Для отчёта достаточно финальной строки, сами архивы присылать
или публиковать не нужно.

Перед успешным итогом проверяются SHA-256/размеры, gzip, файловый архив и ID образов
в Docker-архиве. Итог — `BASELINE BACKUP VERIFIED: <путь>`.

Повторная проверка работает без Docker и без извлечения файлов:

```bash
python3 scripts/backup-clean-baseline.py verify --backup /путь/к/копии
```

Проверка целостности не означает успешную пробу восстановления. Следующий этап —
восстановление в отдельном окружении с новым MySQL-томом и непересекающимися
портами, без замены рабочего сервера. Клиент и его профиль сохраняются отдельно.
