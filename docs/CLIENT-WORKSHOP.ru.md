# Клиентская мастерская Multi 1.2.1

Мастерская работает до входа в аккаунт сервера. Она сравнивает **файлы установки**
по SHA-256 с выбранным оригиналом или манифестом. Это не чтение всех объектов
внутри CASC и не проверка совместимости клиента с сервером.

## Проверить и восстановить тестовую копию

1. Закройте все копии игры и другие загрузчики клиента.
2. Откройте **Client workshop** слева или нажмите **Verify files** на главной.
3. **Test client folder**: `E:\WoWForEver-work\experiments\Forever-client-v3\_forever_`.
4. **Original game installation**: `E:\WoW_Forever`. Можно выбрать корень или
   `_forever_`. Если этот оригинал существует, Windows-лаунчер предложит его
   по умолчанию. При отсутствии папки выберите её вручную.
5. Оставьте **Download manifest** пустым для работы по локальному оригиналу.
6. Нажмите **Verify files**. Оригинал и копия читаются потоково; проверка
   десятков гигабайт может занять несколько минут. Сравниваются хеши, а не
   только размеры. Проверка не заменяет файлы клиента; отчёт записывается
   в каталог настроек лаунчера.
7. **Restore files** восстанавливает только отличающиеся или отсутствующие
   файлы из оригинала. Все поступающие файлы проходят проверку до установки;
   прежние версии остаются в `.forever-multi/operations/.../backup` тестовой копии.
8. **Install / download** может также создать новую копию из выбранного
   оригинала. Для новой копии выберите отдельную папку, например
   `E:\WoWForEver-work\experiments\Forever-client-v4`.

WTF, Interface/AddOns, Cache, Logs, Errors и Screenshots не входят в эту
эталонную сверку. Дополнительные файлы в копии не удаляются. Копирование
источника на самого себя или во вложенную папку запрещено. Сборка источника
должна совпадать со сборкой существующей копии: незаметного обновления нет.
Установки с несколькими активными продуктами Forever пока требуют отдельной
однозначной копии. Исходный клиент и прежний эксперимент сохраняйте отдельно.

Изменение служебных файлов CASC после запуска игры может давать различия даже
без повреждения ресурсов. Мастерская показывает **different**, не утверждая,
что каждое отличие означает повреждение игры. Если оригинал сам неполон или
повреждён, совпадение с ним не доказывает полноту клиента.

В 1.2.1 под полями папок отображаются разрешённые корни установки и пути `Data`.
Папка `_forever_` разрешается в родительскую папку с `.build.info` и общим `Data`;
этот предварительный просмотр не проверяет хеши или полноту данных.
Кнопки обслуживания блокируются с объяснением, пока запущена игра или другая
операция. У существующего явного выбора английского нет автоматической замены:
для русского интерфейса выберите «Русский» в настройках.

## HTTP-загрузка

Реализован протокол `forever-multi-client-v1`: JSON содержит точные пути,
размеры, SHA-256 и HTTPS URL **полных файлов установки**. Манифест выбирается
как локальный JSON или HTTPS URL. Он имеет приоритет над локальным оригиналом.
Готового профиля CDN Nvord в комплекте пока нет; его существующие feed/peer/CASC
профили нельзя выдать за этот формат. Весь игровой клиент в Git не хранится.

Контракт описан в [схеме манифеста](../content/client-manifest.schema.json).
Профиль задаёт `product`, `version` и `buildKey`. Пути отсчитываются от корня
установки с `Data`, `.build.info` и `_forever_` либо `_classic_beta_`.
Манифест должен представлять полный выбранный baseline, а не несколько
произвольных файлов. Наличие `.build.info`, EXE и путей config/data проверяется,
но объективная полнота всех игровых ресурсов без нативного CASC-профиля
этим не устанавливается. Выбирайте манифест из своего доверенного источника:
SHA-256 сверяет данные с манифестом, не устанавливая личность его автора.

Загрузка потоковая, с проверкой SHA-256. При HTTP Range возобновляется
временный файл; неправильный Content-Range отклоняется. Если сервер отвечает
200 на запрос Range, файл начинается заново и не дописывается к старым данным.
Файл с неверным хешем не устанавливается. Проверка TLS включена; HTTP разрешён
только для localhost/127.0.0.1 при локальном тестировании. Прямой ремонт отдельных
объектов из архивов Blizzard/Nvord пока не реализован.

Все отличающиеся файлы сначала подготавливаются во временной папке на том же
диске. Только после проверки начинается замена с журналом и резервной копией;
`.build.info` устанавливается последним. Пауза работает во время чтения,
копирования и HTTP-загрузки. Во время короткого этапа замены операция завершается
до согласованного состояния. При прерывании процесса журнал блокирует следующую
операцию до **Recover interrupted operation**. Завершённые резервные копии
остаются доступны вручную, отдельной кнопки отката последнего завершённого
восстановления пока нет. Между экземплярами Multi действует файловая блокировка;
другие программы обслуживания игры следует закрыть самостоятельно.

## Отчёты и ограничения

JSON-отчёты находятся в `forever-launcher-app/workshop/reports` пользовательского
каталога настроек. **Copy report path** копирует точный путь; список различий
также раскрывается в интерфейсе. Он ограничен первыми 200 путями, счётчик
различий учитывает все файлы. Во время восстановления требуется свободное место
для новых файлов и сохранения заменённых оригиналов.

В отчёте `different` — число найденных отличий до восстановления, `repaired` —
число заменённых файлов, `remaining` — число оставшихся отличий на момент
завершения операции. Например, `different: 92`, `repaired: 92`, `remaining: 0`
означает успешное восстановление. Следующая проверка после запуска игры может
снова найти отличия в локальном состоянии CASC.
`storageDifferent` учитывает `.idx`, `.lru` и `shmem` непосредственно в `Data/data`;
`resourceDifferent` — остальные проверяемые файлы. Это классификация путей,
а не отдельная проверка объектов CASC. Служебные файлы не исключаются из сверки.
`targetRoot` и `referenceRoot` фиксируют фактические корни операции.

Исходная тестовая цель — wowf 1.60.1.70658. Доступность её ресурсов на внешнем
CDN ещё не подтверждена: необходимы `.build.info` и соответствующий профиль.
Эта версия приложения не подтверждает устранение зависания на выборе персонажей.
