# Диагностика раннего закрытия клиента

Это отдельный сборщик данных для нового `_forever_/Wow.exe`, совместимый с
Windows PowerShell 5.1. Он не запускает игру и не меняет установки, hosts,
сертификаты, реестр или процессы. Записывается только новый JSON-отчёт вне
обеих установок. Права администратора не требуются.

1. Воспроизведите ошибку один раз, закройте её окно и оба лаунчера.
2. Запустите `scripts/collect-client-startup.ps1` из распакованного комплекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\collect-client-startup.ps1"
```

По умолчанию сравниваются `E:\WoWForEver-work\experiments\Forever-client-v3`
и `E:\WoW_Forever`. Если нужно, задайте `-ClientRoot` и `-ReferenceRoot`.
Можно указать корень установки или подпапку `_forever_`.

В конце выводится `Report saved: ...` с путём нового JSON во временной папке.
Отчёт содержит последние 200 строк Tact, General, Connection, Client и DeveloperLog,
их время изменения, выбранные параметры подключения/языка/графики и состав
`Data/data` в оригинале и копии. Служебные файлы до 64 МиБ хешируются, архивы
`data.NNN` не читаются целиком. Выделяются имена файлов, отсутствующие в оригинале,
и максимальное поколение индекса каждого бакета. Это диагностические признаки,
а не доказательство повреждения и не проверка всех объектов CASC.

Параметры аккаунта из WTF не включаются. В самих журналах игры могут присутствовать
имя учётной записи, адреса серверов и пути: просмотрите отчёт перед отправкой.
Сборщик не отправляет его в сеть. Если оригинал отсутствует, сравнение явно
помечается недоступным, а все файлы копии не объявляются лишними.

Успешное совпадение файлов с локальным оригиналом не подтверждает, что сам
оригинал исправен. Для разграничения причин отдельно проверьте, доходит ли
исходная установка до экрана входа через её обычный лаунчер. Повторять
восстановление одних `.idx`/`shmem` до получения свежей ошибки Tact не требуется.
