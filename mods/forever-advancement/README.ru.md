# Forever Ascension — новый аддон развития

Новый аддон и серверный адаптер заменяют ForeverSubclass. Основной класс,
обычная книга заклинаний, нативные таланты и уровни персонажа сохраняются.
Изученные чужие способности разных классов работают в одном наборе; кнопки
классов в меню только фильтруют каталог. Отдельной прокачки подклассов нет.

## Что взято из присланных файлов

Из `Content.zip` без потери полей сохранены 23 709 записей
`CharacterAdvancementData.json`, `SpellRankData.json` и русские названия/описания
заклинаний. Для серверного сопоставления также сохранены названия всех восьми
предоставленных локализаций. Сравнение точное, но не привязано только к enUS: это
важно для сервера с русскими извлечёнными DB2. Названия, иконки-ссылки, классы, школы, ранги, AE/TE, требования,
связи и поля расположения доступны для дальнейшего переноса. Импорт повторяется
командой `python3 scripts/import-ascension-content.py Content.zip`; без аргумента
генератор пересоздаёт файлы из сохранённых JSON. Контрольные суммы — в provenance.json.

В `Content.zip` нет исходных Lua/XML/текстур окна Character Advancement.
В присланном `xml.rar` есть панель `AllStats.xml`, но нет окна Character Advancement.
Структура её разделов перенесена в CharacterStats.lua, исходный XML сохранён
в reference/AllStats.xml; он не загружается напрямую, потому что требует отсутствующие
AllStats.lua и родительские фреймы Ascension. Content2.zip содержит те же 82 файла
с теми же данными, что Content.zip.
Поэтому интерфейс воссоздан под Forever в стиле старинных деревьев: классы слева,
вкладки школ, способности и таланты рядом, поиск и страницы. Изученное находится
в штатной книге заклинаний; отдельной копии книги и плавающей панели нет.
Оригинальные текстуры не включены. Рисунки и иконки берутся из установленного клиента.

Для диагностики доступна прежняя команда `bash scripts/subclass-debug-bundle.sh`
(теперь собирает сведения о ForeverAdvancement).

Это экспериментальный порт данных, а не заявление о переносе всех механик Ascension.
Полный исходный каталог сохранён, но в текущем UI доступны девять классических классов.
У героических/переработанных классов Ascension нет готовой реализации в Forever.

## Установка и дальнейшие обновления

Сначала получите опубликованную ветку изменений Git. Закройте игру и лаунчер.
Сервер должен закончить первый импорт и сообщить `worldserver-daemon ... ready`.
Из существующего `~/WoWForEver` выполните одну команду:

```bash
bash scripts/advancement-mod.sh update /mnt/e/_classic_beta_
```

Подставьте свою папку с `WowB.exe`, если путь другой. Команда сначала собирает
новый сервер, затем устанавливает модуль и аддон. Старая команда
`bash scripts/subclass-mod.sh update /mnt/e/_classic_beta_` вызывает тот же новый установщик.
Дальнейшее серверное обновление: `git pull --ff-only` на ветке нового аддона, затем та же команда.

Для правок только интерфейса используйте быстрый путь (закройте игру и лаунчер):

```bash
git pull --ff-only
bash scripts/advancement-mod.sh addon /mnt/e/_classic_beta_
```

Эта команда сохраняет копии аддонов в `backups/advancement-ui-…` и обновляет
только папку клиента. Она не запускает Docker, не собирает образ, не перезапускает
контейнеры и не обращается к базе. Серверная поддержка версии 1.1 должна уже быть
установлена. Для отката такого обновления используйте обычную команду
`bash scripts/advancement-mod.sh rollback backups/advancement-ui-ДАТА-XXXXXX`;
тип резервной копии определяется автоматически, сервер при этом не затрагивается.


Установщик проверяет готовность прежнего сервера, сохраняет образ работающего
контейнера, `.env`, SQL-дамп четырёх баз, привязки заклинаний, прежние записи
экспериментальных ресурсов и обе папки аддонов в `backups/advancement-…`.
Папка ForeverSubclass удаляется из клиента только после сохранения копии;
устанавливается одна папка ForeverAscension. Сохранённые переменные старого аддона
в WTF не трогаются. Его таблицы прогресса также не удаляются и не превращаются
автоматически в покупки нового модуля. В базе создаются отдельные таблицы
`forever_advancement_spells`, `forever_advancement_resources` и
`forever_advancement_talents`. Обновление с версии 1.0 добавляет таблицу талантов,
не сбрасывая уже купленные способности и ресурсы.

Во время миграции игровые сервисы останавливаются. После запуска установщик
проверяет одновременно готовность worldserver и `ForeverAdvancement ready:`.
При ошибке он возвращает прежний образ, настройки, привязки и аддоны.
Секретные файлы, SQL-дампы и образы с конфигурацией не отправляйте в Git/чат.

## Первая игровая проверка

1. Включите **Forever Ascension** в списке аддонов; при необходимости разрешите
   устаревшие модификации. Войдите и откройте `/ascension` (также `/fa`, `/fsub`).
2. Проверьте три полосы маны, энергии и ярости внутри рамки портрета.
   Прежний отдельный блок под портретом удалён. В окне персонажа нажмите
   «Все характеристики»: доступны основные параметры, ближний и дальний бой,
   заклинания, защита и сопротивления. Значения берутся из API клиента и
   серверного состояния ресурсов; если соответствующего API нет, показано «—». Дополнительная мана рассчитывается
   по уровню основного персонажа и базовой мане жреца с бонусом интеллекта;
   энергия восстанавливается по 10/с, ярость приходит при уроне и убывает вне боя.
   Существующие инициализированные нативные ресурсы остаются основными.
3. Переключите класс и школу. ЛКМ изучает доступную чужую способность или применяет
   уже изученную; ПКМ забывает её. Можно собрать способности нескольких
   классов без переключения активного подкласса. Основные навыки не удаляются.
4. Откройте штатную книгу заклинаний и перетащите изученное на обычную панель.
   Перетаскивание изученной иконки доступно также из меню развития.
   Сохраняются штатные проверки целей, расстояния, движения, формы, экипировки,
   реагентов, GCD и перезарядки. Через аддон обходится только нативная оплата
   ресурса — её один раз выполняет сервер для общего запаса.
5. В дереве талантов левой кнопкой повышайте ранг, правой — возвращайте очко.
   Для дополнительных талантов даётся 1 TE за каждый уровень начиная с 10-го,
   отдельно от нативных талантов основного класса. Цена ранга, колонка, школа
   и вложения предыдущих рядов берутся из каталога. Переключение фильтра
   класса сохраняет покупки и таланты других классов.
6. Проверьте расход общего ресурса, повторный вход и сохранность покупок/рангов.

Для стартового опыта действует серверный лимит 8 изученных способностей.
`ForeverAdvancement.MaxAbilities` в overrides/worldserver.conf меняет его (1–100).
Исходная экономика AE для способностей ещё не реализована: действует лимит
покупок. Дополнительные TE для талантов уже учитываются сервером; предел
задаётся ForeverAdvancement.MaxTalentEssence (по умолчанию 71). Панель быстрых действий
показывает первые восемь покупок; остальные доступны из меню при повышенном лимите.

Поддержаны только совместимые пассивные таланты: обычные модификаторы заклинаний,
характеристик, критического удара, защиты, скорости и аналогичные эффекты из
явного списка сервера. Сложные проки, питомцы, активные таланты и отсутствующие
в Forever ранги не включаются автоматически. Ранги проверяются по нативным
названиям и эффектам. Ауры применяются без выдачи/удаления нативных навыков;
возврат ранга снимает только ауры, добавленные этим модулем. Пассивные ауры не
сохраняются ядром как временные баффы — модуль восстанавливает их из своей
таблицы рангов после входа. Проверяются уровень, TE и предыдущие ряды школы;
возврат нижнего ранга запрещён, если он ломает требования верхних талантов.

Меню использует иконки классов, список умений и сетку талантов по
Column/RequiredTEInvestment исходного каталога. Повторы и отключённые старые
записи режимов скрыты. По умолчанию показаны доступные способности; «Все умения»
открывает весь отфильтрованный каталог. Серые иконки талантов означают требование
уровня/вложений либо отсутствие совместимой реализации — подробности в подсказке.

Сервер допускает непассивные способности с подходящим нативным названием,
уровнем и привязкой SpellScript. Процентные расходы маны поддержаны; если у
основного класса нет нативной маны, базовая стоимость рассчитывается на той же
базе жреца, что и дополнительный запас, а затем проходит штатные модификаторы
стоимости. Периодические, условные, дополнительные расходы и другие ресурсы пока
блокируются. Нельзя обходить их оплату через TRIGGERED_IGNORE_POWER_COST.
При старте журнал содержит причины отсева строк и число совместимых умений/талантов.
Нативные ограничения могут отклонить отдельный каст; проверять их нужно в игре.
Совместимость клиента 70532 целиком не подтверждена облачными тестами.

## Состояние, отключение и откат

```bash
bash scripts/advancement-mod.sh status
bash scripts/advancement-mod.sh disable
bash scripts/advancement-mod.sh rollback backups/advancement-ДАТА-XXXXXX
```

Отключение сохраняет новые покупки и аддон. Откат возвращает прежний сервер,
настройки и обе старые папки аддонов, сохраняя новые таблицы для повторной установки;
он не откатывает весь прогресс игроков полным SQL-дампом. Старые резервные копии
`backups/subclass-…` по-прежнему обрабатываются командой `scripts/subclass-mod.sh rollback`.
Не удаляйте сохранённые образы до завершения игрового теста.

```bash
python3 -m unittest discover -s tests -q

docker compose --env-file .env.example config -q
```

Проверки каталога, замены/отката папок, Lua с подставным WoW API и C++-правил

### Версия 1.2: аналоги Forever и новое оформление

Меню использует тёмные одноцветные панели вместо растягивания пергамента и
рисунков дерева. «Можно изучить» открывает первую ещё не купленную совместимую
способность чужого класса для текущего уровня. «Все умения» показывает также
исторические записи, которые не имеют аналога. Нажатие на такую запись объясняет отказ.

Теперь сервер проверяет не только исходный ID: при его отсутствии или несовпадении
ищет точное имя на доступных языках, семейство класса и номер нативного ранга.
Неоднозначные совпадения исключаются. Привязка обработчика добавляется в память
только для прошедших проверки нативных способностей; существующие обработчики сохраняются.
Это использует эффекты Forever, а не воспроизводит баланс или поведение 3.3.5.
Отсутствующие эффекты, питомцы и сложные таланты требуют отдельной адаптации;
копирование старой DBC в современный клиент эту задачу не решает.

Для этой версии нужен **полный update**, поскольку меняется сервер:

```bash
cd ~/WoWForEver && git pull --ff-only && bash scripts/advancement-mod.sh update /mnt/e/_classic_beta_
```

Закройте игру и лаунчер перед установкой. Установщик делает резервную копию.
После запуска нужны строки `ForeverAdvancement ready`, `catalog remapped` и
`unresolved`: количество найденных аналогов зависит от извлечённых данных клиента.
Обновление только действием `addon` не включает новое сопоставление на сервере.

### Исправление 1.2.1: регистр локализованных названий

В предоставленном каталоге встречаются названия с заглавной буквой каждого слова
(например, «Ледяная Стрела»). Проверка имён теперь не различает регистр Unicode:
такое название совпадает с «Ледяная стрела». Семейство класса, ранг, неоднозначность,
стоимость и ограничения эффектов проверяются по-прежнему. Это исправление не создаёт
отсутствующие заклинания и не гарантирует совпадения разных переводов.

Диагностика `catalog locale` показывает число названий в загруженных языках.
`unresolved` выводит все непустые локализации нативного названия, семейство класса и
русский вариант из источника; примеры ограничены 12 различными способностями.
Ранее пустое `native=` означало только отсутствие английского имени.
Установка требует полного `update`, как в примере выше.

### История 1.3: книга заклинаний и панель действий (интерфейс заменён в 1.4)

Покупка активной способности теперь добавляет её нативный ID в известные заклинания
персонажа. Уже купленные способности восстанавливаются при следующем входе; учить
их заново не нужно. При повышении уровня выбирается совместимый ранг. Отказ от
способности удаляет только временную запись, которой владеет модуль. Постоянные
заклинания, полученные обычным способом, сохраняются. Пассивные таланты остаются
аурами и не превращаются в активные кнопки.

Купленные способности представлены временными записями ядра: покупка хранится в
`forever_advancement_spells`, а не дублируется в `character_spell`. Это также избегает
автоматического изучения всей чужой школы через `SetSkill` или зависимых заклинаний
через `LearnSpell`. Модуль отправляет штатные пакеты изучения/забывания клиенту.
Обычный каст такой способности из книги или панели проходит ту же проверку и оплату
общими ресурсами, что и каст из меню. Предметы, срабатывания и обычные постоянные
заклинания этим маршрутом не переопределяются.

Расположение нативных записей по вкладкам зависит от метаданных клиента. Аддон
дополнительно прикрепляет к штатной книге панель «Книга мультикласса» с вкладками
только изученных школ: например, «Свет», если изучена способность Holy. ЛКМ применяет
способность; перетаскивание иконки использует нативный `PickupSpell`. Пустая вкладка
исчезает после отказа от последней способности школы. Книга может загружаться
отложенно; поддерживаются `SpellBookFrame` и книга внутри `PlayerSpellsFrame`.

Для установки нужен полный `update`, затем вход в игру заново. Работу нативной книги,
панели и отображение доступности ресурсов необходимо проверить в клиенте пользователя;
облачные тесты проверяют серверные правила, пакеты через двойники API и Lua-панель.

### Версия 1.4: штатные школы и оформление старинного дерева

Боковая «Книга мультикласса» и нижняя плавающая панель полностью удалены.
Изученные способности остаются нативными известными заклинаниями. Для их группировки
сервер получает связанные навыки из `SkillLineAbility` и выдаёт только навыки
категории CLASS с подходящей маской исходного класса. Ни профессии, ни дочерние
навыки сюда не включаются. Ранее имевшиеся навыки не становятся собственностью модуля.

Это временные строки навыков для штатной книги. Они не попадают в `character_skills`
и восстанавливаются по покупкам при входе. Специальный путь изменения не обучает
другим заклинаниям школы и не удаляет их при скрытии вкладки. Дополнительная защита
в `LearnSkillRewardedSpells` блокирует автоматические награды для временных школ
при других вызовах ядра. Когда забыта последняя способность школы, удаляется только
её временная строка, добавленная модулем. Основной класс персонажа не меняется.

Окно развития использует нативные текстуры рамок, вертикальный выбор классов и
кнопки школ; крупные иконки талантов и значки рангов не уменьшаются для длинных
деревьев — доступна прокрутка. Кнопка книги над штатной кнопкой талантов открывает
мультиклассы, не сдвигая и не перекрывая другие кнопки микроменю. `/fa` также работает.

ЛКМ в каталоге изучает или применяет способность; ПКМ забывает. Подсказка использует
нативный ID, как и иконка, если API клиента доступен. Перетаскивание использует
`C_Spell.PickupSpell`, затем совместимые старые API; во время боя интерфейс не
пытается менять защищённую панель. Штатные записи книги не подменяются Lua-функциями
и используют обработчики клиента для описаний, перезарядки, кастов и перетаскивания.

Требуется полный `update` и повторный вход. Облачная проверка включает компиляцию
`Player.cpp` и адаптера, правила владения навыками, отсутствие выдачи других
заклинаний, повторное внедрение патчей, Lua-перетаскивание и кнопку микроменю.
Распределение по вкладкам штатной книги и окончательный внешний вид необходимо
подтвердить именно на клиенте 70532; интерфейс этого клиента в облаке не запускается.

### Версия 1.5: известные способности, кнопка талантов и нативные ранги

Каталог отдельно получает `KNOWN` для уже известных нативных заклинаний. Они
показываются как «Известно персонажу», допускают перетаскивание и не занимают слот
покупки. Купить известное заклинание повторно нельзя. Навыки основного класса
по-прежнему изучаются штатно; из каталога их нельзя забыть. Названия и подсказки
известных способностей используют их нативный ID.

В `catalog/ForeverSpellAliases.json` добавлен подтверждённый пользователем перевод
Entangling Roots: «Гнев деревьев». Он применяется к исходной цепочке 339 только
друида, с прежними проверками семейства, ранга и цены. Оригинальные данные Ascension
не изменены. Другие неточные переводы потребуют отдельных проверенных соответствий.

В правом верхнем углу штатного окна талантов добавлена кнопка «Мультикласс».
Поддерживается отложенная загрузка окна и создание кнопки после выхода из боя.
Кнопка возле микроменю и `/fa` сохранены.

Для пассивных талантов приоритетно проверяется нативная таблица `Talent`: точный
ID заклинания должен принадлежать нужному классу и указанному рангу. Это позволяет
использовать реальные таланты с общим семейством заклинаний или другим переводом.
Если такого подтверждения нет, сохраняется прежняя проверка имени и семейства.
Прежний список допустимых положительных пассивных эффектов, стоимость TE,
требования предыдущих рядов и безопасный возврат действуют по-прежнему. Сложные
проки и активные талант-способности автоматически не включаются. Подсказка показывает
нативное заклинание текущего купленного ранга. Очки мультикласса остаются отдельными
от штатных очков основного класса.

Для исправления клиентской фильтрации книги сервер публикует нативные hotfix-записи
`SkillLineAbility` с `ClassMask=0` только для совместимых способностей принятого
каталога и подходящих навыков CLASS. Другие поля, профессии, дочерние навыки и
`SkillRaceClassInfo` не меняются. Временные школы по-прежнему не выдают остальные
способности автоматически. Также исправлен статус генерируемых ядром hotfix-записей:
валидная существующая запись должна отправляться клиенту как Valid, а не Invalid.
Hotfix создаётся штатным генератором в памяти; SQL с клиентскими данными не добавляется.

Нужен полный `update` с закрытыми игрой и лаунчером, затем повторный вход. Для проверки:

```bash
docker compose logs worldserver | grep -E 'ForeverAdvancement (ready|talent metadata|spellbook metadata)' | tail -5
```

Число доступных талантов зависит от извлечённой таблицы клиента. Классовые вкладки
книги после клиентского hotfix и расположение кнопки требуется подтвердить в 70532:
облачные тесты не запускают этот клиент.

### Версия 1.6: адаптер современных Traits

Проверка версии 1.5 в клиенте пользователя подтвердила «Гнев деревьев», но классовые
вкладки остались в «Общих». Изменение `SkillLineAbility.ClassMask` не считается
завершённым исправлением группировки. Для дальнейшей интеграции требуется отчёт
именно штатной книги клиента 70532:

```bash
cd ~/WoWForEver && git pull --ff-only && bash scripts/advancement-mod.sh addon /mnt/e/_classic_beta_
```

Закройте игру перед обновлением. Затем откройте таланты, книгу заклинаний и введите
`/fa bookdebug`. Появится выделенный текст для Ctrl+C. Отчёт содержит API вкладок,
поля группировки и пути Lua-реализации штатных фреймов. Он не подменяет функции книги,
не изменяет классы и не требует сборки сервера. Последний отчёт также хранится в
`ForeverAscensionUI.nativeSpellbookReport`.

Серверная часть 1.6 включается **полным update**; действие `addon` оставляет текущий
сервер и его прежнее число доступных талантов. Ветка Forever использует боевые
`TraitTree`/`TraitNode`/`TraitNodeEntry`/`TraitDefinition`, а не только `Talent.db2`.
Адаптер теперь определяет класс дерева по нативной связи с навыком CLASS, связывает
исходный базовый ID со SpellID/VisibleSpellID определения и ограничивает число рангов
нативным MaxRanks. Неоднозначные определения исключаются. Профессии не включаются.
Прежний список допустимых пассивных эффектов, TE и требования исходных рядов сохранены.

Для Traits один и тот же SpellID может представлять несколько рангов. Перед
применением принадлежащей модулю ауры устанавливается временная метаинформация
определения и ранга. Штатный `SpellEffectInfo::CalcValue` рассчитывает эффект по
нативным кривым. При смене ранга старая аура снимается и применяется заново; при
возврате очков метаинформация очищается. Нативные записи персонажа имеют приоритет;
другие классовые конфигурации не редактируются. Пассивные заклинания этим путём не
изучаются в обычной книге и не записываются в `character_spell`.

Подсказка запрашивает описание ранга через `C_Traits.GetTraitDescription`, когда API
доступен. Для купленного таланта отдельные строки показывают реальные значения
эффектов применённой серверной ауры (`TEFFECT`), а не предполагаемые клиентские числа.
Если API описания отсутствует, остаётся штатная подсказка заклинания с этими фактическими
значениями; собственный произвольный пересчёт формул не используется.

Нативные активные способности теперь могут подтверждаться точным ID, семейством
(включая общие заклинания с семейством 0), строкой `SkillLineAbility` и принадлежностью
навыка исходному классу через `SkillRaceClassInfo`. Это устраняет зависимость от
машинного перевода при наличии нативной идентичности. Проверки стоимости, пассивности
и обычных ограничений каста сохраняются. Отсутствующий ID не включается таким способом.
Неподключённые записи больше не объявляются отсутствующими аналогами.

Диагностика после полного обновления:

```bash
docker compose logs worldserver | grep -E 'ForeverAdvancement (ready|trait |native abilities)' | tail -12
```

Количество подключённых Trait-рангов и эффекты необходимо подтвердить на данных
клиента пользователя. Облачные проверки включают боевой Trait-граф при пустом старом
каталоге талантов, повышение/понижение ранга одного SpellID, сохранность нативных
конфигураций, подсказки и фактические значения ауры. Обычная книга остаётся нативной;
боковая копия не возвращается.
