# Мультиклассы Forever — экспериментальная интеграция

Адаптация присланного `forever-subclass-prototype-v0.2.0.zip` для TrinityCore
Forever `91d49b230f89` и клиента **1.60.1.70532**. Исходный прототип сохранён
в `vendor/`; серверный адаптер, аддон и установка находятся рядом.
Это первый ограниченный игровой эксперимент, а не перенос всех классов и талантов.
Проверки сборки и изолированные тесты не заменяют тест в настоящем клиенте.

## Установка на вашем компьютере

Выполняйте в WSL из существующего `~/WoWForEver`. До установки сервер должен
полностью запуститься: `worldserver-daemon ... ready`. Закройте игру и лаунчер.
Проверьте свободное место для новой сборки Docker и резервной копии базы.

```bash
cd ~/WoWForEver
git pull --ff-only
bash scripts/subclass-mod.sh build
bash scripts/subclass-mod.sh install /mnt/e/_classic_beta_
```

Сборка может занять заметное время; работающий сервер продолжает использовать
предыдущий образ. Установка затем остановит игровые сервисы, сохранит полный
SQL-дамп четырёх баз, `.env`, предыдущий образ и прежнюю папку этого аддона
в `backups/subclass-ДАТА-…` внутри репозитория. Пароли и дампы в Git не попадают.
Путь к копии будет напечатан: сохраните его для отката.

Если Docker Desktop не может найти прежний образ по ссылке работающего контейнера
(`No such image: sha256:…`), установщик сохраняет файловую систему именно этого
контейнера в отдельный локальный образ. Он не подменяет резервную копию новым
`latest`. Подключённые тома в такой образ не входят: база сохраняется отдельным
SQL-дампом после остановки игровых сервисов. Способ сохранения указан в
`image-preservation.json`. Этот локальный образ может содержать конфигурацию
с паролями; он предназначен для восстановления на вашем компьютере.

Установщик создаёт четыре собственные таблицы в `characters`, привязки своего
SpellScript в `world`, включает `SUBCLASS_ENABLED=1`, копирует аддон в
`E:\_classic_beta_\Interface\AddOns\ForeverSubclass` и пересоздаёт игровые сервисы.
При ошибке пытается вернуть предыдущие образ, конфигурацию, привязки и аддон.
Сервер должен подтвердить `ForeverSubclass ready: … supported spell ranks`.
Повторная установка создаёт новую резервную копию; существующий прогресс сохраняется.

Конфигурация `ForeverSubclass.Enable` в `overrides/worldserver.conf`, если задана,
имеет приоритет над переменной окружения. Для управления установщиком удалите
эту ручную строку. По умолчанию функциональность выключена.

## Первый тест

1. Включите **ForeverSubclass** в списке модификаций игры. При необходимости
   включите загрузку устаревших аддонов: номер Interface ещё не проверен в клиенте.
2. Войдите персонажем основного класса **40-го уровня или выше**. Придите
   в город или таверну, выйдите из боя и введите `/fsub`.
3. Выберите другой класс → **Изучить** → **Активировать**. Он начинает с уровня 1.
4. Нажмите **Направить XP** для выбранного класса. Получаемый через серверный
   `GiveXP` опыт пойдёт ему вместо основного класса. Для возврата выберите основной
   класс и ту же кнопку. Уровень подкласса ограничен уровнем персонажа и лимитом мира.
5. Выберите доступную способность, выберите подходящую цель в игре и нажмите
   **Каст**. Например, воин + жрец: Lesser Heal на себя либо Smite на противника.
6. Проверьте расход ресурса, время каста, дистанцию, перезарядку, получение XP.
   Перезайдите: изученные классы, их уровни, выбранные способности и остаток
   дополнительного ресурса должны сохраниться.

Для ускоренного теста **только GM** может после изучения класса задать уровень:

```text
/fsub debuglevel 5 40
```

Здесь `5` — жрец; уровень не может превышать уровень персонажа и лимит мира.
Команда сбрасывает выбранные способности этого активного подкласса и восполняет
его виртуальные ресурсы. Обычному игроку сервер её запрещает.

## Правила и границы версии

- Основной класс постоянный; можно изучать девять классических классов,
  но активен один подкласс. DK, Monk и DH не включены.
- До 8 выбранных способностей, каждая стоит 1 слот. Ранги учитываются отдельно;
  для повышения ранга снимите старый и выберите новый. Смена активного подкласса
  разрешена в зоне отдыха, вне боя; выбор способностей — вне боя и каста.
- Сила прямого урона и лечения умножается на отношение уровней подкласса
  и основного класса, максимум 100%. Дополнительный вклад интеллекта пока
  экспериментальный. Это требует игровой проверки баланса.
- Начальный каталог: Battle Shout, Holy Light, Arcane Shot, Sinister Strike,
  Smite, Lesser Heal, Heal, Greater Heal, Flash Heal, Lightning Bolt,
  Healing Wave, Frostbolt, Fire Blast, Shadow Bolt, Wrath, Healing Touch
  и их найденные в ядре ранги. Доступность определяется уровнем подкласса.
- Нет полного дерева талантов, питомцев, форм, DoT, поглощений, комбо-финишеров,
  всех классовых квестов и новой специализации. Второй класс не выдаёт владение
  бронёй или оружием; нативные ограничения экипировки продолжают действовать.
- Способности подкласса вызываются кнопками аддона, не добавляются в обычную книгу
  заклинаний. Клиентские файлы CASC, DB2 и `WowB.exe` не изменяются.
- Если оба класса используют один тип ресурса, расходуется настоящий ресурс
  персонажа. Иначе сервер хранит отдельные ману/энергию/ярость, аддон показывает
  дополнительную полосу. Энергия восстанавливается на 10/с; мана — от духа,
  в бою медленнее; ярость приходит от нанесённого и полученного урона.
  Виртуальный запас создаётся полным один раз; переключение и перезаход его
  не восполняют. Сохранение происходит при изменениях, сохранении персонажа и выходе.
- Нативные проверки цели, расстояния, движения, времени каста, GCD, перезарядки,
  реагентов и экипировки остаются в ядре. Оплата ресурса выполняется адаптером
  однократно. Стоимость — экспериментальная, с минимальным порогом из каталога.
- Опыт за убийства проходит через адаптер, в том числе при максимальном уровне
  основного класса. Квесты, которые ядро на максимальном уровне превращает
  в деньги вместо XP, могут не давать опыт подклассу.

## Проверка и откат

```bash
bash scripts/subclass-mod.sh status
docker compose logs --tail=150 worldserver
```

Временно выключить механику, сохранив прогресс и аддон:

```bash
bash scripts/subclass-mod.sh disable
```

Вернуть предыдущий образ сервера и аддон (подставьте путь из установки):

```bash
bash scripts/subclass-mod.sh rollback backups/subclass-ДАТА-XXXXXX
```

Откат не восстанавливает весь SQL-дамп и не откатывает обычный прогресс персонажей:
он восстанавливает прежние привязки модуля и выключает механику; собственные
таблицы остаются для повторной установки. Предыдущие образы Docker до завершения
тестирования не удаляйте. При ошибке автоматического восстановления сохраните
вывод и не импортируйте полный дамп поверх работающей базы.

## Проверки разработки

```bash
python3 -m unittest discover -s tests -q
bash -n scripts/subclass-mod.sh
```

Тесты проверяют исходные C++-правила, повторную инъекцию адаптера, установку/
возврат аддона и обмен сообщениями Lua с подставным WoW API. Полная сборка
`worldserver` проверяется отдельно против закреплённого коммита ядра.
В текущей облачной проверке прошли 48 тестов, компиляция двух файлов модуля
с настоящими заголовками ядра и их промежуточная линковка. Полная линковка
`worldserver` и сборка конечного Docker-образа ещё не подтверждены;
локальная команда `build` — обязательный следующий шаг. Подробности —
[validation.json](validation.json).
Игровые эффекты, интерфейс в клиенте и установка на вашем компьютере требуют
первого локального теста. Исходный архив не содержал отдельного файла лицензии;
его уведомления сохранены, авторство не переобозначено.
