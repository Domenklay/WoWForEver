# Живая энциклопедия — проект модуля WoW Forever

Статус: **архитектурный прототип, не установлен и не активен**. Цель — серверная система для TrinityCore forever (клиент пользователя 1.60.1.70532, полная совместимость не подтверждена).

## Правила
- Энциклопедия — независимый летающий спутник; не занимает слот hunter pet; визуальная модель требует отдельной проверки доступных DisplayID.
- Прогресс и распределение очков — на аккаунте; текущая мана, cooldown и настройки активного персонажа — на персонаже.
- PvE only; отключение при PvP, дуэлях, battleground/arena, группе более 4 участников, включая рейд; запрет проверяется **сервером** при каждом срабатывании и при наложении/сохранении эффектов.
- В бою базовая регенерация +1 маны/5 с, вне боя +5 маны/5 с; при запрете действия регенерация не даёт применять эффекты.
- Ветка Мудрость: +1 max mana за 1 вложенное очко; все способности используют один запас.
- Лечение: не более 25% максимального HP за применение, после полного развития — 40%; щит не более 30% max HP. Ограничения применяются **после** всех множителей.
- Щит при HP <80%, лечение при HP <50%; настраиваемые пороги; cooldown и резерв маны.
- Для предотвращения гонок аккаунтные открытия фиксируются уникальным ключом (account_id, kind, entry_id), награда начисляется транзакционно только за успешную первую вставку.
- Очки за уникальные открытия: обычное существо 1, редкое 3, босс 10, предмет 1, эпический предмет 5, достижение 5–25, зона 3, мировой босс 20 (настраиваемые правила; классификация должна быть определена отдельно).
- Исторические открытия не начисляются автоматически, пока не разработана безопасная миграция.
- Записи каталога по локациям: map_id, area_id, zone_id; показывать обнаруженные существа и неизвестные силуэты/«???», количество неизвестных, фильтры и категории. Каталог должен строиться из серверного индекса spawn/creature templates, не из одних kill events. Исключать GM-only, тестовых, несуществующих и временных NPC; различать доступных в зоне и привязанных к инстансам.
- Приватность: каталог не раскрывает недоступный/скрытый контент и персональные данные других игроков.

## Этапы
1. Сверить upstream API ядра и существующие docker/patches и subclass; добавить отключённый по умолчанию серверный модуль с тестами и SQL миграциями.
2. Реализовать атомарные открытия и выборку каталога по зонам, API для аддона.
3. Реализовать companion, mana tick, cooldown, PvE guard, heal/shield с верхними лимитами и server-side audit.
4. Сделать интерфейс аддона: ветки Защита, Исцеление, Усиление, Мудрость, Познание; каталог локаций с поиском, сортировкой, статусом открытия, карточками NPC и наградами.
5. Прогнать unit/integration тесты и тест в клиенте 70532; только после этого включать на игровом сервере.

## Критические тесты
- Два персонажа одного аккаунта не получают повторную награду; одновременные открытия не дублируются.
- Shield <= 0.30 * MaxHP и Heal <= 0.25 * MaxHP (<= 0.40 с полным улучшением) при любых коэффициентах.
- PvP/raid/group>4 блокируют активацию, а существующие эффекты снимаются.
- Смена карты, logout, death, resurrection, relog не дублируют companion и не обнуляют очки.
- Каталог показывает неизвестных существ по выбранной локации даже до первого убийства, но не раскрывает недоступных NPC.
