# Локальный запуск v3 с публичным ключом нашего сервера

В журнале 5 ноября 2026 года обе попытки с именем
`trinity.actual.battle.net:1119` успешно проходят TLS и авторизацию,
получают список миров и подключаются к `70-1-70`. Через 1,5 секунды клиент
пишет `Protocol error: server identity check failed regionGroup="8"`.
Прямой запуск с отдельным WTF проверил авторизацию, но не выполнил настройку
публичного ключа игрового сервера. Это отдельный этап от сертификата TLS.

`Start-LocalForever.ps1` запускает только самостоятельную тестовую копию
v3, создаёт отдельный WTF с правильным DNS-именем и настраивает в памяти клиента
публичный ключ TrinityCore для группы 8. Код проверки 12 записей массива,
ключи, флаги и размер записи перенесены из имеющегося
`app/src-tauri/src/patcher/mod.rs`. Ключ сервера совпадает со
`STOCK_PUBLIC_KEY` нашего лаунчера. Это не настройка отключения проверки подписи:
клиент продолжает проверять подпись, используя публичный ключ нашего сервера.

Скрипт требует 64-битную Windows PowerShell и маркер проверенной копии
`forever-client-migration.json`, продукт wowf, `_forever_/Wow.exe` и общую Data.
Имя сервера должно разрешаться только в loopback. Перед открытием памяти
проверяется путь именно запущенной тестовой копии и время её запуска. Небольшой
bootstrap-процесс отделяется от полного клиента порогом 50 МиБ. Если полных
клиентов этой копии несколько, запуск останавливается. Другие установки
не выбираются по потреблению памяти.

Обнаружение массива допускает оригинальный ключ или уже установленный ключ
нашего сервера только в записи группы 8. Все остальные 11 записей, идентификаторы,
флаги и значимое заполнение должны совпадать. При нескольких подходящих массивах
скрипт останавливается до записи. Единственная разрешённая запись — 32 байта
публичного ключа группы 8 с повторным чтением и проверкой всего массива.
Игровой EXE, Data, серверные базы, сертификаты и настройки лаунчера 2.0.5
не изменяются. Аддоны не устанавливаются.

## Получить два исходных файла в WSL

Закройте игру и другие лаунчеры. Текущий сервер оставьте работающим.

```bash
cd ~/WoWForEver &&
git fetch origin codex/server-refresh-70658-20261105 &&
mkdir -p /mnt/e/WoWForEver-work/tools/local-login-v3 &&
git archive FETCH_HEAD tools/local-login/Start-LocalForever.ps1 tools/local-login/LocalKey.cs |
  tar -x --strip-components=2 -C /mnt/e/WoWForEver-work/tools/local-login-v3
```

Повторное извлечение обновляет только два файла инструмента; завершите предыдущий
запуск инструмента перед его обновлением.

## Запустить в Windows PowerShell

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\WoWForEver-work\tools\local-login-v3\Start-LocalForever.ps1"
```

ExecutionPolicy меняется только для этого процесса запуска, системная политика
не переписывается. C# компилируется штатным Add-Type в памяти процесса PowerShell;
дополнительная установка Python или .NET SDK на Windows не нужна.

Дождитесь **`LOCAL KEY READY`**, затем войдите учётной записью нашего сервера.
Оставьте это окно PowerShell открытым, пока работает игра: скрипт проверяет,
что ключ остаётся на месте, и повторяет поиск при замене массива самим клиентом.
При закрытии игры её память освобождается; для следующего запуска снова используется
этот инструмент. Если появляется `Stopped`, закройте оставшийся процесс игры и
передайте текст сообщения. Не меняйте EXE/имена файлов ради прохождения проверки.

Это временный локальный запускатель для диагностики и проверки нового клиента.
Он не использует вход или загрузчик 2.0.5. После успешного входа в мир можно
перенести подтверждённые настройки в постоянный лаунчер.

## Проверки и ограничения

Профиль ключей и серверный публичный ключ сравниваются с существующим Rust-кодом
Python-тестами. C# компилируется в режиме языка C# 5 и выполняет отдельный набор
проверок на искусственной памяти: все группы/флаги, неверные и неоднозначные
кандидаты, изменение массива до записи, границы записи, проверка результата и
повторный запуск. Запуск:

```bash
docker build --target test -f tools/local-login/Test.Dockerfile .
python3 -m unittest discover -s tests -q
```

Облачная проверка не запускает Windows API и игру. Совместимость Win32-поиска
с фактическим процессом 70658 и вход в мир должны быть подтверждены на ПК.
Если профиль клиента отличается, скрипт останавливается, а не угадывает адрес
записи. Полная поддержка игрового протокола и всех ресурсов клиента этим
инструментом не обеспечивается.
